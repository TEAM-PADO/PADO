## 구현해야 할 것

### 맡는 결과

첫 구현은 1~4인 리슨 서버다. 호스트 서버가 배달, 시간, 전투 결과, 거래·보상·차량 규칙을 최종 판정한다. 코어는 방 식별자와 방별 `SaveGame`을 연결하며, 같은 방에 돌아온 참가자는 그 방의 자기 상태를 이어 받는다. 개인 돈·장비 변경은 플레이어 담당의 `PlayerState` 공개 서버 API를 통해 반영한다.

**호스트의 판정 권한과 개발 담당을 구분한다.** 호스트에서 실행하는 공격 측 명중 재검증·피해 요청, 플레이어 피해·차량 충돌과 총 습득·드롭·사망 드롭의 서버 처리는 플레이어 전투가 구현한다. AI는 서버에서 적의 피해 수신·체력·보호·사망 처리를 구현한다. 코어는 배달·방의 공통 요청 유효성, 처치자·보상 자격·거래·부활 규칙, 방 진행과 공유 복제 상태, 방 저장 호출·통합을 맡는다. 개인 아이템의 소유·복제·이동 검증과 저장 스냅샷 구현은 플레이어 담당이며, 각 파트의 공개 계약으로 결과를 연결한다.

**배달의 게임 규칙과 전체 진행 사이클을 구현한다.** 배송지 ID와 배달 데이터 정의·관리·Anchor 매칭 검증, 후보 생성·수락·교체·재수락, 택배·타이머, 문 앞 상호작용·배송 완료·실패, 보상·보스 해금, 수취인 선택·결말·도전과제·저장을 하나의 흐름으로 연결한다. 레벨디자이너는 건물·문·좌표·동선 등 공간 정보를 제공하고, 코어가 발급한 ID를 배송지 Anchor/Actor에 할당한다.

### 서버 요청과 상태 소유권

```text
UI/플레이어 입력 → PlayerController 등의 Server RPC
  → 코어가 배달·방·거래·보상 규칙 검증
  → PlayerState 공개 서버 API로 개인 돈·총·택배 변경 요청
  → 복제된 GameState·PlayerState를 UI가 표시
```

| 대상 | 구현 소유자와 계약 |
|---|---|
| `GameMode` | 코어. 서버 전용 배달·방 규칙, 보상 자격·금액과 부활 조건 판정 |
| `GameState` | 코어. 진행 중 배달, 목적지 ID, 서버 타이머, 보스·공용 결말 상태 복제 |
| `PlayerController` 요청 진입점 | 대상 탐색·캐릭터 입력은 플레이어, 메뉴 입력은 UI가 연결. 코어는 배달·거래 요청의 규칙을 검증하고 거절 이유를 응답 |
| `PlayerState` | 플레이어. 클래스·돈·인벤토리·개인 장비의 복제, 공개 서버 API, 개인 저장 스냅샷 직렬화·복원 |
| 방 `SaveGame` | 코어. 방 진행·후보·해금·차량 상태와 플레이어가 제공한 개인 스냅샷을 통합 저장하고 재개 시 복원을 위임 |

코어는 `PlayerState` 변수·인벤토리 배열·총 소지 상태·개인 저장 직렬화 코드를 직접 수정하지 않는다. 택배 소지 여부도 공개 조회 API로 확인하며 지급·회수·보상 반영은 공개 서버 API로 요청한다. 개인 API는 플레이어 담당이 서버 권한·중복 적용을 검증한다. UI는 복제된 상태와 서버 응답을 표시한다.

### 배송지 ID와 데이터 검증

- 기획의 배송지 추가 요청에는 표시 이름·배달 유형·보상·목적지 설명·보스 연결 여부를 포함한다. 코어가 `DeliveryLocationId`를 발급하고 생성·변경·폐기를 관리하며 배달 정의 구조를 설계한다. 기획과 레벨은 ID 문자열·열거값을 직접 만들지 않는다.
- 레벨은 발급받은 ID를 공간에 할당하고 배송 상호작용·문·수취인·지도 마커 위치를 제공한다. 코어는 서버의 레벨 시작 시 Anchor의 ID와 배달 정의를 매칭하고 누락·중복·정의 없는 ID 및 위치·정의 불일치를 오류로 처리한다.
- 검증을 통과한 배송지 Anchor만 후보가 된다. 수락·배송·문 열기·수취인 확인 예외 요청은 현재 시도·배달 상태·배송지 ID·거리와 택배 소지를 서버에서 확인한다. UI와 레벨은 배달 결과를 판정하지 않는다.

### 배송지 후보와 표시 개수

- 일반 배송지 후보 풀은 **최소 9곳**이며, 제작하면서 더 늘릴 수 있다. 각 일반·보스 배송지의 **월드 위치·ID는 고정**한다. 새 게임마다 이 풀에서 첫 일반 후보를 무작위로 뽑고, 완료 후 빈자리도 풀에서 무작위로 보충하므로 게임마다 배송지가 제시되는 순서가 달라진다. 이어하기에서는 저장된 후보·진도를 복원하며, 방을 다시 열었다는 이유로 후보를 새로 뽑지 않는다.
- 최종 플레이 규칙에서는 우체국 지도에 **서로 다른 일반 배송지 3개**를 수락 가능한 후보로 제공한다. 플레이어는 그중 하나를 골라 팀 배달 한 건을 시작한다. 다른 후보 2개는 그대로 남는다.
- 일반 배달을 완료하면 완료한 후보 자리만 일반 배송지 풀에서 무작위로 뽑은 후보 1개로 채운다. 이 후보는 남은 2개와 ID가 달라야 한다. 기존 규칙대로 완료한 배송지도 다시 추첨될 수 있으므로, 완료하지 않은 곳을 모두 소진한 뒤에만 반복한다는 규칙은 두지 않는다. 우체국에 돌아와 지도를 열면 **기존에 남은 2개 + 새로 뽑은 후보 1개 = 일반 후보 3개**를 확인한다. 후보 교체와 완료 보상·진도는 같은 서버 결과 및 저장에 반영한다. 실패·중단은 완료가 아니므로 기존 후보를 유지하고 재수락할 수 있다.
- 보스 해금 조건이 충족되면 해금된 보스 배달지를 일반 후보와 **별도 고정 항목**으로 추가한다. 미완료 보스가 하나 열린 동안 선택지는 **일반 3개 + 보스 1개 = 총 4개**다. 보스 후보는 일반 배달 완료로 교체되지 않으며 해당 보스 배달을 완료할 때까지 유지한다. 후보가 4개여도 동시에 진행하는 팀 배달은 한 건이다.
- 1단계 통합판의 일반 후보 1개는 후보 생성·완료·보충을 검증하기 위한 임시 범위다. 위 3개 유지와 보스 해금 시 4개 표시는 2·3단계에서 완성한다.

### 방 열기와 참가 경로

2026-10-01 갱신: **게임 저장은 호스트별 슬롯 1개부터 구현한다.** 단일 슬롯의 저장·재개·삭제 검증을 통과한 뒤 여러 슬롯으로 확장한다. 이는 구현 순서이며 현재 저장 기능의 검증 결과를 뜻하지 않는다.

- 메인 메뉴의 게임 시작에서 호스트는 저장이 없으면 새 게임을 만들고, 저장이 있으면 유일한 저장 게임을 이어 하거나 삭제한다. 기존 저장이 있을 때 새 게임 생성은 삭제 확인 후 허용하며 자동으로 덮어쓰지 않는다. 이어하기·새 게임을 확정하면 별도 로비 레벨 없이 게임 지도에 바로 입장한다. 여러 저장 게임의 목록·선택은 단일 슬롯 검증 후 추가한다.
- 새 게임 생성과 저장된 게임 재개로 방을 열 때마다 **공개 / 친구(초대 전용)**를 선택한다. 공개 방만 게임 참가 UI의 검색 목록에 표시한다. 친구(초대 전용) 방은 목록에서 숨기고 스팀 초대로 들어온 참가 요청만 허용한다. 공개 방은 목록 선택으로 참가할 수 있으며, 참가가 승인되면 두 방식 모두 진행 중인 지도에 곧바로 입장한다.
- 호스트가 최대 4인 정원을 확인하고 참가 경로에 맞게 접근을 검증한다. 참가자의 기존 상태는 그 방의 저장 데이터와 현재 진행 상태를 기준으로 연결한다. 배달 진행 중 처음 합류한 사람의 시작 위치와 보상 자격은 아래 규칙을 따른다.

| 2. 실패·성장 | 고정된 일반 배송지의 무작위 제시 순서와 일반 후보 3개 유지, 완료 시 남은 2개 + 신규 1개 보충·실패/중단 후 재수락, 시간별 보상 감소·최종 실패와 택배 만료 제거, 중도 합류·재합류, 구매·수리·아이템·차량의 호스트 판정과 방별 저장 |
| 3. 보스·결말 | 일반 누적 횟수와 앞 보스 완료에 따른 순차 해금, 일반 3개 + 고정 보스 1개로 총 4개 선택지·재도전, 처치 제한시간·배송 단계 전환, 보스 3종 처치 직후 자동 저장·해당 문 앞 배송 재개, 최종 문 앞 체크포인트의 별도 보존·불러오기, 마지막 선택·결말·업적의 공유 상태, 결말 후 일반 배달과 완료한 보스 3마리의 자유 전투용 재등장 |

현재 기반과 연결할 때는 플레이어 전투가 총격 명중 재검증 범위를 제안하고 서버의 공격 측 명중 검증·피해 요청과 플레이어 피해 처리를 구현한다. 적의 피해 수신·체력·보호·사망 처리는 AI 서버 기능에 연결한다. 현재 아이템 한 개를 손에 드는 구조에서 여유 있는 일반 인벤토리와 별도 택배 전용 슬롯, 장착 전환·아이템 이동·줍기·투하 기능 및 `PlayerState` API·개인 복제·저장 스냅샷도 플레이어 전투가 구현한다. 코어는 배달·보상·거래·부활 규칙과 방 저장 계약을 제공하고, 택배 수명 판정을 API로 전달한다. 최근 사망 드롭의 기록·정리는 플레이어 서버 처리에 연결한다. 게임 단계 메시지 정의는 코어가 실제 방 진행 상태의 생성·복제·전환에 연결해야 한다. 이 분담은 구현 목표이며 위 표의 현재 구현 상태를 뜻하지 않는다.

### 상태와 판정 규칙

- 한 번에 진행할 팀 배달은 한 건이다. **우체국에 있는 팀원**은 누구나 후보 지도를 확인·수락할 수 있고 수락 즉시 시간이 흐른다. 일반 배달은 후보 → 수락 → 진행 → 감액 → 완료/실패로 전환한다. 최소 9곳의 고정 배송지 풀에서 무작위로 뽑은 일반 후보 3개와 해금 시 별도 보스 후보 1개는 위의 후보 규칙에 따른다. 우체국·상점·도로·배달지가 같은 지도에 있어 구역 이동 중에도 타이머는 계속 흐른다. 일반 배달은 첫 기준에서 보상이 한 번 줄고 두 번째 기준에 실패한다. 보스는 제한시간 내 처치에 실패하면 즉시 실패하며, 처치하면 배송 시간제한을 없앤다.
- 완료 보상 자격은 **수락 시 방에 있었고 완료 순간에도 접속 중인 참가자**에게 있다. 코어는 수락 시 참가자 식별자 목록을 기록해 중간 이탈·복귀에도 같은 사람의 자격을 유지한다. 수락 후 처음 들어온 참가자는 우체국에서 시작해 목표에 참여할 수 있지만 그 건의 완료 보상은 받지 않는다. 코어는 보상 대상·금액을 계산하고 각 대상의 `PlayerState` 공개 서버 API로 한 번만 지급한다. 일반 좀비 처치 보상은 코어가 최종 인정한 처치자 한 명에게 주고, **보스 처치 자체에는 별도 코인을 주지 않는다**. 새 방의 플레이어는 기본 권총만 지급받고 코인·차량 없이 시작한다.
- 택배는 일반 인벤토리와 별도의 전용 슬롯에 넣고, 바닥에 떨어뜨린 뒤 동료가 줍는 방식으로 전달한다. 차량 탑승 중에도 운반 제약은 없다. 사망 시 총·택배는 플레이어 전투의 서버 처리로 개별 드롭하며 플레이어별 최근 사망 1회분만 현장 유지한다. 다음 사망 때 이전 미회수분을 제거하되 이미 회수한 아이템·다른 팀원의 드롭·차량은 제외한다. 사망 드롭에는 3분 정리를 적용하지 않고 직접 내려놓은 일반 아이템만 3분 뒤 제거한다. 코어는 택배의 최종 제한시간 초과·완료·중단·교체를 판정해 공개 API로 인벤토리·바닥의 해당 택배 제거를 요청한다. 제때 보스 처치 후에는 배송 무제한이므로 시간 경과만으로 제거하지 않는다.
- 진행 중에도 우체국 팀원이 다른 후보를 수락하면 기존 배달을 중단하고 새 건으로 교체한다. 동시 활성은 한 건이며, 유효한 새 수락과 기존 택배 제거를 함께 확정한다. 실패·중단한 후보는 같은 건 재수락을 위해 유지하고, 새 시도마다 새 택배·시작 시각·보상 자격을 정한다. 기존 시도의 지연된 배송 요청은 거부한다. 사망 현장 택배 회수는 필수가 아니다. 상세 사건은 [공동 판정표](../공용/07_배달_상태와_저장_규칙.md)를 따른다.
- 보스 배달은 해금 → 수락 → 처치 제한 → 배송 → 완료/실패로 진행한다. 의뢰 미수락 상태의 보스는 AI 보호 상태로 처치할 수 없다. 코어가 수락·실패를 전달하고 AI가 활성화 또는 전투 해제·최대 체력 회복을 수행한다. AI의 처치 이벤트를 코어가 검증해 배송 단계로 전환한다. 의뢰 진행 중 보스는 시간 경과로 자동 재생성하지 않는다. 결말 후 자유 전투용 재등장은 아래 기존 예외를 따른다.
- 차량의 운전·승하차·`Ctrl+1~4` 좌석 변경·동승 사격·충돌·내구도·파괴는 플레이어 전투가 구현한다. 운전자는 사격할 수 없고 동승자만 창밖으로 사격한다. 운전석이 비면 마지막 가속 입력 이후 감속하며, 소유자나 운전자가 죽어도 멀쩡한 차는 남아 동승자가 운전석으로 이동할 수 있다. 파괴 시 탑승자는 사망하고 차량은 재구매해야 한다. 코어는 구매·수리·처치 수익과 차량 저장 규칙을 판정한다. 차량 소환 대수에 현재 상한을 두지 않는다. 멀리 있는 빈 차와 정지한 차의 갱신을 낮춰 성능을 관리한다.

### 저장과 재개 계약

#### 단일 슬롯 구현과 확장 조건

- **먼저 만들 범위:** 호스트별 저장 게임 1개에 새 게임·일반 저장·불러오기·삭제를 연결한다. 저장이 없을 때 이어하기를 제공하지 않고, 삭제 후에는 저장 없는 초기 상태로 돌아간다. 저장 실패를 성공으로 표시하지 않는다.
- **검증 기준:** [1단계 통합 검증표](../공용/08_1단계_통합_검증표.md)의 V09·V10·V13·V22·V23을 포함해, 1~4인 방에서 저장 후 종료·재개를 반복해도 완료 진도·참가자별 코인·해당 단계의 장비·차량 상태가 일치하고 보상이 중복 지급되지 않아야 한다. 개인 데이터의 저장·복원은 기존 `PlayerState` 공개 스냅샷 API 경계를 따른다. 2단계에서 추가되는 총·수리·내구도·재합류도 같은 슬롯에서 먼저 검증한다.
- **확장 시점:** 단일 슬롯의 저장·재개·삭제 검증 결과를 기록하고 관련 결함을 해결한 뒤 여러 슬롯 지원에 착수한다. 다중 슬롯을 1단계 통과 조건으로 요구하지 않는다. 코어가 결과를 취합하고 기획자가 인수 기준에 따라 확인한다.
- **확장할 범위:** 여러 저장 게임의 목록·선택·개별 생성·삭제를 추가한다. 방 ID와 참가자 ID를 기준으로 게임별 진행·개인 스냅샷·차량을 분리하고, 기존 단일 저장은 하나의 슬롯으로 유지한다. 다른 슬롯을 열거나 삭제해도 나머지 저장이 바뀌지 않는지 검증한다. 슬롯 최대 개수는 확장 시 정한다.
- **체크포인트 구분:** 3단계의 최종 문 앞 체크포인트는 해당 게임에 속하는 별도 저장 상태다. 게임 슬롯이 1개여도 일반 저장과 체크포인트를 함께 보존하며, 여러 슬롯으로 확장해도 체크포인트는 게임별로 분리한다.

#### 저장 담당과 복원 범위

코어가 방 저장 사건·방 식별자·`SaveGame` 파일과 통합 저장 결과를 관리한다. 개인 돈·인벤토리·장비의 저장 형식, 스냅샷 생성·직렬화·복원은 플레이어 담당의 `PlayerState` 구현에 맡긴다. 저장 시 공개 스냅샷 API로 개인 데이터를 받아 방 진행·차량 상태와 함께 보존한다. 방 종료 후 불러오기에는 선택한 저장본의 스냅샷을 적용하고, 호스트가 방을 유지하는 동안의 재접속에는 **현재 방이 유지한 상태/스냅샷**을 연결한다. 필요한 개인 복원은 공개 API에 위임하며 현재 방의 돈·인벤토리를 과거 저장본으로 되돌리지 않는다. 코어는 스냅샷 내부 필드나 개인 인벤토리를 직접 변경하지 않는다.

**자동 저장 사건은 세 종류:** 배달 완료 직후, 야외에서 우체국 안전 구역에 도착할 때, 그리고 수락한 보스 배달 3종 각각의 제한시간 내 보스 처치 확정 직후다. 우체국은 새로 도착할 때만 저장하고, 보스 처치는 현재 배달·보스·시도·마감을 검증해 한 번만 저장한다. 방 진행·후보·해금·결말, 참가자별 코인·총의 공개 스냅샷, 파괴되지 않은 차량과 내구도를 일관된 한 상태로 보존한다. 처치 후에는 배송 대기·배송 시간 무제한·배달지 ID·문 앞 재개 지점·택배 소지/바닥 상태·수락 당시 보상 자격도 저장한다. 처치 자체에는 배달 완료 보상·완료 진도·다음 보스 해금을 부여하지 않으며 자유 전투 처치는 이 저장 사건에서 제외한다. 최종 배달은 기존대로 택배 소지자가 마지막 문 앞에 도착하면 선택 전 상태를 별도 체크포인트로 보존하고 이후 일반 저장이 갱신돼도 유지한다.

저장본에 보스 처치 후 배송 대기가 있으면 **팀은 해당 배달지 문 앞에서 재개**한다. 보스는 처치 상태, 배송은 시간 무제한을 유지하고 택배·보상 자격을 복원한다. 보스 택배가 소지 중이면 해당 참가자의 전용 슬롯, 바닥에 있었다면 문 앞에 하나만 복원하며 일반 바닥 아이템은 복원하지 않는다. 파괴되지 않은 차량은 남은 내구도로 해당 배달지의 접근 가능한 차량 재개 지점에 배치한다. 우체국 도착 저장이 갱신돼도 활성 보스 배송 대기는 유지한다. 완료·중단·교체가 다음 저장에 반영되면 이 재개 상태를 해제한다. 그 외 일반 저장은 플레이어·차량을 우체국에서 재개하고 진행 배달은 처음부터 다시 받는다. 최종 문 앞 체크포인트를 명시적으로 불러오면 팀이 마지막 선택 전으로 돌아가고 이후 코인·장비·일반 진도는 체크포인트 시점으로 되돌린다. 체크포인트는 계속 보존하며 보상은 선택한 진행에서 완료 시 한 번만 지급한다. 호스트가 방을 유지한 채 재합류할 때는 현재 방 상태를 사용한다.

### 다른 파트와의 경계

- 사망·부활은 [공동 판정표](../공용/07_배달_상태와_저장_규칙.md)를 따른다. 호스트가 생존자 수, 우체국 내부 생존자 유무, 사망자별 대기·부활 진행 상태를 관리한다. 전멸(1인 포함)은 자동 부활, 생존자가 있으면 한 명의 우체국 내부 도착으로 대기 중인 사망자 전원 부활을 확정한다. 이미 내부에 생존자가 있으면 조건 충족이며, 도착·전멸 판정 중복에도 몸 생성과 권총 지급은 한 번만 처리한다. 데이터 귀환 연출만으로 부활이나 도착 저장을 판정하지 않는다. 대기·연출 중에도 배달 타이머를 유지한다.

- 레벨디자이너가 건물·문·상호작용 위치와 우체국 내부 경계 등 실제 월드 공간 정보와 제작용 명칭을 제공하고 발급된 ID를 Anchor에 할당한다. 코어가 배송지 ID를 정의·관리하고 Anchor 매칭을 검증하며 각 지점의 배달 규칙을 구현·판정한다. 거리 등급·배달 제한시간·보상은 레벨의 측정과 제안을 받아 기획자가 승인하고 코어가 배달 데이터에 반영한다.
- 일반 배달은 택배를 가진 플레이어의 문 앞 상호작용으로 바로 완료한다. 첫 보스 배달은 수취인 등장·수령 후 완료한다. 둘째는 미등장 선택 뒤 충전 중 로봇 확인이면 정상 보상, 확인 생략이면 차감(수치 미정)한다. 셋째는 문 열기 시 인간 좀비화 컷신과 「ai의 시대」, 열지 않으면 인간 번영 결말과 「인간을 지켜준 로봇」을 확정한다. 마지막 선택 권한은 배송한 플레이어 한 명에게만 주고 서버가 요청자를 확인한다. 선택·보상·도전과제 결과는 중복 처리하지 않고 공용 결말 상태로 팀 전원에게 동일하게 전파한다.
- AI는 적·보스·수취인 행동과 서버의 적 피해 수신·체력·보호·사망 처리를 구현한다. 플레이어 전투는 호스트의 공격 측 명중 재검증·피해 요청과 플레이어 피해·차량 충돌, 캐릭터 조작, 월드 상호작용 대상 탐색·우선순위·입력, 총 습득·드롭·사망 드롭의 서버 검증 및 `PlayerState`의 인벤토리·장착·복제·개인 스냅샷을 구현한다. 코어는 받은 결과의 처치 최종 인정·보상·배달·부활 규칙을 판정하고 개인 변경은 공개 서버 API로 요청한다.
- UI/클라이언트는 체력·탄약·장착 총을 포함한 HUD, 메뉴 입력과 상호작용 안내를 구현하고 수락·배송·구매·수리·문 열기 요청과 결과를 표시한다. 코어는 공통 유효성을 검증하고 확정 상태를 참가자에게 전달한다. 월드 대상 탐색·캐릭터 입력과 인벤토리 상태 변경 기능은 플레이어 전투가 맡는다.
- 컷신의 선택·결말·도전과제 상태는 코어가 확정한다. 기획자가 콘티를 확정하고 UI/클라이언트가 컷신 제작 계획·자산 취합·통합·재생을 주관한다. 코어는 팀 전체 재생에 필요한 확정 결과와 동기화 계약을 제공한다.
- 기획 + PM이 단계별 인수 기준·테스트 시나리오와 기능 변경 시 영향 담당자를 관리한다. 코어는 그 기준에 따른 통합 검증의 일정·절차·실행·결과 취합과 성능 측정의 조건·기록 취합을 총괄한다. 각 파트는 자기 기능을 검증·측정하고 실패 항목을 수정한다. 기획자가 체감 품질과 단계 통과를 최종 승인한다. 결과는 [통합 검증표](../공용/08_1단계_통합_검증표.md)와 [공동 결과물](../공용/13_팀원별_문서_작성_요청.md)에 기록한다.

### 완료 확인

최소 9곳 이상의 유효한 고정 일반 배송지에서 새 게임마다 서로 다른 후보 3개가 무작위로 제시되는지 확인한다. 한 건을 완료하고 우체국 지도를 다시 열었을 때 남은 2개와 무작위로 보충된 1개가 보이고, 같은 화면에 중복 ID가 없는지 검증한다. 실패·중단은 후보를 바꾸지 않고, 저장 후 이어하기에서도 후보가 임의로 다시 뽑히지 않아야 한다. 보스 해금 시에는 일반 3개와 고정 보스 1개로 총 4개가 보이되 동시 활성 배달은 한 건인지 확인한다.

서버 시작 시 배송지 ID 누락·중복·정의 불일치를 감지하고 오류 Anchor가 후보에서 제외되는지 확인한다. 코어의 보상·거래·택배 변경이 모두 `PlayerState` 공개 서버 API를 거치는지, 개인 저장·복원이 플레이어의 스냅샷 API에 위임되는지 확인한다. UI는 `GameState`·`PlayerState`와 서버 응답에서 같은 목표·자격·타이머·거절 이유를 표시해야 한다. 의뢰 미수락 보스의 처치 보호와 실패 시 최대 체력 회복도 확인한다.

새 게임·이어하기 모두 공개/친구(초대 전용) 설정 후 로비 없이 바로 시작하는지, 공개 방만 목록에 보이고 초대 전용 방은 스팀 초대로만 입장하는지 확인한다. 1~4인 방에서 완료 보상 자격의 네 경우(처음부터 접속, 중간 이탈 후 복귀, 수락 후 첫 합류, 완료 순간 미접속)를 확인한다. 배달 완료 직후 종료해도 진도·보상이 남는다. 일반 배달 또는 보스 처치 전 종료는 같은 배달을 처음부터 받는다. 우체국 재도착 저장 후 코인·총·차량 내구도가 일치하는지 확인한다. 보스 배송 대기가 없으면 우체국, 있으면 해당 배달지 문 앞에서 재개한다. 보스 3종 각각 처치 직후 문 앞에 도착하기 전에 종료·재개해도 재전투 없이 택배·배송 시간 무제한·보상 자격이 복원되고 배송 완료 보상이 한 번만 지급되는지 확인한다. 최종 문 앞 체크포인트는 결말 뒤 일반 배달을 여러 번 저장해도 남고, 불러오면 보스가 처치된 채 팀이 문 앞에 있으며 이후 코인·장비·진도가 되돌아가는지 검증한다.
