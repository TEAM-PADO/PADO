# 1단계 통합 검증표 — 배달 한 건이 끝까지 돌아가는 통합판

기준: [개발 순서 1단계](01_개발순서.md) · [배달 상태·저장 규칙](07_배달_상태와_저장_규칙.md). 이 표는 **실제 빌드에서 사람이 실행할 확인 절차**다. 현재 결과는 모두 미실행이며, 테스트를 마친 사람이 기록한다.

**인수 기준·시나리오 관리는 기획·PM, 실행 주관은 네트워크 코어다.** 기획·PM은 1·2·3단계 기준과 변경 영향 담당을 관리한다. 코어가 공통 빌드·실행 일정·파트별 실행자를 조율하고 결과와 수정 담당을 취합한다. 각 파트는 자기 확인 항목을 실행하며, 여러 파트가 적힌 항목은 코어가 실행 주 담당 한 명을 지정한다. 코어가 실제 통과 근거를 제출하고 기획자가 단계 통과를 승인한다. 담당 지정은 실행 결과를 대신하지 않는다. 구현 경계는 [역할 분담과 서버 API 경계](14_역할분담과_서버_API_경계.md)를 따른다.

## 실행 준비

- 같은 빌드로 1인, 2인, 4인 리슨 서버 방을 각각 준비한다. 호스트와 참가자의 화면을 모두 확인한다.
- 호스트별 게임 저장 슬롯은 **1개**로 준비한다. 여러 슬롯의 목록·선택은 이번 통과 조건에 포함하지 않는다.
- 한 지도에 우체국, 맞은편 총 상점 안전 구역, 두 건물 사이 좀비가 활동하는 길, 첫 차를 살 수 있는 차량 상점, 가까운 일반 배달지 1곳과 약한 일반 좀비를 둔다.
- 가까운 배송지 Anchor에는 코어가 발급한 `DeliveryLocationId`를 할당한다. 서버 시작 시 ID 누락·중복·정의 불일치가 없는 정상 지도와 검수용 오류 사례를 준비한다.
- 코어의 `GameState`와 플레이어 담당자의 `PlayerState` 공개 서버 API·개인 스냅샷 경로를 확인할 서버 기록 또는 디버그 표시를 준비한다. UI는 복제 상태와 서버 응답만 표시한다.
- 새 방은 기본 권총 1정·돈 0·차량 없음으로 시작한다. 첫 테스트 값은 약한 좀비 처치 20, 첫 차량 가격 200이다. **통과 검증에서는 테스트용 차나 돈을 지급하지 않는다.**
- 결과 기록에 빌드 버전, 실행 날짜, 호스트/참가자 수, 사용한 임시값을 적는다. 보상·시간은 [기본 기획의 첫 테스트 값](00_기획핵심과_미결정.md)을 쓰거나 변경값을 함께 기록한다.

## 통과 판정과 기록

- **1단계 통과:** V01~V23을 모두 실제 빌드에서 통과한다. 공개/친구 방 즉시 입장, 새 방 첫 차 구매, 1/2/4인 완료와 재개, **이 단계의 일반 저장 지점이 우체국뿐인 규칙**, 전멸/생존자 복귀 부활, 최근 사망 1회분 드롭, 배송지 ID 검증과 PlayerState API/스냅샷 경계, 단일 슬롯의 반복 저장·재개·삭제를 확인한다. 3단계 최종 문 앞 체크포인트는 별도 검증 대상이다.
- **다중 슬롯 확장 착수:** 단일 슬롯의 저장·재개·삭제 결과를 기록하고 관련 결함을 해결한 뒤 착수한다. 2단계의 총·수리·내구도·재합류 기능도 추가될 때 같은 슬롯에서 먼저 검증한다.
- 실패한 항목은 `ID / 빌드 / 실행자 / 재현 순서 / 기대 결과 / 실제 결과 / 수정 주 담당 / 협조 파트`로 기록하고 코어가 취합한다. 같은 버그가 여러 항목에 영향을 주면 하나의 문제로 묶고 관련 ID를 함께 적는다.
- 배달지·좀비 능력치에 임시값을 사용했다면 결과에 적는다. 첫 차 구매 경로를 건너뛰는 테스트용 차량·자금을 사용한 실행은 **1단계 통과 판정에 포함하지 않는다.**

## 다음 단계에서 추가할 검증

1단계에 포함하지 않는 확인: 일반 배달의 보상 감소·실패와 최소 9곳 풀에서의 일반 후보 3개 유지, 부활 대기 중 시간 초과에 따른 실패·택배 제거, 진행 중 배달 교체·실패 후 새 택배 재수락, 배달 중 종료, 중도 합류와 재합류의 보상 자격, 동승·좌석 변경, 총 전달·직접 내려놓은 일반 아이템 3분 정리, 첫 차 외 추가 차량 구매·차량 수리/파괴, 보스 해금 시 총 4개 선택지·재도전과 두 결말. 첫 차 구매는 V03·V22의 필수 항목이며 사망 드롭과 기본 부활은 V15~V20에서 확인한다. 나머지는 [개발 순서](01_개발순서.md)의 2·3단계 검증표로 확장한다.

2단계 추가 절차(미실행):

- 고정된 일반 배송지 최소 9곳에서 새 게임을 여러 번 열어 첫 후보 3개의 무작위 구성을 확인한다. 완료 뒤 우체국 지도로 돌아가면 남은 2개와 새로 추첨한 1개가 보이고 같은 화면에 중복 ID가 없어야 한다. 실패·중단 시 후보는 유지하며, 저장한 방을 이어 열 때 후보가 임의로 다시 뽑히지 않는지 확인한다.
- 수락 당시 참가자 이탈 후 완료 전 재접속·완료 순간 미접속·수락 후 최초 합류를 각각 실행한다. 재접속자는 자격 유지, 완료 순간 미접속자와 후발 최초 합류자는 해당 완료 보상 제외. 현재 방 재접속 때 과거 저장본으로 돈·인벤토리를 되돌리지 않고 UI가 본인 자격을 서버 상태로 표시하는지 확인한다.
- 택배를 전용 슬롯에서 바닥에 드롭하고 동료가 줍는다. 동시에 줍거나 중복 요청해도 소지자가 한 명이고 일반 슬롯과 충돌하지 않으며 차량 안에서도 운반 제약이 없는지 확인한다.
- 택배가 바닥과 인벤토리에 있는 경우 각각 일반 배달의 최종 마감을 넘긴다. 자동 삭제·실패 후 우체국에서 같은 건을 재수락해 새 택배·전체 제한시간·새 보상 자격으로 배송한다. 보상 감소 시각에는 택배가 남아 있어야 한다.
- 동료가 기존 택배를 소지하거나 현장에 남긴 상태에서 우체국 팀원이 다른 배달을 수락한다. 기존 택배가 모든 위치에서 제거되고 한 건의 새 목표만 공유하는지, 기존 배송 요청이 거부되는지, 회수 없이 새 택배로 완료 가능한지 확인한다.
- 택배를 잃고 회수하지 않은 채 다른 배달로 교체한다. 실패·중단한 건의 보상·완료 횟수는 늘지 않고, 재수락한 새 시도에서만 보상이 한 번 지급되는지 확인한다. 보스 배달 교체·재수락은 3단계에서 보스 초기 상태와 처치 후 배송 무제한·문 앞 체크포인트 별도 보존까지 확인한다.
- 정차·주행 중 문 근처에서 상호작용 0.5초 유지 탑승을 확인한다. 입력 해제·거리 이탈은 시간 초기화, 이동·피격 자체는 유지되어야 한다. 동시 요청은 완료된 요청부터 빈 운전석 우선·가까운 빈 좌석으로 배정한다. 사격·재장전 중 즉시·연속 좌석 변경과 점유 좌석 이동 불가, 운전자 사격 금지·빈 운전석 감속을 호스트/참가자에서 확인한다.
- 가까운 빈 공간으로 즉시 하차하고 속도 경계 **20km/h 이하 피해 0 / 20 초과~60 이하 피해 50 / 60 초과 즉사**를 확인한다. 창밖 사격 중에도 차량만 피해를 받으며, 같은 공격의 차체·탑승자 명중은 해당 차량에 한 번만 적용되어야 한다. 내구도 0 즉시 폭발·탑승자 사망, 근거리 즉사(차량 즉시 파괴)·외곽 피해 70·벽 완전 차폐와 동료/좀비/다른 차량 적용을 확인한다. 폭발 반경은 미정이므로 기획 데이터가 정해진 뒤 실행하고 사용값을 기록한다.
- 속도별 좀비 충돌 피해·재충돌 재피해, 차량 내구도 손실·감속과 동료 충돌 피해를 확인한다. 낮은/높은 충돌 속도와 낮은/높은 낙하를 비교하여 **고속 충돌·높은 낙하에서 더 큰 내구도 손상**이 발생하는지 확인한다. 구간·손상·감속 표는 미정이므로 파트 제안과 기획 데이터 확정 후 실행한다. 빈 차량도 좀비 공격 대상이고 좀비가 돌진 차량을 회피하지 않는지 확인한다.

3단계 수취인·결말 추가 절차(모두 미실행):

- 보스 배달 해금 뒤 우체국 지도에 일반 후보 3개와 별도 고정 보스 후보 1개가 함께 보이는지 확인한다. 일반 배송을 완료해도 보스 후보는 유지되고, 네 후보 중 어느 것을 수락해도 활성 팀 배달은 한 건인지 확인한다.
- 미수락 보스 보호·수락 활성화, 인원별 일반 좀비 수/체력만 변경, 보스 체력/시간 유지, 제한시간 실패 시 전투 해제·최대 체력 회복·재도전, AI 처치 이벤트 검증 뒤 배송 무제한 전환을 확인한다. 결말 전 보스 시간 재생성 금지와 결말 뒤 자유 전투 재등장 예외를 구분한다.
- 보스 차량 충돌 피해·밀려나지 않음·선제 공격 인정을 확인한다. 보스의 폭발 근거리 피해는 즉사 판정 없이 **200**을 차감하고 외곽 피해는 **70**을 적용하며, 차량 충돌·폭발에서도 기존 미수락 처치 불가 보호가 우선하는지 확인한다. 자유 전투에서는 보호 해제 상태를 구분하고 처치·배송 전환·보상을 중복 적용하지 않는다. 200/70은 첫 테스트용 임시값이며 반경과 보스 체력은 사용값을 기록한다.
