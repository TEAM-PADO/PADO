# 단계별 통합 검증과 실행 기록

기준: [게임 기획](../기획_PM/00_게임기획.md). 기획·PM과 실행자가 관리하는 검증 기록 원본이다. 담당별 작업 문서에는 자기 인수 항목을 함께 둔다. 결과는 **모두 미실행**이며 실행자가 실제 빌드의 결과와 근거를 기록한다. 단계 구분은 검증 묶음이며 현재 개발 단계나 완료 상태를 확정하지 않는다.

기획·PM이 인수 기준·시나리오와 변경 영향 담당을 관리한다. 코어가 공통 빌드·일정·실행자·결과·수정 담당을 취합하고 공동 항목에 실행 주 담당 한 명을 지정한다. 각 파트가 실행하고 코어가 통과 근거를 제출하면 기획자가 단계 통과를 승인한다. 담당 지정이나 문서 수정만으로 통과 처리하지 않는다.

## 실행 준비

- 같은 빌드의 1/2/4인 리슨 서버에서 호스트·참가자 화면과 서버 기록을 비교한다.
- 1단계는 호스트별 단일 저장 슬롯으로 실행한다. 여러 슬롯의 목록·선택은 단일 슬롯 검증 후 별도 확장 대상이다.
- 한 지도에 우체국·맞은편 총 상점의 안전 구역, 두 건물 사이 야외 좀비 구역, 차량 상점, 가까운 일반 배달지와 약한 좀비를 준비한다.
- 코어 발급 `DeliveryLocationId`가 있는 정상 Anchor와 ID 누락·중복·정의 불일치 사례를 준비한다. `GameState`, `PlayerState` 공개 서버 API·개인 스냅샷 경로를 관측할 기록 또는 디버그 표시를 마련한다.
- 장비·보상·가격·시간·피해·거리 등 사용값은 게임 기획에서 확인한다. **통과 검증에서 테스트용 차나 돈을 지급하지 않는다.** 수치가 바뀌면 표에 복사하지 않고 실행 기록에 사용값을 남긴다.
- 기록에는 **빌드 버전 / 기획 기준 버전 또는 날짜 / 실행 날짜 / 실행자 / 호스트·참가자 수 / 사용한 임시값·변경값 / 실제 결과 / 증거 위치**를 적는다.

## 통과 판정과 기록

- **1단계 통과:** V01~V23을 실제 빌드에서 모두 통과해야 한다. 완료 직후 저장과 우체국 도착 저장은 V09·V10, 총 상점 저장 제외는 V11로 확인한다. 최종 문 앞 체크포인트는 후속 검증 대상이다.
- **다중 슬롯 착수:** 단일 슬롯의 저장·재개·삭제 결과를 기록하고 관련 결함을 해결한 뒤 착수한다. 총·수리·내구도·재합류 기능도 추가될 때 같은 슬롯에서 먼저 검증한다.
- 실패는 `ID / 빌드 / 실행자 / 재현 순서 / 기대 결과 / 실제 결과 / 수정 주 담당 / 협조 파트`로 기록하고 코어가 취합한다. 같은 버그는 한 문제로 묶고 영향받는 ID를 모두 적는다.
- 임시 배달지·좀비 능력치 및 기획값 변경은 결과에 기록한다. 테스트용 차량·자금으로 첫 차 구매 경로를 건너뛴 실행은 **1단계 통과 근거에 포함하지 않는다.**
- 후속 검증은 해당 기능 구현 뒤 실행한다. 미정 수치·규칙은 기획 결정 후 기대값·사용값을 기록하며 결정 전에는 통과 판정하지 않는다.
