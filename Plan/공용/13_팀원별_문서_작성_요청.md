# 팀원별 기술·제작 문서 작성 요청

기획 기준: [기본 기획](00_기획핵심과_미결정.md) · [개발 순서](01_개발순서.md) · [공동 상태·저장 규칙](07_배달_상태와_저장_규칙.md) · [역할·서버 API 경계](14_역할분담과_서버_API_경계.md). 기획자가 정한 첫 콘텐츠판은 [배달 진행표](09_배달_콘텐츠_진행표.md), [경제 초안](10_경제_밸런스_초안.md), [화면 흐름](11_화면_흐름_요구사항.md), [이야기 연출안](12_수취인_이야기_연출안.md)을 따른다.

각 담당자는 **1단계 구현에 필요한 부분부터** 자기 문서의 원안을 쓴다. 기획값 변경이 필요하면 원래 값, 제안 값, 바꾸는 이유, 영향받는 파트를 함께 적어 기획자에게 제안하고 승인받은 뒤 반영한다. 엔진·코드 구조·구현 방식은 담당자가 제안한다.

**호스트가 최종 판정한다는 실행 권한과 개발 담당을 구분한다.** 전투·AI 담당은 자기 기능의 서버 실행까지 구현하고, 네트워크 코어는 공통 요청 검증·소유권·동기화 계약과 배달·보상·부활·방 저장 규칙을 연결한다. 전투는 공격측 명중 재검증·피해 요청과 플레이어 피해·차량 충돌을 구현하고, AI는 적의 서버 피해 수신·체력·보호·피격/사망을 구현한다. 적 피해는 AI의 수신 경로에서 한 번 적용하며, 코어는 처치 최종 인정과 보상을 연결한다. `GameMode` 서버 규칙·`GameState` 공유 복제 상태·방 저장 호출/통합은 코어, `PlayerState` 클래스·돈·인벤토리·개인 장비의 복제·공개 서버 API·개인 저장 스냅샷 직렬화/복원은 플레이어 담당이다. UI/플레이어 입력은 `PlayerController` 등의 Server RPC로 요청하고, UI는 복제 상태와 서버 응답을 표시한다.

## 구현·제작 경계

| 항목 | 주 담당 | 다른 파트와 연결 |
|---|---|---|
| 명중·피해·차량 충돌 | 전투가 서버의 공격측 명중 재검증·피해 요청, 플레이어 피해 처리·차량 충돌 구현 | AI가 서버의 적 피해 수신·체력·보호·피격/사망을 구현하고 적 체력에 한 번 적용. 코어는 공통 요청·소유권 검증과 처치 최종 인정·보상·방 상태 연결. 전투와 코어는 적 피해를 별도로 재적용하지 않음 |
| 체력·장탄·장착 총 HUD | UI가 화면 제작 | 전투는 확정 상태 제공과 호스트/참가자 상태 일치 확인 |
| 공용 월드 상호작용 | 전투가 문·차량·상점·아이템의 대상 탐색·우선순위·캐릭터 입력과 요청 연결 구현 | UI는 대상 안내·메뉴 입력, 코어는 배달·거래 등 요청의 유효성과 결과 확정 |
| `PlayerState`·인벤토리·개인 장비 | 플레이어 담당이 클래스·필드·개인 복제·일반/택배 전용 슬롯·장착·총/택배 드롭 후 줍기·공개 서버 API 구현 | 코어는 보상/배달 택배 규칙·공통 요청 계약을 검증한 뒤 API로 변경 요청. 개인 변수·배열을 직접 수정하지 않음. UI는 복제 상태 표시·요청 |
| 개인 저장·방 저장 | 플레이어 담당이 개인 저장 스냅샷 직렬화·복원 API, 코어가 방 저장 호출·통합과 방 진행/후보/해금/차량 저장 | 코어는 `PlayerState` 스냅샷을 함께 저장하고 복원 API를 호출. 일반 재개는 진행 배달 초기화·완료 진도 복원, 최종 문 앞 체크포인트 예외 유지 |
| 배송지 ID·Anchor | 코어가 ID 생성·변경·폐기와 배달 정의·서버 시작 매칭 검증, 레벨이 발급 ID 할당·공간 배치 | 기획은 표시 이름·배달 유형·보상·목적지 설명·보스 연결이 있는 추가 요청서를 관리. 기획·레벨·UI는 ID를 임의 발급하지 않음 |
| 컷신·부활 연출 | UI/클라이언트가 제작 계획·콘티 초안·카메라·시퀀스·자산 취합·통합/재생 주관 | 기획은 콘티·길이·필수 표현 승인, AI·전투는 캐릭터 동작, 레벨은 공간, 코어는 시작/종료 상태와 팀 동기화. 애니메이션·효과·사운드 등 실제 자산 제작 담당은 UI가 공동 자산 목록의 항목별로 지정 |
| 거리 등급·제한시간·보상 | 기획이 변경값 최종 승인 | 레벨은 측정·변경 제안과 승인 목표에 따른 공간 조정, 코어는 승인된 배달 데이터 반영 |
| 지도 좌표·표시 이름 | UI가 월드→지도 변환·핀 표시, 기획이 게임 표시 이름 확정 | 레벨은 월드 위치·제작용 명칭·도면 기준, 코어는 배송지 ID와 공간/표시 데이터 연결 |

## 파트 공동 결과물

- **제작 자산 목록 — UI/클라이언트 주관:** 레벨·AI·전투가 건물, 좀비·보스, 수취인, 총·차량, 애니메이션, 이펙트, 사운드, 컷신 자산의 필요 항목과 수량을 제출한다. UI가 목록을 취합해 항목별 제작 담당·통합 담당·임시/최종 자산 상태를 명시하고, 기획자가 제작 우선순위를 승인한다. 1단계는 임시 자산을 사용해도 최종 필요 목록을 잃지 않도록 한다.
- **1~3단계 통합 검증 — 기획+PM 기준 관리, 네트워크 코어 실행 조율:** 기획+PM이 [1단계 검증표](08_1단계_통합_검증표.md)와 2·3단계 후속 검증표의 인수 기준·시나리오·변경 영향 담당을 관리하고, 코어가 기술 검증 항목·실행 조율·결과 취합을 맡는다. 각 파트는 자기 항목을 실행하고 빌드·재현·결과·수정 담당을 기록한다. **1/2/4인·호스트/클라이언트·중도 이탈/복귀·저장/재개**를 공통 조합으로 확인한다. 택배 만료·새 택배 재수락·진행 중 교체·드롭 후 줍기·회수 없이 진행, 수락 당시 참가자 재접속 자격 유지/최초 후발 합류 제외/완료 순간 접속 중 보상, 배송지 ID 누락/중복/정의 불일치, 차량 파괴·보스 보호/실패 회복/처치 후 무제한 배송·두 결말, 공개 `PlayerState` API를 통한 개인 데이터 반영과 스냅샷 저장/복원, 문 앞 체크포인트 별도 보존/불러오기/성장 되돌리기, 결말 뒤 일반 배달·보스 자유 전투를 실제 빌드에서 확인한다. 코어가 필수 항목 통과 근거를 제출하고 기획자가 단계 통과를 최종 승인한다. 주관 지정만으로 미실행 항목을 통과 처리하지 않는다.
- **오픈 지도 성능 기준과 측정 결과 — 네트워크 코어 주관:** 코어가 1~4인, 일반 좀비 다수, 여러 대의 차량, 보스전의 공통 빌드·측정 시나리오·수치 목표·측정 방법을 취합한다. 레벨·AI·전투·UI는 자기 영역의 프레임·처리 비용을 측정하고 코어는 네트워크·동기화 비용을 측정한다. 코어가 결과와 개선 담당을 정리하고 기획자가 성능 목표와 체감 품질을 승인한다.

## 첫 회신에서 받을 피드백

각 담당자는 문서를 쓰기 전에 `① 1단계에서 먼저 만들 것 ② 다른 파트가 제공해야 할 ID·상태·자산 ③ 기획의 모호함이나 충돌 ④ 예상되는 성능·일정 위험`을 짧게 회신한다. 특히 네트워크 코어는 저장 직후 보상 중복, 클라이언트 재접속, 총 상점에서 구매 후 저장 전 종료를 어떻게 처리할지 제안한다.
