# 역할 분담과 서버 API 경계

이 문서는 기획·PM, 레벨, 네트워크/코어, AI, 플레이어/전투, UI/클라이언트 시스템의 공통 담당 기준이다. 게임 규칙·수치는 [기획 핵심](00_기획핵심과_미결정.md), 단계별 범위는 [개발 순서](01_개발순서.md), 사건별 결과는 [배달 상태·저장 규칙](07_배달_상태와_저장_규칙.md)을 따른다. 기존 최종 문 앞 체크포인트와 결말 뒤 보스 자유 전투의 예외도 유지한다.

## 핵심 흐름

```text
UI/플레이어 입력
  → PlayerController 등의 Server RPC로 요청
  → 네트워크/코어가 배달·방 규칙과 보상 자격 검증
  → 플레이어 담당자의 PlayerState 공개 서버 API로 개인 상태 변경 요청
  → 복제된 GameState·PlayerState를 UI가 표시
```

총 습득·드롭·사망 아이템 드롭은 플레이어/전투의 서버 처리 경로에서 검증하고 `PlayerState`를 변경한다. 전투는 공격 측 명중 재검증·피해 요청, 플레이어 피해·차량 충돌을 구현하고 AI는 서버 적 피해 수신·체력·보호·피격/사망을 처리한다. 코어는 배달·방 규칙, 처치의 최종 인정과 보상 판정을 맡는다. 같은 피해를 두 경로에서 중복 적용하지 않는다.

## 언리얼 클래스별 소유자

| 항목 | 구현 소유자 | 책임과 경계 |
|---|---|---|
| `GameMode` 및 방 규칙 | 네트워크/코어 | 서버 전용 배달·방·보상 자격·부활 조건 판정 |
| `GameState` | 네트워크/코어 | 현재 배달, 목적지 ID, 서버 시간 기준, 보스 단계, 공용 결말 상태 복제 |
| `PlayerState` | 플레이어/전투 | 개인 돈·인벤토리·총·택배·장비 상태, 복제, 공개 서버 API, 개인 저장 스냅샷 직렬화·복원 |
| `PlayerController`의 요청 경로 | 코어가 공통 계약 제공, 기능 담당이 연결 | 클라이언트 요청의 서버 진입점. UI는 요청·응답 표시에 연결하고 기능별 검증 담당으로 전달 |
| 방별 `SaveGame` | 네트워크/코어 | 방 ID 연결, 저장 시점·파일 입출력·방 상태 통합, 개인 스냅샷 수집과 복원 호출 |
| 배송지 Anchor/Actor 배치 | 레벨 | 코어 발급 ID 할당, 월드 위치·상호작용 범위·문·수취인·마커 위치 제공 |

코어는 `PlayerState`의 변수·인벤토리 배열·개인 저장 직렬화 코드를 직접 수정하지 않는다. 개인 상태 구현 담당과 방 전체 영속 저장을 호출·통합하는 담당을 구분한다.

## 1. 기획 + PM

- 일반 배달 후보 수·교체 조건, 감액 시점·감액량·최종 실패 시간, 보스 해금·처치 제한·보상·재도전 규칙을 확정한다.
- 총·차량 가격, 수리비, 처치 보상, 아이템 정리 시간과 택배 예외를 관리한다. 수치는 기획 데이터로 제공하고 코드에 상수로 고정하지 않는다.
- 배달 이름·설명·보상·거리 등급·난도·수취인 대사, 일반/보스 구분·해금 순서·복선, 최종 선택지와 두 결말 조건을 문서화한다.
- 배송지 추가 요청에 **표시 이름, 배달 유형, 보상, 목적지 설명, 보스 연결 여부**를 적어 코어에 전달한다. ID 문자열이나 열거값은 코어가 발급한다.
- 1·2·3단계 인수 기준과 1/2/4인, 호스트/클라이언트, 이탈·복귀, 저장·재개 시나리오를 관리한다. 기능 변경에는 영향 담당자를 적는다.
- 배송지 ID·데이터 구조 구현, 레벨 위치 지정, `PlayerState` 필드·저장 형식 결정, 서버 판정 코드는 각 구현 담당에게 맡긴다.

## 2. 레벨 디자이너

- 우체국·상점·도로·야외 좀비 구역·배달지와 도보/차량 동선을 제작한다. 차량 회전·정차·파괴 후 복귀, 부활 후 재합류 동선을 검수한다.
- 코어가 발급한 `DeliveryLocationId` 하나를 각 배송지 Anchor/Actor에 할당한다. 문, 배송 상호작용 지점·범위, 수취인 출현 위치, 지도 마커 위치와 거리별 실제 공간을 제공한다.
- 일반 좀비 스폰 가능·금지·밀도 구역, 안전 구역 진입 금지 경계, 보스 전투장의 차량 진입·엄폐·재진입·탈출 공간을 배치한다.
- 총·차량 구매와 수리 위치, 우체국 저장 트리거의 위치·진입 동선을 배치한다. 총 상점은 안전 구역이지만 저장 트리거가 아니다.
- NavMesh 범위·이동 불가 구역, AI·차량이 끼는 지형과 스폰 밀집 구역을 점검한다.
- 인수 시 ID 없는 배송지·중복 ID·정의 없는 ID와 위치/데이터 불일치를 오류로 기록한다. 코어의 서버 시작 검증도 통과해야 후보로 사용할 수 있다.

## 3. 네트워크/코어 게임 플레이 프로그래머

- 1~4인 리슨 서버 방 생성·참가·퇴장·재접속, 방 ID와 `SaveGame` 연결, 호스트 종료·재개를 구현한다.
- 배송지 ID 생성·변경·폐기, 배달 정의 데이터 구조, 서버 시작 시 Anchor와 ID 매칭 검증을 소유한다. 누락·중복·정의 불일치를 검출하고 유효한 Anchor만 후보로 사용한다.
- 일반 후보 최대 3개 보충과 일반 배달의 수락·진행·감액·완료/실패, 보스 3종 순차 해금·수락·처치 제한·배송·재도전, 방당 활성 배달 한 건을 관리한다.
- 수락·교체·배송·문 열기·수취인 확인 예외에서 요청자, 거리, 배송지 ID, 현재 시도·상태, 택배 소지와 선택 권한을 검증한다. 보스 처치 이벤트를 검증해 배송 단계로 전환한다.
- 수락 시 참가자 집합을 기록한다. 수락 당시 참여자는 이탈 후 재접속해도 자격을 유지하며, 완료 순간 접속 중일 때 지급한다. 수락 후 처음 합류한 사람은 해당 완료 보상에서 제외한다.
- 완료·처치 보상 대상과 금액을 계산해 `PlayerState` 공개 서버 API로 지급을 요청한다. 구매 비용 차감, 총·택배 변경과 소지 여부 확인도 공개 API를 사용한다.
- 배달 완료 직후·야외에서 우체국 도착 시 방 저장을 호출한다. 방 진행·후보·해금·차량 상태와 플레이어 제공 개인 스냅샷을 함께 저장한다. 일반 재개는 진행 배달을 초기화하고 완료 진도를 복원한다. 최종 문 앞 체크포인트는 별도 예외로 처리한다.
- `GameState`와 방 전체 복제 상태를 소유한다. `PlayerState` 클래스·내부 변수·인벤토리 배열·개인 직렬화, 레벨 배치, AI 행동·무기 조작·UI 위젯은 해당 담당이 구현한다.

## 4. AI 프로그래머

- 적의 탐지·추적·공격·피격·경직·사망·비활성화, 플레이어/차량 공통 타깃 규약과 서버 의사결정·피해 처리를 구현한다.
- 일반 좀비의 위협 대상 선택, 인원별 수·체력 조정 훅, 야외 재생성, 안전 구역 진입/스폰 금지와 플레이어 주변 스폰 방지를 구현한다.
- 레벨 구역과 플레이어 위치·인원·밀도에 따라 스폰·활성화를 관리한다. 원거리·비가시 적의 갱신 비용을 줄이고 사망·거리·시간 기반 재생성을 관리한다.
- 차량 회피/공격, 충돌 피해 수신·사망, 차량 정지·파괴 후 타깃 전환을 연결한다.
- 배달 단계의 보스 미수락 처치 불가 보호, 수락 활성화·공격 패턴·다인 타깃·사망, 실패 시 전투 해제·최대 체력 회복을 구현한다. 처치 이벤트는 코어에 전달하고 배송 전환·보상은 코어가 판정한다.
- 로봇 수취인의 등장·응답·퇴장·충전 상태와 문 상호작용을 연결한다. 최종 인간은 시네마틱/퀘스트와 연결할 이벤트를 제공한다.
- AI 수·경로 실패·행동·타깃 디버그 도구와 NavMesh 누락·길 막힘·군집 정체 처리를 제공한다.
- 1~4인에 따라 일반 좀비 수·체력만 변하고 보스 체력·배달 시간은 유지한다. 결말 전 보스는 시간 경과로 재생성하지 않으며, 결말 후 자유 전투 재등장은 기존 예외를 따른다.

## 5. 플레이어/전투 프로그래머

- `PlayerState` 클래스와 개인 돈·인벤토리·장비 복제, 공개 서버 API와 개인 저장 스냅샷의 생성·직렬화·복원을 구현한다. 보상·처치 최종 인정과 방 저장 호출은 코어의 판정에 연결한다.
- 3인칭 이동·카메라·달리기·조준·상호작용 사거리, 사망/부활 조작 잠금·복구, 우체국 새 몸과 기본 권총 재지급 흐름을 구현한다.
- 총 발사·장전·탄약·반동·명중 피드백, 히트스캔/투사체 방식과 서버 명중 검증, 총 줍기·드롭·전달, 사망 총·택배 개별 드롭과 무기 데이터 확장을 구현한다.
- 플레이어 피해·사망과 적 피격/사망 애니메이션·효과를 연결한다. 차량 파괴 시 탑승자 사망 처리와 코어 부활 규칙을 연결한다.
- 구매 차량 운전·승하차, 1~4인 좌석, `Ctrl+1~4` 좌석 변경, 빈 운전석의 마지막 가속 이후 감속을 구현한다. 운전자는 사격 불가, 동승자는 창밖 사격 가능 상태를 검증한다.
- 로드킬·내구도 피드백과 차량 네트워크 보정을 검증한다. 소유자 사망 뒤 멀쩡한 차량은 남아 동승자가 운전석으로 옮길 수 있고, 차량 파괴 뒤에는 재구매해야 한다.
- 여유 있는 일반 인벤토리와 **별도 택배 전용 슬롯**을 구현한다. 택배 전달은 **바닥에 드롭한 뒤 동료가 줍는 방식**이며 차량 탑승 중에도 운반 제약이 없다.
- 클라이언트 입력 예측·전투 연출, 발사 요청·명중 검증·차량 충돌 계약과 무기 DPS·생존성 플레이 테스트를 담당한다. 수치는 기획 데이터에서 받는다.
- 혼자서 운전·로드킬·정차 후 사격·재탑승, 2~4인 좌석 변경·동승 사격, 운전자 사망 후 운전 승계, 현장 총·택배 재습득을 인수 기준으로 확인한다.

## 6. UI/클라이언트 시스템 프로그래머

- 화면 전환·모달·팝업 우선순위·입력 모드, 로딩·접속·재접속·호스트 종료, 서버 응답 실패, 공통 알림·토스트·확인창을 구현한다.
- 일반 후보 최대 3개와 별도 고정 보스 항목, 수락 확인·진행 HUD·목적지 마커·남은 시간, 감액/실패·보스 처치 후 무제한 배송 상태를 표시한다.
- 현재 목표와 본인 보상 자격을 중도 합류·재접속 때 동기화한다. 수락 후 최초 합류자와 기존 자격자를 구분해 안내한다.
- 배송·문·택배 드롭/줍기·총·상점·수리·승하차 안내와 불가 사유를 표시한다. 거리·돈·상태·택배에 관한 서버 거절 응답을 사용한다.
- 택배 전용 슬롯, 총·탄약·돈·처치 보상, 드롭·전달, 차량 구매·수리·내구도·좌석 화면을 구현한다.
- 사망·부활 대기·우체국 부활, 전멸 후 시간이 남은 배달 재도전, 수취인 대화와 문 열기/확인 예외를 표시한다. 마지막 선택은 실제 전달자에게만 활성화하고 결과는 전원에게 동일하게 표시한다.
- 팀 공동 컷신·스킵 정책·엔딩·업적을 코어의 결말 상태에 연결한다. 스킵 정책과 연출 명세는 기획 승인을 받아 정한다.
- 키보드/마우스·게임패드, 해상도·안전 영역·색각 보조·자막·UI 스케일, 긴 텍스트·지연·중복 클릭을 처리한다.
- `GameState`·`PlayerState`와 서버 응답을 표시한다. 서버 시간 기준을 표시용으로 이용하되 타이머 만료·감액·보상·자격·결말을 독자 판정하지 않는다.

## 기능별 최종 담당표

| 상황 | 요청하는 역할 | 판정/처리 역할 | 데이터 변경 역할 |
|---|---|---|---|
| 배달 수락 | UI | 코어 | 코어 |

## 함께 확정할 API 계약과 인수 기준

- 플레이어 담당자는 돈 지급·차감, 총 지급·습득·드롭, 택배 지급·조회·제거, 기본 권총 재지급, 개인 저장 스냅샷 생성·복원에 필요한 공개 API와 성공/실패 결과를 제공한다. 구체적인 함수명·필드·직렬화 형식은 구현 담당이 합의하며 이 문서에서 고정하지 않는다.
- 개인 상태를 변경하는 API는 서버 권한에서만 실행한다. 코어는 판정 결과를 넘기고 `PlayerState` 구현 내부로 들어가지 않는다. UI는 값을 직접 변경하지 않는다.
- 완료·처치·구매·드롭·택배 회수의 중복 요청은 서버에서 한 번만 반영한다. 개인 API 반영 뒤의 스냅샷을 방 저장에 묶어 보상과 저장이 어긋나지 않게 한다.
- 기획 요청 → 코어 ID 발급 → 레벨 Anchor 할당 → 코어 시작 검증 → 후보 사용 순서로 배송지를 인수한다. 누락·중복·정의 없는 ID는 오류이며 결과는 기획·레벨과 공유한다.
- 코어는 현재 방의 이탈·재접속 자격을 유지하고, 방 종료 후 일반 저장 재개와 구분한다. 현재 방 재접속에 과거 저장본을 덮어써 돈·인벤토리를 되돌리지 않는다.
- 기획·PM이 단계별 시나리오와 변경 영향 담당을 관리하고 코어가 실행 일정·근거를 취합한다. 각 파트가 실제 확인을 수행하며 문서 수정만으로 미실행 항목을 통과 처리하지 않는다.
