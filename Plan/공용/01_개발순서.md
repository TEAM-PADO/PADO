# 좀비세상 우편배달 — 개발 순서

이 문서는 [기본 기획](00_기획핵심과_미결정.md)을 구현하기 위한 작업 순서다. 확정된 게임 규칙은 기본 기획을 따른다. 아래 단계는 일정이나 인원 배분이 아니라, 팀이 함께 플레이하며 다음 단계로 넘어갈 수 있는 통합 기준이다.

## 공통 기준

- 첫 구현은 1~4인 리슨 서버다. 방장이 게임 상태를 판정하고 방별 진행을 저장한다.
- **게임 저장은 호스트별 슬롯 1개부터** 만든다. 새 게임·저장·불러오기·삭제와 종료 후 재개를 검증한 뒤 여러 슬롯으로 확장한다. 여러 저장 게임의 목록·선택은 1단계 필수 범위에 넣지 않는다. 최종 문 앞 체크포인트는 같은 게임 안의 별도 저장 상태다.
- 메인 메뉴에서 새 게임·이어하기로 방을 열 때 공개/친구(초대 전용)를 선택하고 바로 게임 지도에 들어간다. 공개 방은 게임 참가 목록에 표시하고, 초대 전용 방은 스팀 초대로만 참가한다. 별도 로비 레벨은 없다.
- 새 방은 플레이어마다 기본 권총만 주고 돈·차량은 지급하지 않는다. 배달 중 새로 합류한 참가자는 우체국에서 시작한다.
- 한 방에서 진행 중인 팀 배달은 한 건이다. 일반 배송지는 고정된 위치의 **최소 9곳**으로 시작해 늘릴 수 있고, 최종 후보 화면에는 풀에서 무작위로 뽑은 일반 3개를 유지한다. 완료하면 남은 2개에 새로 뽑은 1개를 보충하며 완료한 곳도 다시 나올 수 있다. 미완료 보스 배달이 해금되면 고정 보스 1개를 더해 총 4개가 된다. 1단계는 후보 1개로 기본 흐름을 검증하고 2·3단계에서 이 표시 개수를 완성한다.
- 팀원 한 명이 우체국에 있을 때만 다음 배달을 수락할 수 있다. 보스는 일반 배달 누적 3·6·9회 완료 시 순서대로 해금한다(첫 테스트 값).
- 우체국 내부·차량 상점·총 상점·배달지는 하나의 오픈 지도에 있으며 플레이 중 이동에 따른 레벨 전환이 없다. 우체국 내부와 총 상점 내부는 좀비 진입 금지 안전 구역이고, 두 건물 사이 도로·보도에는 좀비가 활동한다. 저장 구역은 우체국 내부만이다.
- 일반 저장은 **배달 완료 직후**와 **야외에서 우체국 안전 구역에 도착했을 때** 발생한다. 보스 배송 대기가 없는 일반 저장은 우체국에서 시작하고 완료 진도를 유지하며 진행 배달은 처음부터 다시 받는다. 보스 배달 3종은 각각 제한시간 내 처치 직후 자동 저장하고 해당 배달지 문 앞에서 배송부터 재개한다. 최종 문 앞 결말 선택용 별도 체크포인트도 유지한다.
- 수치와 콘텐츠 규모는 플레이 테스트 뒤 기획 승인으로 조정한다. 레벨은 실제 주행·전투·배송 시간과 공간 변경안을 제안하고, 기획은 거리 등급·제한시간·보상을 확정하며 코어가 데이터에 반영한다. 첫 테스트용 시간·보상 값은 기본 기획의 표를 사용한다.
- 담당 경계는 [역할 분담과 서버 API 경계](14_역할분담과_서버_API_경계.md), 공동 산출물 주관은 [팀원별 작성 요청](13_팀원별_문서_작성_요청.md)을 따른다. 코어는 `GameMode`/`GameState`·배달/방 규칙·보상 자격·방 저장 호출/통합, 플레이어 담당자는 `PlayerState`·개인 상태 복제·공개 서버 API·개인 저장 스냅샷 구현을 소유한다. UI는 서버 요청과 복제 상태·응답 표시를 맡는다.
- 배송지는 기획 요청 → 코어 ID 발급 → 레벨 Anchor 할당 → 코어 서버 시작 검증 순서로 연결한다. 누락·중복·정의 불일치 ID는 오류이며 유효한 Anchor만 후보로 사용한다.
- 기획·PM은 단계별 인수 기준과 1/2/4인·호스트/클라이언트·이탈/복귀·저장/재개 시나리오를 관리한다. 기능 변경에는 영향 담당자를 적고 실제 실행 근거로 단계 통과를 승인한다.

## 1단계 — 배달 한 건이 끝까지 돌아가는 통합판

**목표:** 새 방에서 기본 권총으로 약한 좀비를 처치해 첫 차를 사고, 우체국에서 일반 배달을 수락한다. 차로 이동하며 좀비를 돌파해 배송지 문 앞 상호작용으로 완료·보상을 받고, 팀원 한 명이 우체국으로 돌아오면 다음 건을 고를 수 있다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 기획 + PM | 가까운 배달지 추가 요청, 첫 테스트 수치·게임 규칙·콘텐츠와 인수 시나리오 관리, 실행 근거를 확인한 단계 통과 승인 |
| 레벨디자이너 | 한 지도에 이어진 우체국 내부·앞마당·첫 차량 상점·총 상점 자리·야외 도로·가까운 배달지 1곳·약한 좀비 구역. 코어 발급 ID를 배송지 Anchor에 할당하고 문·상호작용/마커 위치 제공, ID 누락·중복 검수, 이동시간 측정 동선 |
| 네트워크 코어 | 저장 슬롯 1개로 새 게임·이어하기·삭제, 공개/친구 방·공개 목록·스팀 초대 참가, 방 ID·배송지 ID 발급/시작 검증, 한 건의 배달과 서버 타이머·완료/처치 보상 자격·다음 후보 1개, 첫 차 구매 판정, GameState와 차량 최소 동기화, PlayerState API 반영 후 개인 스냅샷을 모아 배달 완료·우체국 도착 방 저장 |
| AI 프로그래머 | 약한 일반 좀비의 추적·공격·사망·재생성. 1~4인에 따른 수·체력 조정의 기본 구조 |
| 플레이어 전투 | PlayerState 클래스·개인 돈/인벤토리/장비 복제·공개 서버 API·개인 저장 스냅샷 생성/복원, 3인칭 이동·기본 권총·호스트 명중 재검증/피해, 첫 차 운전·승하차·충돌·로드킬, 월드 대상 탐색·입력, 일반 슬롯과 택배 전용 슬롯·장착·드롭/줍기·사망 개별 투하, 코어 부활 판정에 따른 새 몸·권총 API·조작 복귀·데이터 동작·전투 HUD용 상태 |
| UI/클라이언트 시스템 | 메인 메뉴·저장 게임 1개의 이어하기/삭제·새 게임·방 공개 설정·목록/초대 입장, 입력 모드·상호작용/서버 거절 안내, 첫 차 구매·코인, 배달 후보 1개·지도 변환/핀·수락/진행시간/목표·완료 표시, 전투 HUD와 택배 전용 슬롯·드롭/줍기 요청, GameState/PlayerState 표시, 기본 부활 카메라·자산 취합·통합/재생 |

**통과 기준:** 새 방의 기본 권총·돈 0·차량 없음에서 시작해 약한 좀비 10마리의 처치 수익으로 첫 차를 사고, 혼자와 2인 이상이 각각 한 건을 끝까지 완료한다. 수락 순간부터 타이머가 흐르고, 자격 있는 참가자만 동일한 완료 보상을 받는다. 완료 직후 방을 종료해 다시 열어도 진도와 보상이 유지되며 플레이어는 우체국에서 시작한다.

사망·부활은 1단계에서 함께 확인한다. 1인·전원 사망 시 자동 부활, 생존자가 우체국 밖이면 부활 대기, 한 명의 내부 복귀로 사망자 전원 부활, 이미 내부에 생존자가 있는 경우, 마지막 생존자 사망 시 자동 부활 전환을 검증한다. 몸에서 우체국으로 데이터가 돌아와 새 몸에 들어가는 기본 연출과, 대기 중에도 배달 타이머가 흐르는 규칙을 확인한다.

## 2단계 — 실패, 성장, 합류와 이어하기

**목표:** 의도하지 않은 종료나 실패가 발생해도 방의 상태가 규칙대로 이어지고, 차와 총을 사며 반복 배달할 수 있다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 기획 + PM | 후보·감액/실패·교체·아이템 정리·경제 규칙과 추가 배송지 요청, 중도 이탈·복귀 및 저장·재개 인수 시나리오 관리 |
| 레벨디자이너 | 같은 지도 안의 가까운·중간·먼 배달지 묶음, 총·차 상점 출입·구매·수리 동선, 무자본 회복용 약한 좀비 구역, 우체국 복귀 동선 |
| 네트워크 코어 | 일반 후보 3개·완료 후 2개 유지와 1개 보충·재수락·교체, 시도별 택배/타이머/보상 자격 판정, 감액·실패·중도 합류/재접속, 총·차 구매/수리 판정과 PlayerState API 호출, 개인 스냅샷을 포함한 방 저장·차량 내구도 복원·저장 사이 종료 처리 |
| AI 프로그래머 | 야외 일반 좀비 재생성, 위치·인원에 따른 밀도 조정, 차량과 플레이어를 대상으로 한 안정적인 적 판정 |
| 플레이어 전투 | 동승 사격·Ctrl+1~4 좌석 변경·빈 운전석 감속, 일반 인벤토리와 택배 전용 슬롯·장착 전환·총/택배 서버 습득/드롭·바닥 전달, 구매/차감·저장 스냅샷 API 확장, 차량 수리/파괴·탑승자 사망·소유자 사망 후 운전 승계 |
| UI/클라이언트 시스템 | 상점·택배 전용 슬롯/인벤토리·좌석·차량 내구도, 감액/실패·서버 거절 안내, 후발 최초 합류자와 기존 자격자·재접속자의 현재 목표/보상 자격 표시, 지연·중복 클릭 처리 |

**통과 기준:** 시간 초과, 전원 사망, 차량 파괴, 배달 중 합류·재합류, 방 종료 후 재개를 실험한다. 진행 중 다른 배달로 교체, 실패한 같은 건의 새 택배 재수락, 현장 회수 없이 배달 지속이 가능한지도 확인한다. 이 단계에서는 배달 진행 중 종료했다면 완료 진도는 보존하고 해당 배달을 처음부터 다시 받는다. 3단계에서는 보스 3종 처치 저장의 문 앞 배송 재개와 최종 문 앞 별도 체크포인트가 예외다. 사망 드롭은 개별로 최근 사망 1회분만 유지하고 다음 사망 때 이전 미회수분을 제거한다. 직접 내려놓은 일반 아이템만 3분 정리하며 택배는 최종 제한시간 초과·완료·중단·교체 때 제거한다.

## 3단계 — 보스 배달과 결말

**목표:** 일반 배달 누적 횟수와 앞 보스 완료 조건으로 보스 배달 3개가 순서대로 열리고, 마지막 선택 뒤에도 같은 방에서 일반 배달과 완료한 보스 3마리의 자유 전투를 계속할 수 있다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 기획 + PM | 보스 3종 해금·재도전·콘텐츠·수취인 대사와 두 결말 조건·수치 확정, 보스/선택/체크포인트 인수 기준 관리 |
| 레벨디자이너 | 보스 목적지 3곳과 전투 공간, 첫 보스 수취인 등장 공간, 둘째 충전 중 로봇 실내, 셋째 마지막 인간 집과 문 앞 체크포인트 공간 |
| 네트워크 코어 | 배달 게임 규칙·진행 사이클, 배송지 ID 관리, 보스 해금·재도전·처치 제한시간, 보스별 수취인 확인 단계와 둘째 확인 생략 보상 차감, 보스 3종 처치 직후 자동 저장·해당 문 앞 배송 재개와 최종 문 앞 체크포인트, 최종 결말과 「ai의 시대」/「인간을 지켜준 로봇」 도전과제 판정·저장 |
| AI 프로그래머 | 보스 3종의 서버 행동·다인 타깃, 미수락 보호·수락 활성화·실패 전투 해제/최대 체력 회복, 처치 이벤트 코어 전달, 로봇 수취인 응답·최종 인간 이벤트, 결말 뒤 자유 전투 재등장 예외 |
| 플레이어 전투 | 보스전 중 사망·재진입, 다수 플레이어와 차량 전투의 마무리, 전투 피드백과 밸런스 조정 |
| UI/클라이언트 시스템 | 일반 후보와 별도인 보스 항목, 처치 제한시간·이후 무제한 배송 표시, 마지막 문 앞 체크포인트·되돌리기 안내, 문 열기/확인 예외 선택, 기획 승인 콘티에 따른 컷신 제작 계획·카메라·시퀀스·자산 취합·통합/팀 재생, 업적 표시 |

**통과 기준:** 보스 3종 각각 처치 직후 자동 저장하고, 문 앞에 도착하기 전 종료해도 해당 배달지 문 앞에서 택배·보상 자격을 복원해 배송을 이어간다. 보스를 시간 안에 잡으면 배송 시간이 무제한이 되고, 못 잡으면 즉시 실패·체력 회복 후 재도전할 수 있다. 최종 문 앞 체크포인트를 불러오면 팀이 선택 직전으로 돌아가 다른 결말을 볼 수 있으며, 체크포인트 뒤의 성장·진도는 되돌아간다. 마지막 배달자는 ‘충전 중’ 응답 뒤 수취인 확인 여부를 결정하고 팀 전원이 같은 결말을 본다. 결말 뒤에도 일반 배달을 받고, 보스 배달 재수락 없이 재등장한 보스와 자유 전투할 수 있다.

보스별로 첫째는 상호작용 후 로봇 등장·수령, 둘째는 실내 충전 중 로봇 확인/확인 생략에 따른 정상·감소 보상, 셋째는 문을 열어 인간 좀비화 해피엔딩·「ai의 시대」 또는 열지 않고 인간 번영·「인간을 지켜준 로봇」을 확인한다. 둘째 차감 수치는 기획 확정 후 실제 금액 검증에 사용한다.

## 통합할 때 먼저 맞출 계약

게임 저장의 다중 슬롯 확장은 별도 후속 작업으로 둔다. 단일 슬롯 저장·재개·삭제 검증을 통과한 뒤 기존 저장 유지, 게임별 데이터 분리, 선택한 슬롯만 삭제되는지 확인한다. 자세한 확장 조건은 [네트워크 코어의 저장 계약](../네트워크_코어/03_네트워크_코어.md)을 따른다.

1. **배달 상태:** 후보 → 수락/진행 → 보상 감소(일반) 또는 보스 처치 완료(보스) → 완료/실패/중단. 진행 중 다른 건 수락은 중단·교체, 실패·중단한 같은 건 재수락은 새 시도다. 상태 전환과 시간 기준은 네트워크 코어가 판정한다.
   배달 규칙·전체 사이클과 배송지 ID 정의·관리는 네트워크/코어가 구현한다. 레벨은 건물·문·상호작용 위치와 동선 등 공간 정보를 제공한다. 일반 배달은 문 앞 상호작용으로 바로 완료하며, 보스 배달의 수취인 등장·확인 선택·보상 차감·결말 판정도 코어의 진행 단계에 연결한다.
2. **보상 자격:** 수락 시 방에 있었고 완료 순간에도 접속 중인 플레이어 목록을 네트워크 코어가 관리한다. 중간에 나갔다 돌아온 사람도 자격을 유지하며 수락 후 최초 합류자는 제외한다. 대상·금액은 코어가 판정하고 지급은 `PlayerState` 공개 서버 API로 반영한다.
3. **상호작용·인벤토리:** 전투가 문·차량·상점·아이템의 월드 대상 탐색·입력, `PlayerState`·일반/택배 전용 슬롯·장착·서버 습득/드롭을 구현한다. 총·택배 전달은 바닥 드롭 후 동료 줍기다. UI는 안내·메뉴/드롭/줍기 요청·복제 슬롯 표시를 담당한다. 코어는 수락·배송·거래 검증과 동기화 계약을 맡으며 개인 배열을 직접 수정하지 않는다. 서버가 요청 결과를 한 번 확정해 전파한다.
4. **전투 결과:** 전투가 서버 공격 측 명중 재검증·피해 요청, 플레이어 피해·차량 충돌을 구현하고 AI는 서버 적 피해 수신·체력·보호·피격/사망을 담당한다. 적 피해는 AI 수신 경로에서 한 번 적용하며 코어는 처치 최종 인정·보상·배달·부활 상태를 연결한다. 호스트의 최종 판정 권한과 기능별 개발 담당은 구분한다.
5. **저장 경계:** 코어가 배달 완료·우체국 도착·보스 배달 3종 처치 확정 직후 방 저장을 호출한다. 완료 진도·후보·해금·차량/내구도와 플레이어 담당의 개인 스냅샷(돈·인벤토리의 총)을 한 묶음으로 저장한다. 개인 스냅샷 생성·직렬화·복원은 `PlayerState` 소유자인 플레이어 담당, 방 `SaveGame` 통합·입출력·복원 호출은 코어 담당이다. 보스 처치 후 배송 대기·활성 택배·보상 자격은 해당 문 앞에서 복원한다. 그 외 일반 재개는 활성 배달·바닥 아이템을 복원하지 않으며 최종 문 앞 별도 체크포인트도 유지한다.
6. **표시·연출:** 전투는 체력·장탄·장착 총 상태와 플레이어 동작, AI는 적·수취인 동작, 레벨은 월드 위치·제작용 명칭·공간을 제공한다. UI는 HUD·지도 변환/핀·컷신 제작 계획과 통합/재생을 맡고 기획은 표시 이름·콘티를 승인한다.
7. **공동 결과물:** UI는 자산 목록 취합·항목별 제작 담당 지정, 코어는 통합 실행 일정·성능 측정과 결과 취합을 주관한다. 기획·PM은 단계별 인수 기준·시나리오와 변경 영향 담당을 관리한다. 각 파트가 실행·측정하고 기획은 자산 우선순위·성능 목표/체감 품질·실제 검증 근거에 따른 단계 통과를 승인한다.
