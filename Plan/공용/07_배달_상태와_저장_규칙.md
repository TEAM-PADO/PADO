# 배달 상태·저장 규칙표

기준: [기본 기획](00_기획핵심과_미결정.md) · [개발 순서](01_개발순서.md). 이 문서는 네트워크 코어, UI, AI, 플레이어 전투, 레벨디자이너가 **같은 사건을 같은 결과로 처리하기 위한 공동 판정표**다. 규칙이 충돌하면 기본 기획을 우선하고 이 표를 갱신한다.

## 공통 원칙

- 방은 1~4인 리슨 서버이며, 호스트가 배달 상태·타이머·돈·아이템·차량·전투 결과를 최종 판정한다. 클라이언트는 요청과 표시를 담당한다.
- 호스트 판정 권한과 구현 담당은 구분한다. 전투는 공격 측 서버 명중 재검증·피해 요청과 플레이어 피해·차량 충돌, 월드 대상 탐색/입력, `PlayerState`·일반 슬롯/택배 전용 슬롯·장착·서버 습득/드롭을 구현한다. AI는 서버 의사결정·적 피해 수신·체력·보호·피격/사망 행동을 담당한다. 코어는 `GameMode`/`GameState`의 배달/방 규칙, 보상 자격·처치 최종 인정·부활 조건·방 저장 호출/통합을 소유한다. 같은 피해를 중복 계산·적용하지 않는다. [역할 분담과 서버 API 경계](14_역할분담과_서버_API_경계.md)의 최종 담당표를 따른다.
- 요청은 `PlayerController` 등의 Server RPC → 담당 서버 검증 → `PlayerState` 공개 서버 API의 개인 상태 반영 → `GameState`/`PlayerState` 복제와 UI 표시로 연결한다. 코어는 개인 필드·인벤토리 배열·저장 직렬화를 직접 수정하지 않는다. UI는 보상·타이머 만료·자격을 독자 판정하지 않고 서버 거절 이유를 표시한다.
- 배송지 ID는 기획 추가 요청을 받아 코어가 발급·변경·폐기하고 레벨이 Anchor에 할당한다. 코어는 서버 시작 시 누락·중복·정의 없는 ID와 Anchor/정의 불일치를 오류로 처리한다. 유효한 ID와 배치가 확인된 Anchor만 배달 후보로 사용한다.
- **배달 게임 규칙과 진행 사이클의 구현 담당은 네트워크/코어다.** 배송지 ID 정의·관리, 후보·수락·교체·재수락, 타이머, 일반 배송·보스 확인 선택, 완료·실패·보상·해금, 결말·도전과제·저장을 연결한다. 레벨은 공간을 제작하고 AI·UI는 코어가 확정한 단계의 행동·표시·연출을 담당한다.
- 새 방의 플레이어는 기본 권총만 지급받고 돈·차량 없이 시작한다. 배달 중 처음 합류한 참가자는 우체국에서 등장한다.
- 한 번에 활성화된 팀 배달은 한 건이다. 첫 콘텐츠판의 일반 목적지는 거리별 3곳씩 총 9곳이며 우체국 지도에 무작위 후보 최대 3개를 표시한다. 완료한 목적지도 바로 재등장할 수 있다. 해금된 보스 배달은 별도 고정 항목으로 둔다. 팀원은 같은 목표를 보되 우체국·상점·야외를 자유롭게 오간다.
- 배달 수락은 우체국에 있는 팀원만 할 수 있다. 팀원이 한 명만 돌아와도 다음 건을 수락할 수 있고, 진행 중에도 다른 건을 수락해 기존 배달을 중단·교체할 수 있다. 동시 진행은 한 건을 유지한다.
- 우체국과 총 상점 내부는 같은 오픈 지도 안의 좀비 진입 금지 안전 구역이다. **일반 저장 지점은 우체국뿐**이며, 최종 배달에 한해 보스 처치 후 마지막 문 앞에 별도 체크포인트를 둔다. 구역 이동에 로딩이 없으므로 배달 타이머는 계속 흐른다.
- 화폐 단위는 **코인**이다. 완료 보상과 일반 좀비 처치 보상은 별개다. 완료 보상은 수락 당시 방에 있었고 완료 순간 접속 중인 사람에게 각각 같은 금액을 준다. 일반 좀비 처치 보상은 처치자 한 명에게 준다. 보스는 처치 자체에 별도 코인을 주지 않는다.

## 일반 배달 상태

| 현재 상태 | 사건·조건 | 다음 상태와 호스트 판정 | 플레이어에게 보이는 결과 |
|---|---|---|---|
| 후보 | 우체국에 있는 팀원 한 명이 수락 | 진행. 유효한 배송지 ID·수락자·참가자 집합을 기록하고 타이머 시작. `PlayerState` 공개 서버 API로 수락자 택배 전용 슬롯에 지급 | 모두에게 목표·남은 시간·택배 소지 상태 표시 |
| 진행 | 첫 시간 기준을 넘김 | 진행 유지, 완료 보상을 정해진 금액만큼 **한 번만** 감소 | 감소한 예상 완료 보상 표시 |
| 진행 | 두 번째 시간 기준을 넘김 | 실패. 완료·보상 불가, 해당 택배를 소지품과 바닥에서 자동 제거. 같은 배달을 재수락할 수 있도록 후보 유지 | 실패·우체국에서 재수락 가능 표시 |
| 진행 | 우체국 팀원이 다른 후보를 수락 | 기존 배달 중단·택배 제거·보상과 완료 횟수 없음. 기존 후보는 재수락 가능 상태로 유지하고 새 배달 수락·택배 지급·타이머 시작 | 팀 목표·소지품·시간·보상 자격을 새 배달로 갱신 |
| 실패 또는 중단 | 우체국 팀원이 같은 배달을 재수락 | 새 시도로 진행. 새 택배 지급, 수락 시각·제한시간·보상 자격 재설정 | 현장 회수 없이 재시도 가능 |
| 진행 | 해당 택배 소지자가 배송지 문 앞에서 상호작용 | ID·거리·현재 시도·택배 소지·마감을 검증하고 수취인 확인 없이 완료. 보상 자격/금액 판정 → `PlayerState` 공개 서버 API로 지급 → 완료 횟수·후보 갱신 → 공개 서버 API와 월드 아이템 경로로 택배 제거 → 반영 후 개인 스냅샷을 포함해 **즉시 방 저장** | 팀 전체에 완료·보상·새 후보 표시 |
| 완료 또는 실패 | 팀원 한 명이 우체국으로 돌아옴 | 다음 배달 수락 가능. 야외에서 우체국 안전 구역에 들어온 사건이므로 저장 | 저장 완료 및 다음 수락 가능 표시 |

배달지는 레벨이 측정한 실제 주행·전투·배송 시간과 변경안을 바탕으로 기획이 가까운·중간·먼 등급과 제한시간·보상을 확정하고 코어가 데이터에 반영한다. 첫 테스트 값은 각각 보상 감소/실패 **4/7분, 6/9분, 8/12분**이며, 보상은 **100→70, 150→120, 200→170**이다. 이 값은 확정 밸런스가 아니다.

## 보스 배달 상태

| 현재 상태 | 사건·조건 | 다음 상태와 호스트 판정 | 플레이어에게 보이는 결과 |
|---|---|---|---|
| 잠김 | 첫 보스: 일반 배달 누적 3회. 둘째: 누적 6회와 첫 보스 배달 완료. 셋째: 누적 9회와 둘째 보스 배달 완료(횟수는 첫 테스트 값) | 조건을 모두 만족하면 다음 보스 후보 해금. 해금된 후보는 완료 전까지 고정 | 지도에 일반 후보와 별도 표시 |
| 후보 | 우체국에 있는 팀원 한 명이 수락 | 보스 전투 진행. 보상 자격 집합을 기록하고 처치 제한시간 시작. 보스 처치 불가 보호 해제 | 팀 전체에 보스 목표·남은 시간 표시 |
| 전투 진행 | 제한시간 안에 AI가 보스 처치 이벤트 전달 | 코어가 현재 보스·시도·마감을 검증하고 배송 대기로 전환. 보스 처치 상태 유지, **배송 시간제한 제거** | 배송 가능·시간제한 없음 표시 |
| 전투 진행 | 처치 제한시간 초과 | 코어가 실패 확정·택배 제거 요청. AI가 전투 해제·체력 최대치 회복·미수락 보호 적용. 보스 후보는 그대로 유지 | 실패·우체국에서 재수락 가능 표시 |
| 전투 진행 또는 배송 대기 | 우체국 팀원이 다른 배달을 수락 | 기존 보스 배달 중단·택배 제거·보상과 보스 진도 없음. 해당 보스를 재도전 초기 상태로 돌리고 미수락 보호 적용. 고정 보스 후보 유지 후 새 배달 시작 | 새 팀 목표와 기존 보스 재수락 가능 표시 |
| 실패 또는 중단 | 우체국 팀원이 같은 보스 배달을 재수락 | 새 시도로 보스 전투 진행. 새 택배·처치 제한시간·보상 자격 설정, 미수락 보호 해제 | 새 택배로 재도전, 현장 회수 불필요 |
| 최종 배달 배송 대기 | 택배 소지자가 마지막 집 문 앞에 도착 | 노크·선택 전 방·참가자 상태, 최종 택배·전달자·보상 자격, 보스 처치와 시간 무제한 상태를 별도 체크포인트에 저장 | 마지막 문 앞 체크포인트 저장 완료 표시 |
| 첫 보스 배송 대기 | 택배 소지자가 문 앞 상호작용 | 로봇 수취인이 나와 수령 후 완료. 기본 보상 지급·보스 진도 갱신·택배 제거·저장 | 선택지 없이 수취인 등장·완료 |
| 둘째 보스 배송 대기 | 택배 소지자가 문 앞 상호작용 | 수취인이 나오지 않아 문 열기/확인 없이 완료 선택을 전달자에게 제공 | 확인 선택 표시 |
| 둘째 보스 확인 선택 | 문을 열고 들어감 | 충전 중인 로봇 확인 후 완료. 기본 보상 지급·보스 진도 갱신·택배 제거·저장 | 로봇 확인·정상 보상 |
| 둘째 보스 확인 선택 | 확인하지 않고 배달 완료 | 완료 처리하되 기본 보상에서 추가 차감. 진도 갱신·택배 제거·저장. 차감액·비율 미정 | 감소 보상·확인 생략 사유 |
| 셋째 보스 배송 대기 | 택배 소지자가 문 앞 상호작용 | 수취인이 나오지 않아 문 열기/열지 않고 완료 선택 제공 | 전달자에게만 최종 선택 표시 |
| 셋째 보스 확인 선택 | 문을 열고 들어감 | 인간 발견·좀비화 컷신·AI 해피엔딩·「ai의 시대」 도전과제. 완료 보상·결말·진도 확정·택배 제거·저장 | 팀 공동 해피엔딩과 도전과제 |
| 셋째 보스 확인 선택 | 문을 열지 않고 배달 완료 | 인간 번영 결말·「인간을 지켜준 로봇」 도전과제. 완료 보상·결말·진도 확정·택배 제거·저장 | 팀 공동 인간 번영 결말과 도전과제 |

결말 전 미수락 보스는 접근할 수 있지만 처치할 수 없다. 다른 팀원이 수락 전에 보스 앞에서 기다려도 된다. 보스는 일반 좀비처럼 시간 경과로 재생성하지 않으며 수락/실패/재도전 상태를 따른다. 보스 체력과 시간은 인원수로 자동 조정하지 않는다. 첫 테스트용 처치 제한시간/보상은 순서대로 **8분/300코인, 10분/400코인, 12분/500코인**이다. 보스 처치 자체에 코인은 지급하지 않는다. 결말 뒤 자유 전투는 아래 재등장 예외를 적용한다. 마지막 배달의 수취인 선택은 아래 결말 규칙을 따른다.

두 결말 중 하나를 본 뒤에도 방을 계속 플레이한다. 일반 후보와 배달은 유지한다. 완료한 보스 3마리는 맵에 재등장해 **배달 수락·택배·처치 제한시간 없이** 자유 전투할 수 있고, 처치 뒤에도 재등장한다. 보스의 체력·공격 패턴·수치는 첫 배달 때와 같고 미수락 처치 불가 보호는 적용하지 않는다. 최종 보스는 플레이어가 먼저 공격할 때만 싸운다. 자유 전투에는 보스 배달 보상이나 별도 처치 코인이 없다. 결말 기록은 지우지 않는다.

## 사건별 소유권·예외 처리

| 사건 | 호스트가 확정할 상태 | 협업·표시 책임 |
|---|---|---|
| 배송지 추가·배치·검증 | 기획 요청에 따라 코어가 ID 발급·정의 관리. 레벨이 Anchor에 할당. 코어가 시작 시 유효성 검증 | 레벨은 ID 누락·중복·정의 없는 배치 오류 수정, UI는 검증된 ID/위치로 마커만 표시 |
| 배달 수락·교체·재수락 | 우체국 수락자와 후보의 유효성 확인. 다른 건 수락이면 기존 배달 중단·모든 위치의 기존 택배 제거 후 새 건 시작. 새 시도마다 택배·타이머·보상 자격 설정. 동시 활성은 한 건 | UI는 교체·재수락과 새 목표 표시, 레벨은 배달지 제공 |
| 배송 | 배송지·현재 시도·택배·전달자·시간·보스 처치를 검증. 일반은 문 앞 상호작용으로 완료, 첫 보스는 수취인 등장 후 완료, 둘째·셋째는 수취인 미등장 선택 결과에 따라 완료 | 코어가 규칙·최종 결과 확정, AI·UI는 유형별 행동·선택·연출 제공 |
| 참가자 이탈·재합류 | 코어가 수락 당시 자격을 유지. 완료 순간 접속 중인 자격자에게만 `PlayerState` API로 지급. 수락 후 처음 합류한 참가자는 전투·배송 가능하지만 해당 완료 보상에서 제외 | UI는 복제된 현재 목표와 서버 판정 본인 자격 표시. 현재 방 재접속은 과거 저장본으로 덮어쓰지 않음 |
| 일반 좀비 처치 | 총격은 발사자, 로드킬은 운전자에게 처치 보상. 일반 좀비만 인원에 따라 수·체력 조정 | 전투가 호스트 명중 재검증·피해·충돌 경로 구현, AI가 적 체력·사망 반응 연결, 코어가 처치자·보상 한 번 확정, UI가 수익 표시 |
| 보스 처치 | 배달 중에는 처치 후 배송 단계 전환. 결말 뒤에는 자유 전투용 재등장. 어느 경우든 처치 자체에는 코인 없음 | 전투의 호스트 피해 경로와 AI의 보호·체력·사망 상태를 코어의 배송/자유 전투 단계에 연결, UI는 배송 완료 보상만 표시 |
| 총 습득·드롭·택배 전달 | 플레이어 전투의 서버 처리에서 거리·아이템 유효성·소유 상태 검증 후 `PlayerState`와 월드 아이템 변경. 전달은 바닥 드롭 후 동료 줍기 | 전투가 개인 슬롯과 월드 아이템 일치 보장, UI는 복제 슬롯·드롭/줍기 요청/응답 표시 |
| 플레이어 사망 | 돈은 유지. 플레이어 전투 서버 처리로 같은 플레이어의 이전 사망 미회수분 제거·현재 소지품 개별 투하·`PlayerState` 갱신. 최근 사망 1회분 유지. 코어가 생존자·우체국 조건으로 부활 판정. 타이머 계속 진행 | 전투가 개별 투하·드롭 정리·입력 중단·데이터 연출, UI가 부활 조건 표시 |
| 전원 사망 | 접속 중인 팀의 생존자가 0명이 되면 사망한 팀원 전원을 우체국에서 자동 부활. 1인 사망도 동일. 진행 중인 배달·보스 상태는 사망만으로 초기화하지 않음 | 코어가 전멸·부활 판정, 전투가 새 몸·`PlayerState` API의 기본 권총 지급·조작 복귀, UI가 안내 |
| 생존자 우체국 도착 | 생존자 한 명이 우체국 내부 안전 구역에 도착하면 사망해 대기 중인 팀원 전원을 부활. 이미 내부에 생존자가 있으면 사망 판정 시 복귀 조건 충족. 앞마당·총 상점은 제외 | 레벨이 내부 경계 제공, 코어가 부활 대상 확정, 전투·UI가 새 몸과 조작 복귀 반영 |
| 바닥 아이템 정리 | 직접 내려놓은 일반 아이템만 3분 후 제거. 사망 드롭은 같은 플레이어의 다음 사망 때 미회수분 제거. 택배는 배달 최종 제한시간 초과·완료·중단·교체 때 모든 위치에서 제거 | 전투·UI가 사망 회차·회수·택배 유효성에 따른 제거 반영 |
| 차량 상태 변화 | 차가 파괴되지 않았다면 소유자 사망 뒤에도 현장 유지. 파괴 시 탑승자 사망. 구매·수리와 내구도는 방 상태에 반영 | 전투가 호스트 운전·좌석·충돌·내구도 동작, 코어가 거래·소유권·저장 연결, UI가 비용·내구도 표시 |
| 보스 수취인 선택 | 둘째는 실내 충전 중 로봇 확인 시 정상 보상, 확인 생략 시 차감(수치 미정). 셋째는 문 열기 시 인간 좀비화·「ai의 시대」, 열지 않으면 인간 번영·「인간을 지켜준 로봇」. 실제 전달자 선택을 코어가 한 번 확정 | UI가 선택 입력·보상 차감 표시와 컷신 제작·통합/팀 재생 주관, AI·전투는 캐릭터 동작 제공, 레벨은 공간 제공 |
| 개인 돈·인벤토리 저장 | 코어가 방 저장 호출·개인 스냅샷 수집·방 `SaveGame` 통합. 플레이어 담당이 `PlayerState` 개인 스냅샷 생성·직렬화·복원 | 코어가 개인 배열/직렬화 코드를 직접 수정하지 않고 공개 스냅샷·복원 API 사용 |

## 사망 드롭과 택배 회수

- 일반 슬롯과 별도 택배 전용 슬롯은 플레이어 담당 `PlayerState`에서 관리한다. 총/택배 드롭·줍기는 전투의 서버 처리로 연결한다. 코어는 배송 때 공개 API로 택배 소지 여부를 확인하고 배달 지급·완료/실패/교체 제거는 공개 서버 API로 요청한다. 바닥 택배는 전투가 제공한 월드 아이템 경로로 제거한다.
- 사망 시 총·택배 등 소지품을 개별로 떨어뜨린다. 월드의 하나의 묶음이나 공용 회수 가방으로 만들지 않는다. 플레이어별 사망 회차를 기준으로 최근 1회분의 미회수 드롭만 관리한다. 같은 플레이어가 다음에 사망하면 이전 회차의 현장 잔여 아이템을 먼저 제거한다.
- 회수한 아이템은 이전 사망의 정리 대상에서 제외한다. 다른 팀원의 사망 드롭과 차량도 제외한다. 택배를 회수했더라도 해당 배달의 만료·완료·중단·교체에 따른 삭제는 적용한다. 사망 드롭은 3분 정리 대상이 아니며, 직접 내려놓은 일반 아이템의 3분 규칙과 구분한다.
- 다음 사망으로 미회수 택배가 사라져도 사망 자체로 배달을 실패시키거나 시간을 초기화하지 않는다. 회수할 수 없거나 회수를 원하지 않으면 우체국에서 다른 건으로 교체할 수 있다. 실패한 배달은 같은 건을 다시 받아 새 택배로 재시도한다. 회수는 배달 지속을 위한 선택이다.
- 택배 만료는 일반 배달의 최종 실패 시각 또는 보스 처치 제한시간을 따른다. 일반 보상 감소 때는 유지한다. 보스 처치에 성공한 뒤에는 배송 시간이 무제한이므로 시간 경과만으로 삭제하지 않는다.
- 재수락과 교체는 새 시도로 처리한다. 이전 시도의 택배·타이머·배송 요청으로 새 시도를 완료하거나 중복 보상을 지급하지 않는다. 새 후보 수락이 유효한 경우에만 기존 배달을 중단하며, 호스트가 기존 택배 제거와 새 배달 시작을 함께 확정한다. 이미 생성한 최종 문 앞 체크포인트는 기존 별도 보존 규칙을 따른다.
- 이 규칙은 현재 열린 방의 현장 아이템 수명이다. 일반 저장은 사망 드롭·사망 회차를 불러와 현장을 복원하지 않는다.

## 플레이어 사망·부활 흐름

| 팀 상황 | 사망한 플레이어의 처리 | 부활 시작 조건 |
|---|---|---|
| 전원 사망(1인 포함) | 우체국에서 전원 자동 부활 | 호스트가 생존자 0명 확인 |
| 생존자가 있고 모두 우체국 밖 | 데이터는 우체국으로 돌아가지만 새 몸으로 들어가지 않고 부활 대기 | 생존자 중 한 명이 우체국 내부 안전 구역에 도착 |
| 생존자 중 한 명이 이미 우체국 내부 | 사망한 팀원을 우체국에서 부활 | 사망 판정 때 복귀 조건 충족으로 처리 |
| 부활 대기 중 마지막 생존자도 사망 | 대기 중인 팀원과 마지막 사망자 모두 자동 부활로 전환 | 호스트가 생존자 0명 확인 |

- 호스트가 사망·부활 대기·부활 진행·생존 상태와 부활 대상을 확정한다. 생존자 도착과 전멸 판정이 겹치거나 여러 명이 함께 도착해도 각 사망자의 새 몸 생성과 기본 권총 지급은 한 번만 처리한다. 생존자는 우체국 밖에 그대로 있을 수 있으며 전원 집결을 요구하지 않는다.
- 연출 흐름은 **기존 몸에서 데이터 이탈 → 우체국으로 이동 → 조건 미충족이면 대기 → 새 몸에 데이터 진입 → 조작 복귀**다. 데이터의 우체국 도착 자체로 생존자 복귀 조건을 충족시키지 않는다. 전원 사망이면 조건 대기를 생략한다.
- 사망·대기·데이터 이동 중에는 이동·공격·줍기·배달 상호작용을 할 수 없다. 부활 완료 후 새 몸을 조작하고 기본 권총을 지급받는다. 돈은 유지하고, 떨어진 총·택배와 멀쩡한 차량은 기존 현장 유지·정리 규칙을 따른다.
- 배달과 보스 처치 타이머는 대기·연출 중에도 계속 흐른다. 사망만으로 보스 체력이나 배달을 초기화하지 않으며, 시간 초과가 발생하면 기존 실패 규칙을 적용한다. 제때 보스를 잡은 뒤 배송 무제한 상태도 유지한다.
- 생존자의 야외→우체국 도착은 기존 일반 저장 사건이다. 사망자의 데이터 귀환·자동 부활 자체를 야외에서 걸어 들어온 도착 사건으로 취급하지 않는다. 부활은 현재 방 안의 진행이며 저장본을 불러오는 재시작과 구분한다.
- UI/클라이언트가 연출 시간·카메라 방식·대기 화면의 후속 명세와 자산 취합·통합/재생을 주관하고 기획자가 승인한다. 전투는 데이터 이탈·새 몸 진입 동작과 조작 복귀를 연결하고 레벨은 우체국 공간을 제공한다. 부활 조건은 위 규칙을 따른다.

## 저장 사건과 복원 범위

코어는 방별 `SaveGame`·저장 시점·공유 상태·차량 저장과 입출력을 구현한다. 개인 돈·총·인벤토리·장비의 저장 스냅샷 생성·직렬화·복원은 플레이어 담당자의 `PlayerState`가 제공한다. 코어는 개인 변경 API의 반영이 끝난 뒤 스냅샷을 수집해 한 묶음으로 저장하고, 재개 시 개인 복원 API에 위임한다. 최종 문 앞 체크포인트도 같은 구현 경계로 저장·복원하되 최종 택배/전달자 등 예외 상태를 포함한다.

| 사건 | 저장 여부 | 저장·재개 시 의미 |
|---|---|---|
| 배달 완료 직후 | **일반 저장** | 완료 진도, 보상 지급, 다음 일반 후보 또는 보스 진행을 같은 저장 결과에 반영 |
| 야외에서 우체국 안전 구역에 도착 | **일반 저장** | 도착한 팀원 한 명으로 방 전체 상태 저장. 같은 안전 구역에 계속 서 있는 동안 반복 저장하지 않음 |
| 최종 보스 처치 후 택배 소지자가 마지막 문 앞에 도착 | **별도 체크포인트 저장** | 노크·선택 전 방·참가자 상태와 최종 택배·전달자·보상 자격, 보스 처치 완료·배송 시간 무제한을 보존. 이후 일반 저장으로 덮어쓰지 않음 |
| 총 상점 출입, 구매·수리, 아이템 이동, 배달 수락·실패, 참가자 퇴장 | **그 사건만으로 저장하지 않음** | 다음 완료·우체국 재도착 또는 최종 문 앞 체크포인트 전에 종료하면 마지막 일반 저장 상태로 돌아감 |

일반 저장 데이터에는 방별 완료 횟수·해금·후보·결말 기록, 참가자별 코인과 인벤토리에 보관한 총, 파괴되지 않은 차량의 종류·소유·남은 내구도를 넣는다. 결말 기록이 있는 방에서는 일반 배달과 완료 보스의 자유 전투를 재개한다. **일반 저장은 진행 중 배달의 타이머·보스 체력·택배 소지, 바닥 아이템, 플레이어의 야외 위치를 재개하지 않는다.** 일반 저장으로 방을 다시 열면 모두 우체국에서 시작하고 멀쩡한 차는 남은 내구도로 우체국 앞에 놓는다. 완료된 배달은 다시 지급하지 않으며, 진행 중이던 배달은 저장된 후보에서 처음부터 다시 받는다. 호스트가 방을 열어 둔 동안의 재합류에는 저장본이 아닌 현재 방 상태를 사용한다.

최종 문 앞 체크포인트는 **선택 전의 방 전체 상태를 별도로 보존**한다. 명시적으로 불러오면 택배 전달자를 포함한 팀이 마지막 문 앞에서, 보스가 처치되고 배송 시간제한이 없는 상태로 재개해 다른 결말을 선택할 수 있다. 체크포인트 뒤에 번 코인·구매한 장비·완료한 일반 배달 진도는 체크포인트 시점으로 되돌아간다. 결말 뒤 일반 저장을 여러 번 해도 체크포인트는 남는다. 최종 배달 보상은 선택한 진행에서 완료할 때 한 번만 지급한다.

**주의할 플레이 경험:** 총 상점이나 차량 상점에서 구매·수리한 뒤 다음 저장 전에 게임을 종료하면 그 변경은 되돌아간다. 배달 실패·중단·교체만으로는 저장하지 않으며, 종료하면 마지막 일반 저장 상태에서 다시 수락한다. 최종 문 앞 체크포인트를 불러오면 이후 성장도 되돌아간다. UI는 저장 완료와 불러오기 시 되돌아갈 범위를 분명히 보여준다.

## 아직 수치·콘텐츠 결정이 필요한 것

보스 배달 3개를 여는 일반 배달 완료 횟수의 첫 테스트 값은 3·6·9회이며, 뒤 보스는 앞 보스 배달 완료도 필요하다. 배송지 추가 요청 항목·코어 발급 ID 연결과 초반 경제값은 [배달 콘텐츠·진행표](09_배달_콘텐츠_진행표.md)와 [경제·밸런스 초안](10_경제_밸런스_초안.md)에 있다. 라이플·샷건·스나이퍼는 첫 테스트에 각각 150코인이다. 실제 건물 위치, 총·차의 개별 성능, 추가 차량 가격, 일반 좀비 이외 적의 처치 수익, 좀비·보스 전투 수치와 결말 후 보스 재등장 간격은 담당 파트의 상세 명세와 테스트로 확정한다. 보스 처치 자체에는 별도 코인이 없다.
