# 화면 흐름·문구 요구사항 — 기획자 기준

기준: [기본 기획](00_기획핵심과_미결정.md) · [배달 상태·저장 규칙](07_배달_상태와_저장_규칙.md) · [역할·서버 API 경계](14_역할분담과_서버_API_경계.md). 이 문서는 화면에서 **무엇을 알리고 어떤 행동을 허용할지** 정한다. 화면 배치·시각 디자인·메뉴/화면 입력은 UI/클라이언트 담당자의 와이어프레임에서 구체화한다. 문·차량·상점·아이템의 월드 대상 탐색·우선순위·캐릭터 상호작용 입력과 요청 연결은 플레이어 전투 담당이며, UI는 선택된 대상의 안내를 표시한다. 배달·방·거래 규칙은 코어가 서버에서 검증하고, 총 습득·드롭·사망 드롭의 서버 처리는 플레이어 담당이 구현한다.

체력·장탄·장착 총 HUD는 전투가 제공한 확정 상태로 UI가 제작한다. `PlayerState` 클래스·돈·인벤토리·개인 장비의 복제와 공개 서버 API·저장 스냅샷 직렬화·복원은 플레이어 담당이 소유한다. 코어는 공통 요청·소유권 계약과 방 저장 호출·통합을 맡고 개인 데이터 변경·복원은 해당 API로 요청한다. UI는 슬롯 화면·이동 요청을 맡는다. 지도는 레벨의 실제 월드 위치·제작용 명칭을 받아 UI가 좌표 변환·핀 표시를 구현하며, 게임 표시 이름은 기획이 확정하고 코어가 배송지 데이터에 연결한다. UI는 코어 발급 ID를 표시·마커 연결에만 사용한다.

UI/플레이어 입력은 `PlayerController` 등의 Server RPC로 요청한다. 코어 서버가 배달·방 규칙을 검증하고 필요하면 `PlayerState` 공개 서버 API로 개인 데이터를 변경한 뒤, UI가 복제된 `GameState`·`PlayerState`와 서버 응답을 표시한다. UI는 보상·타이머·자격·배송 결과를 독자 판정하지 않는다.

## 화면 흐름

**첫 구현의 게임 저장은 호스트별 슬롯 1개**다. 저장이 없으면 새 게임, 저장이 있으면 그 게임의 이어하기·삭제를 제공한다. 기존 저장이 있을 때 새 게임은 삭제 확인 후 진행하며 자동으로 덮어쓰지 않는다. 여러 저장 게임의 목록·선택은 단일 슬롯 검증 후 확장한다. 최종 문 앞 체크포인트는 같은 게임의 별도 저장 상태로 구분한다.

`메인 메뉴 → 게임 시작 → 새 게임/이어하기 → 공개 또는 친구(초대 전용) 선택 → 게임 지도`가 호스트 흐름이다. 저장된 진행 데이터는 게임 시작 화면에서 삭제할 수도 있다. 참가자는 `메인 메뉴 → 게임 참가 → 공개 방 목록 선택 → 진행 중인 게임` 또는 `스팀 초대 수락 → 진행 중인 게임`으로 들어간다. 친구(초대 전용) 방은 공개 목록에 보이지 않는다. **별도 로비 레벨 없이** 방을 열거나 참가가 승인되면 바로 게임에 들어간다.

입장 뒤에는 `우체국 → 배달 후보 지도에서 수락 → 이동·전투 HUD → 문 앞 상호작용(보스별 수취인 단계) → 완료·보상 → 우체국 복귀 → 다음 수락`이 기본 흐름이다. 실패하면 같은 건을 우체국에서 다시 받아 새 택배로 재시도할 수 있다. 진행 중에도 우체국에서 다른 건을 수락해 기존 배달을 중단·교체할 수 있으며 사망 현장 회수는 필수가 아니다. 결말을 본 뒤에도 일반 배달과 성장 플레이로 돌아갈 수 있다.

| 장면 | 플레이어가 알아야 하는 정보 | 허용할 행동과 제한 |
|---|---|---|
| 메인 메뉴 | 게임 시작·게임 참가·게임 종료 | 시작은 저장 데이터/새 게임 선택으로, 참가는 공개 방 목록으로 이동. 스팀 초대 수락 시 해당 게임으로 바로 입장 |
| 게임 시작·방 공개 설정 | 저장 게임 1개의 유무와 진행 정보, 이어하기·삭제 또는 새 게임, 공개/친구(초대 전용) 선택 | 새 게임 또는 이어하기로 방을 열 때 참가 방식을 고르고 바로 게임 지도에 입장. 기존 저장을 삭제한 뒤 새 게임 생성. 검증 후 여러 슬롯의 목록·선택·개별 삭제로 확장 |
| 게임 참가·스팀 초대 | 참가 가능한 공개 방 목록과 참가 실패 이유 | 공개 방은 목록에서 참가. 친구(초대 전용) 방은 목록에 노출하지 않고 스팀 초대로만 참가. 승인되면 진행 중인 게임으로 바로 입장 |
| 방 생성·이어하기 | 방별 진행과 자기 코인·장비, 일반 저장과 최종 문 앞 체크포인트의 차이 | 새 방은 기본 권총만, 코인·차량 없이 시작. 보스 처치 후 배송 대기 저장은 해당 배달지 문 앞에서 재개. 그 외 일반 저장은 우체국에서 재개. 최종 문 앞 체크포인트는 선택 직전 문 앞에서 재개하며 이후 코인·장비·일반 배달 진도가 되돌아감을 불러오기 전에 알림 |
| 우체국 배달 지도 | 고정 배송지 풀에서 무작위로 뽑은 일반 후보 3개, 완료 후 남은 2개 + 신규 1개, 거리·목적지·보상·시간 기준, 해금 시 일반 3개 + 고정 보스 1개로 총 4개, 현재 진행 건과 교체·재수락 가능 여부 | **확인·수락은 우체국 팀원만 가능**. 진행 중 다른 건 수락은 기존 배달을 중단·교체하며 동시 활성은 한 건 유지. 기존 택배 제거·기존 보상 없음·새 시간 시작을 수락 전에 알림. 실패·중단한 같은 건은 새 택배로 재수락 가능. 1단계 후보 1개는 임시 범위 |
| 진행 HUD | 팀의 같은 목표, 목적지 방향, 남은 시간, 택배 소지자, 일반 배달의 현재 예상 보상 또는 보스 처치 단계 | 우체국·상점·도로·배달지 어디에 있어도 진행 상태를 확인. 후보 지도는 우체국에서만 확인 |
| 전투 HUD | 체력·현재 장탄·장착 총 | 전투가 제공한 확정 상태를 UI가 표시. 표시를 위한 체력·탄약 계산을 UI에서 별도로 구현하지 않음 |
| 인벤토리 | 택배 전용 슬롯과 여유 있는 일반 슬롯의 총 등 소지품 표시 | 택배·총 모두 바닥에 떨어뜨린 뒤 동료가 줍는 방식으로 전달. 차량 탑승에 따른 택배 제한 없음 |
| 총·차 상점 | 개인 코인, 구매 가능 물품, 차의 수리 비용·남은 내구도 | 호스트가 코인·소유권·수리 가능 상태를 확정. 라이플·샷건·스나이퍼는 각각 150코인. 탄약 판매와 총·차 판매는 제공하지 않음. 총 상점 출입이나 구매는 저장 사건이 아님 |
| 일반 배달 현관 | 택배 보유·배송 가능 여부·완료 결과 | 택배 소지자가 해당 문 앞에서 상호작용하면 완료. 수취인 등장 대기·문 열기·확인 생략 선택 없음 |
| 수취인 공통 식별 | 직접 만난 수취인의 스캔·인간/로봇 판정 | 만날 때마다 자동 식별. 첫째·둘째는 ‘로봇 확인’, 셋째는 ‘인간 확인’. 문을 열지 않아 만나지 않은 수취인의 정체는 공개하지 않음 |
| 첫 보스 배달 현관 | 처치 완료·로봇 수취인 등장과 식별·수령 | 상호작용하면 수취인이 나오고, 로봇 식별 후 택배를 받아 완료. 확인 선택 없음 |
| 둘째 보스 배달 현관 | 수취인 미등장·문 열기/확인 없이 완료 선택·보상 차이 | 전달자만 선택. 들어가면 충전 중 로봇 확인·정상 보상, 확인하지 않으면 감소 보상. 차감액·비율 미정이며 시간 지연 차감과 구분 |
| 보스 목적지 | 보스 처치 여부와 남은 처치 제한시간, 처치 직후 자동 저장·문 앞 재개 | 보스 3종 모두 제때 처치하면 배송 단계·시간 무제한으로 전환. 서버 저장 성공 응답 후 자동 저장 완료와 해당 배달지 문 앞에서 이어하기 안내 |
| 월드 상호작용 | 수락·배송·택배/총 드롭·줍기·구매·수리·승하차 가능 여부 | 거리 부족·돈 부족·상태 불일치·택배 없음 등의 서버 거절 이유를 응답으로 표시. 중복 입력·응답 지연 중 요청 대기 상태를 표시 |
| 차량 탑승 | 차량 내구도·속도·좌석 구성·현재 좌석·운전자 여부, 문 근처 탑승 0.5초 유지와 거리 이탈 시 초기화 | 주행 중 탑승과 완료 요청 순서·운전석 우선 배정을 안내. `Ctrl+1~4`로 사격·재장전 중에도 빈 좌석에 즉시·연속 변경 가능, 점유 좌석 이동 불가. 운전자 사격 불가·동승자 사격 가능과 운전자 사망 후 좌석 이동을 서버 확정 상태에 맞춰 표시 |
| 차량 하차·파괴 | 즉시 하차와 속도별 위험, 내구도 손상·폭발·탑승자 사망 | 하차 20km/h 이하 피해 0, 20 초과~60 이하 피해 50, 60 초과 즉사 안내. 창밖 사격 중에도 차량 보호, 내구도 0 즉시 폭발·탑승자 사망, 폭발 근거리 플레이어/일반 좀비 즉사·보스 피해 200·차량 즉시 파괴, 외곽 피해 70과 벽 차폐를 서버 결과로 표시. 고속 충돌·높은 낙하는 큰 내구도 손상으로 안내하며 미정 반경·손상 구간/수치는 임의로 표시하지 않음 |
| 완료·실패·중단 결과 | 결과 원인, 지급 보상, 택배 제거, 다음 행동 | 완료 직후 서버의 저장 성공 응답을 받은 뒤 저장 완료 표시. 실패·중단은 완료 보상 없음, 같은 배달 재수락 안내. 만료·교체된 택배는 줍기·배송 불가. 우체국에서 새 택배를 받아 진행하므로 현장 회수를 필수 목표로 표시하지 않음 |
| 사망·부활 대기 | 현장에 떨어진 소지품, 돈 유지, 생존자 복귀 필요 여부와 우체국 방향 | 생존자가 모두 우체국 밖이면 사망자는 대기. 생존자 한 명이 우체국 내부에 도착하면 사망한 팀원 전원 부활. 이미 내부에 생존자가 있어도 조건 충족. 사망자의 이동·공격·줍기·배송 입력 중단 |
| 전원 사망·부활 진행 | 전원 사망 시 자동 부활, 데이터 귀환과 새 몸으로의 진입 단계 | 1인 포함 전멸 시 우체국 자동 부활. 새 몸 조작 시 기본 권총 지급. 부활 대기·연출 중에도 배달 시간은 계속 진행 |
| 보스 배달 안내 | 보스 목적지가 의심 주소라는 시스템 안내 | 첫 두 보스의 수취인은 평범한 로봇. 최종 배달은 '매우 의심스러운 주소'로 안내하고 반드시 수취인을 확인하라는 지시를 표시 |
| 최종 문 앞 저장점 | 보스 처치 후 택배 소지자가 문 앞에 도착한 선택 전 상태 | 별도 체크포인트 저장 완료를 표시. 이후 일반 저장과 별개로 불러와 다른 결말을 선택할 수 있게 함 |
| 최종 배달·결말 | 수취인 미등장·문 열기/열지 않고 완료 선택 | 코어가 확인한 실제 전달자에게만 선택 활성화. 들어가면 인간 발견·좀비화 해피엔딩 컷신·「ai의 시대」 도전과제. 열지 않으면 인간 번영 결말·「인간을 지켜준 로봇」 도전과제. 서버가 확정한 결과로 팀 전원이 같은 결말을 봄. 문을 연 결말에서만 좀비 한 마리가 집 밖으로 나오고 집 안은 비어 있음 |
| 결말 이후 | 일반 배달 지속과 보스 재등장 | 같은 방에서 코인·장비를 늘리며 일반 배달을 계속하고, 완료한 보스 3마리와 배달 수락 없이 자유 전투할 수 있음을 안내. 자유 전투 보상은 없음 |

## 반드시 구분해서 보여줄 상태

- **일반 배달:** 첫 시간 기준 전/후의 예상 완료 보상, 최종 마감, 실패 여부. 보상은 첫 기준을 넘긴 뒤 한 번만 감소한다.
- **보스 배달:** 보스 처치 제한시간, 처치 성공 뒤 배송 무제한, 실패 시 재수락 가능 여부. 일반 후보와 섞지 않는다.
- **보스별 확인:** 첫째는 로봇 등장·수령, 둘째는 미등장 선택과 충전 중 로봇·확인 생략 보상 차감, 셋째는 미등장 선택과 두 결말·두 도전과제를 구분한다. 보상 차감액을 확정하기 전 임의의 코인이나 비율을 표시하지 않는다.
- **개인 보상 자격:** 코어가 기록한 수락 시 참가자 명단과 완료 순간 접속 상태에 따른 자격을 표시한다. 당시 참가자가 이탈 후 재접속하면 자격을 유지하고, 수락 후 처음 합류한 참가자는 목표에는 참여하지만 그 건의 완료 보상을 받지 않는다. 합류·재접속 화면에서 현재 목표와 자기 자격을 함께 동기화한다.
- **저장 상태:** 배달 완료·야외→우체국 도착·보스 배달 3종 처치 직후 서버의 저장 성공 응답을 받은 때 완료를 표시한다. 보스 처치 후 배송 대기는 해당 배달지 문 앞에서, 그 외 일반 저장은 우체국에서 재개함을 안내한다. 우체국 도착 저장이 갱신돼도 활성 보스 배송 대기의 문 앞 재개는 유지한다. 상점 출입·구매·수리만으로는 저장 완료 표시를 띄우지 않는다. 기존 최종 문 앞 별도 체크포인트의 저장 완료·불러오기와 이후 성장·진도가 되돌아가는 안내도 유지한다.
- **후보 지도와 목표 안내:** 후보 선택 지도는 우체국 전용이다. 야외에서는 이미 수락한 목표와 목적지 안내를 계속 볼 수 있어야 한다.
- **부활 상태:** 생존자가 우체국 밖이면 사망자에게 “부활 대기 · 생존자의 우체국 복귀 필요”, 생존자에게 “우체국에 복귀하면 사망한 팀원 전원 부활”과 우체국 방향을 표시한다. 전멸 시 “전원 사망 · 우체국 자동 부활”, 새 몸 진입 단계에는 “새 몸 복원 중”, 완료 시 “부활 완료 · 기본 권총 지급”으로 구분한다. 우체국 앞마당·총 상점 도착은 복귀 완료로 표시하지 않는다.
- **사망 드롭:** 아이템별 줍기 안내를 표시한다. “사망 아이템은 다음 사망 전까지 회수 가능”을 알리고, 다음 사망 시 이전 현장 잔여 아이템의 안내를 제거한다. 이미 회수한 아이템은 유지한다. 한 묶음 회수 UI는 제공하지 않는다.
- **택배와 재시도:** “택배 만료 · 우체국에서 재수락 가능”, “배달 중단 · 새 배달 시작”을 구분한다. 택배 회수는 선택이며, 교체·재수락 후 새 택배·목표·시간·본인 보상 자격을 표시한다. 만료 삭제는 최종 실패 시각에 적용하고 보상 감소와 구분한다.

## 클라이언트 공통·접근성 요구사항

- 화면 전환·모달·팝업 우선순위·입력 모드와 키보드/마우스·게임패드 입력 문맥을 관리한다. 공통 알림·토스트·확인창을 사용한다.
- 로딩·접속·재접속·호스트 종료와 네트워크 상태·서버 응답 실패를 안내한다. 재접속 뒤 서버 상태를 받은 후 현재 배달·개인 장비·보상 자격을 표시한다.
- 상호작용 가능/불가 이유와 구매·수리 비용은 서버가 제공한 정보로 표시한다. 최종 거절은 서버 응답을 사용하며 로컬 추측으로 결과를 확정하지 않는다.
- 긴 텍스트·접속 지연·중복 클릭·응답 지연·해상도·안전 영역·색각 보조·자막·UI 스케일을 확인한다.
- 전원 공유 컷신의 진입·스킵 정책은 기획이 확정하고 코어의 시작/종료 상태와 연결한다. 확정 전 임의의 개인 스킵으로 팀 결말 상태를 바꾸지 않는다.

인수 시 HUD·메뉴가 같은 서버 판정 상태를 표시하고, 최초 후발 합류자와 재접속자가 자기 보상 자격을 구분하며, 마지막 선택은 실제 전달자만 활성화되고 전원에게 같은 결과가 표시되는지 확인한다.

## 사망·부활 연출

플레이어의 기존 몸에서 데이터가 빠져나와 우체국으로 이동하고, 우체국의 새 몸에 들어가 조작이 돌아오는 느낌을 전달한다. 생존자 복귀 조건이 남아 있으면 우체국에 도착한 데이터가 대기하는 장면을 보여주고, 조건 충족 후 새 몸에 들어간다. 전멸하면 복귀 대기 없이 이 흐름을 완료한다. 데이터는 작은 청록·흰색 입자를 연출 후보로 사용하며, 총·택배·차량은 현장에 남는다. 대기·전송 중 체력은 0으로 표시하고 조작 복귀 전까지 공격·줍기 안내를 제공하지 않는다. 생존자의 플레이는 계속 진행한다. UI/클라이언트가 연출 길이·카메라·대기 화면 명세와 자산 취합·통합/재생을 주관하고 기획자가 승인한다. 전투는 데이터 이탈·새 몸 진입 동작과 조작 복귀, 레벨은 우체국 공간, 코어는 부활 시작/완료 상태·팀 동기화를 연결한다. 효과·사운드 등 자산 제작 담당은 UI가 공동 자산 목록의 항목별로 지정한다.

## 문구 톤

우체국 시스템과 수취인은 감정을 크게 드러내지 않는 **담담한 업무 말투의 블랙코미디**를 기본으로 한다. 수취인 확인 예외나 보상 감소도 행정 처리처럼 간결하게 알린다. 일반 배달 화면에는 마지막 인간의 정체를 암시하는 특별한 경고·색상·효과를 넣지 않는다. 최종 배달에는 의심 등급과 수취인 확인 지시를 평소 업무 안내 형식으로 표시한다.

## UI 담당자에게 요청할 결과물

이 요구사항을 바탕으로 메인 메뉴·저장 데이터 선택/삭제·방 공개 설정·공개 방 목록/스팀 초대 입장, 우체국 배달 지도, 진행·전투 HUD, 상점·인벤토리, 현관 선택, 완료·실패, 사망·부활, 결말 화면의 **흐름도와 와이어프레임**을 만든다. 각 화면은 1/2/4인, 호스트/클라이언트, 일반/보스 배달, 자격 있는/없는 참가자, 이탈·복귀·저장·재개 상태를 모두 표시할 수 있어야 한다. 화면별로 `GameState` 공유 상태·`PlayerState` 개인 상태·서버 응답과 연결되는 항목을 적는다. UI가 부활·결말의 콘티 초안과 카메라·시퀀스·필요 자산·항목별 제작 담당을 포함한 **연출 제작 명세**를 취합하고 기획 승인 뒤 통합·팀 재생을 구현한다. AI·전투는 캐릭터 동작, 레벨은 공간, 코어는 시작/종료 상태를 제공한다.
