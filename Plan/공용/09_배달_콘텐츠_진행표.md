# 배달 콘텐츠·진행표 — 첫 콘텐츠판

기준: [기본 기획](00_기획핵심과_미결정.md) · [배달 상태·저장 규칙](07_배달_상태와_저장_규칙.md) · [역할·서버 API 경계](14_역할분담과_서버_API_경계.md). 이 문서는 첫 번째로 결말까지 플레이할 수 있는 판의 **배달 수·거리·수취인 유형·해금 순서**를 정한다. 아래 요청 항목명은 문서에서 구분하기 위한 이름이며 ID 문자열·열거값이 아니다. **실제 배송지 ID의 생성·변경·폐기와 배달 정의 구조·진행 사이클 구현은 네트워크/코어 담당자가 맡는다.** 코어 발급 전 실제 ID는 미정이며, 레벨디자이너는 발급받은 ID를 실제 배송지 Anchor/Actor에 할당하고 건물·문·좌표·동선을 배치한다.

## 일반 후보 생성

- 우체국에서만 배달 후보 지도를 열고 수락한다. 최종 규칙의 일반 후보는 전체 배송지 풀에서 **서로 다른 목적지 3개**를 무작위로 보여준다. 1단계 통합판은 후보 1개로 기본 흐름을 먼저 검증한다.
- 일반 배달 완료 시 그 자리를 새 후보로 채운다. 다른 두 후보와 중복하지 않는 범위에서 방금 완료한 목적지도 다시 뽑힐 수 있다. 실패·중단한 배달은 같은 건을 다시 받을 수 있도록 후보에 유지한다.
- 동시에 활성화되는 팀 배달은 한 건이다. 우체국에 있는 팀원은 진행 중에도 다른 배달을 수락해 기존 건을 중단·교체할 수 있다. 기존 택배는 제거하고 새 택배·타이머·보상 자격을 설정한다. 실패한 건을 재수락할 때도 새 시도로 시작하므로 현장 택배 회수는 필수가 아니다.
- 보상이 한 번 감소한 일반 배달도 정상 완료라면 완료 횟수에 포함한다. 실패한 배달은 완료 횟수에 포함하지 않는다.
- 후보 목록과 완료 누적 횟수는 방별 진행으로 저장한다. 배달 완료는 즉시 저장하고, 야외에서 우체국에 도착할 때도 저장한다.
- 후보 생성·교체·타이머·완료/실패는 코어 서버가 판정한다. 코어가 정의한 ID와 레벨 Anchor의 매칭 검증에 통과한 목적지만 후보가 된다. UI는 복제된 후보·진행 상태를 표시하고 수락을 요청한다.

## 보스 배달 3회

| 요청 항목(문서용) | 해금 조건: 일반 배달 누적 완료 | 첫 테스트 처치 제한시간/완료 보상 | 목적지와 역할 |
|---|---:|---|---|
| 첫 보스 배송지 | 3회 | 8분 / 300코인 | 처치 후 문 앞 상호작용하면 로봇 수취인이 나와 수령·완료. 선택지 없음 |
| 둘째 보스 배송지 | 6회 및 첫 보스 배달 완료 | 10분 / 기본 400코인 | 처치 후 수취인이 나오지 않아 선택. 들어가면 충전 중인 로봇 확인·정상 보상, 확인하지 않으면 감소 보상(차감액·비율 미정) |
| 최종 보스 배송지 | 9회 및 두 번째 보스 배달 완료 | 12분 / 500코인 | 수취인이 나오지 않아 선택. 들어가면 인간 좀비화 해피엔딩·「ai의 시대」, 열지 않으면 인간 번영 결말·「인간을 지켜준 로봇」 |

해금된 보스 배달은 일반 후보와 별도 고정 항목으로 남으며, 원할 때 우체국에서 수락한다. 미완료 보스가 열려 있으면 일반 후보 3개와 보스 후보 1개로 총 4개가 보인다. 일반 배달을 더 해도 된다. 결말 전 의뢰 단계의 보스는 미수락 상태에서 처치할 수 없고 시간 경과만으로 재생성하지 않는다. 보스 처치 제한시간을 넘기면 코어가 실패를 판정하고 AI가 전투 해제·체력 최대 회복을 처리한 뒤 같은 보스 배달을 다시 받을 수 있다. AI가 서버의 보스 처치 이벤트를 코어에 전달하면 코어가 현재 의뢰와 제한시간을 검증해 배송 단계로 전환한다. 시간 안에 처치한 뒤에는 배송 제한시간이 없다. 보스 배달 자체는 일반 배달 완료 횟수에 포함하지 않는다.

최종 보스 배달에서 보스를 처치한 뒤 택배 소지자가 마지막 집 문 앞에 도착하면, 노크와 결말 선택 전에 **문 앞 체크포인트를 별도로 저장**한다. 어느 결말을 보거나 일반 배달을 계속한 뒤에도 이를 불러와 다른 결말을 선택할 수 있다. 불러오면 코인·장비·일반 배달 진도를 포함한 방 상태가 문 앞 시점으로 돌아간다. 체크포인트에는 보스 처치 완료와 배송 시간 무제한, 최종 택배·전달자·보상 자격을 남긴다. 코어가 체크포인트 저장·복원을 통합하며, 개인 돈·인벤토리·장비는 플레이어 담당자가 제공한 `PlayerState` 저장 스냅샷과 복원 API를 사용한다.

보스 처치 자체에는 별도 코인을 주지 않는다. 자격 있는 참가자는 배송 완료 시에만 표의 기본 보상을 받되 둘째에서 확인 생략 시 추가 차감한다. 결말을 본 뒤에도 같은 방에서 일반 배달을 계속한다. 완료한 보스 3마리는 맵에 재등장해 **배달 수락 없이 자유 전투**로 다시 싸울 수 있고, 처치 뒤에도 반복해서 등장한다. 자유 전투에는 보스 배달 보상이나 별도 처치 코인을 지급하지 않으며 보스의 체력·공격 패턴·수치는 첫 배달 때와 같다. 최종 보스는 먼저 공격받을 때만 싸우고 처치 불가 보호는 해제된다. 재등장 간격과 초기 위치는 AI·레벨 파트가 제안한다. 보스 외형과 패턴은 사용할 에셋을 확인해 정한다.

## 레벨·AI 파트가 채울 연결 정보

네트워크/코어 담당자는 배송지 ID와 데이터 구조를 정의·관리하고 레벨의 건물·문·상호작용 위치를 배송지 데이터에 연결한다. 레벨디자이너는 건물·현관·실제 월드 위치·제작용 명칭·차량 접근 경로·안전 구역과의 거리 등 공간 정보를 제공하고 코어 발급 ID를 Anchor/Actor에 할당한다. 모든 배송지 Actor는 유효한 ID 하나를 가지며, 누락·중복·정의 없는 ID는 코어의 레벨 시작 검증과 레벨 검수에서 오류로 처리한다. 도면 픽셀 좌표는 제작용 자료이며 UI가 월드→지도 좌표 변환과 핀 표시를 구현한다. 게임 표시 이름은 기획자가 확정하고 코어가 배송지 데이터에 연결한다. AI는 보스 3종의 행동·미수락 보호, 첫 보스 수취인 등장, 둘째 충전 중 로봇과 셋째 인간의 반응을 코어가 확정한 단계에 연결한다. **레벨은 실제 1~4인 주행·전투·배송 시간과 등급·제한시간 변경안을 제출하고 기획자가 거리 등급·제한시간·보상을 승인한 뒤 코어가 반영**한다. 레벨은 승인된 목표에 따라 도로·공간을 조정한다. 수취인 연출은 [이야기·연출안](12_수취인_이야기_연출안.md)을 따른다.

## 배송지 추가 요청과 콘텐츠 확정

기획+PM은 새 배송지마다 아래 요청서를 작성해 코어에 전달한다. 기획·레벨·UI는 ID 문자열이나 열거값을 직접 만들지 않는다. 코어가 발급한 ID를 받은 뒤 레벨은 Anchor를 배치하고, 코어는 정의·배치의 일치를 검증한다.

| 요청 항목 | 기획이 작성할 내용 |
|---|---|
| 표시 이름 | 게임에 보일 이름. 현재 12곳의 최종 표시 이름은 미정 |
| 배달 유형 | 일반 또는 보스 |
| 보상 | 위 표의 기본 보상·감액 규칙. 둘째 보스 확인 생략 차감액·비율은 미정 |
| 목적지 설명 | 필요한 건물·현관·수취인 상황과 거리 등급. 실제 Transform·공간 배치는 레벨 담당 |
| 보스 연결 여부 | 연결 없음 또는 첫째·둘째·최종 보스와의 연결 |

기획은 요청서와 함께 배달 설명·난도·수취인 대사·해금 순서·복선 여부를 채우고, 최종 배달의 선택지와 두 결말 조건을 관리한다. 수치·규칙을 바꾸면 영향받는 레벨·AI·플레이어·코어·UI 담당과 관련 문서를 함께 명시한다.
