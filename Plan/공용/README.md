# 공용 기획 문서

모든 담당자가 공유하는 게임 규칙, 첫 콘텐츠판 입력, 통합 확인 기준이다. 담당별 구현 방식과 산출물은 각자의 폴더에 둔다.

| 읽는 순서 | 문서 | 용도 |
|---|---|---|
| 1 | [기획 핵심과 미결정](00_기획핵심과_미결정.md) | 확정된 게임 규칙과 남은 결정 |
| 2 | [개발 순서](01_개발순서.md) | 단계별 통합 목표와 담당 범위 |
| 3 | [배달 상태와 저장 규칙](07_배달_상태와_저장_규칙.md) | 배달·보상·저장의 공동 판정 |
| 4 | [1단계 통합 검증표](08_1단계_통합_검증표.md) | 실제 빌드에서 확인할 항목 |
| 5 | [배달 콘텐츠·진행표](09_배달_콘텐츠_진행표.md) | 배송지 추가 요청·코어 발급 ID 연결과 해금 순서 |
| 6 | [경제·밸런스 초안](10_경제_밸런스_초안.md) | 첫 플레이 테스트용 수치 |
| 7 | [화면 흐름 요구사항](11_화면_흐름_요구사항.md) | 플레이어에게 보여줄 상태와 행동 |
| 8 | [수취인·이야기·결말 연출안](12_수취인_이야기_연출안.md) | 수취인 반응과 결말 제작 기준; 스포일러 포함 |

| 공통 담당 기준 | [역할 분담과 서버 API 경계](14_역할분담과_서버_API_경계.md) | 6개 역할·클래스 소유자·기능별 최종 담당표 |

전체를 처음부터 끝까지 읽기 어려우면 **1~3번, 공통 담당 기준과 자기 담당 폴더의 안내문**부터 읽고, 안내문에 적힌 콘텐츠 입력을 이어서 확인한다. 수치가 '첫 테스트 값'인 경우 확정 사양으로 취급하지 말고 플레이 결과와 함께 조정 제안을 남긴다.

기획·PM은 이 폴더에서 게임 규칙·수치·콘텐츠·배송지 추가 요청과 1·2·3단계 인수 시나리오를 관리한다. 배송지 ID 발급은 코어, 실제 위치·Anchor 배치는 레벨, `PlayerState` 필드·개인 저장 스냅샷 구현은 플레이어 담당자에게 맡긴다. 기능 변경 시 영향 담당자와 함께 요청을 기록한다.
