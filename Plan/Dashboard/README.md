# PADO 프로젝트 대시보드

`대시보드_열기.cmd` 또는 `index.html`을 열면 브라우저에서 사용할 수 있다. 설치, 로그인, 인터넷 연결, 별도 서버가 필요 없다. 팀원도 이 폴더와 상위 Plan 자료를 함께 받으면 같은 화면을 볼 수 있다.

## 확인하는 것

- **한눈에 보기:** 1단계 목표, 확인된 구현 기반, 결정할 일, 주의할 연결.
- **최근 변경:** 최근 로컬 Git 이력과 기획 관점의 검토 요약. GitHub에서 받지 않은 변경은 포함하지 않는다.
- **작업·담당:** 1단계 범위를 작업으로 정리한 표. 실제 목표일과 개인 담당자는 정하지 않았다.
- **기획 결정:** 문서에 남은 결정, 파트 제안 요청과 관련 근거.
- **통합 검증:** 공용 검증표의 실제 결과. 미실행은 완료로 표시하지 않는다.
- **문서·도면:** 원문 읽기, 검색과 실제 존재하는 블록아웃 이미지 확대.

## 팀 변경을 받은 뒤

1. 평소 방식으로 GitHub에서 팀 변경을 받는다.
2. Codex에 `팀 변경 받았어. 지난 검토 이후 변경을 확인해서 Plan 대시보드의 현황·결정할 일·검증 결과를 갱신해줘.`라고 요청한다.
3. Codex는 변경된 문서·코드·검증 근거를 읽고 `review.json`의 요약을 갱신한다. 코드 존재만으로 실행 검증 완료를 판단하지 않는다. 기획 제안을 사용자 확정으로 승격하지 않는다.
4. 검토를 마친 뒤 `Refresh.ps1 -ConfirmReview`를 실행하여 검토 기준과 원문 묶음을 갱신한다.
5. 브라우저를 새로고침한다. 대시보드 파일을 함께 커밋하면 팀원도 같은 요약을 받는다.

`자료_새로고침.cmd`는 현재 Plan 문서·Git 이력·검증표를 다시 묶는다. **기획적 판단이나 구현 상태 요약은 자동으로 바꾸지 않는다.** 검토 기준 이후 문서·코드가 달라졌으면 재검토 안내가 표시된다. GitHub에서 변경을 받는 동작은 수행하지 않는다.

## 기록과 근거

- 원본 기획은 기존 공용·담당별 Markdown 문서에 유지한다. 대시보드에서 원문을 읽어도 수정하지 않는다.
- `review.json`: 사람이 검토한 기능·작업·결정·변경 요약과 검토 기준. 기존 문서의 내용을 근거로 갱신한다.
- `dashboard-data.js`: 새로고침 스크립트가 만든 문서·Git·검증표 묶음. 직접 편집하지 않는다.
- 결정 항목의 **검토 메모**는 이 브라우저에만 저장되는 개인 초안이다. 기획 확정이나 팀 공유 기록이 아니다. **메모 내보내기**로 파일을 받아 Codex에 전달한 뒤 원본 문서에 반영한다. 저장이 차단되면 화면에 안내하며 내보내기는 계속 가능하다.
- 대시보드가 실제 파일 목록과 대조하여 없는 자료는 링크를 비활성화한다. 기존 도면 안내에는 현재 작업 폴더에 없는 v3 자료 링크가 있어, 초기 화면은 실제 존재하는 블록아웃 PNG 두 개를 사용한다.
- 현재 단계는 문서에 제안된 1단계 작업 기준이다. 팀이 실제 진행 단계를 확정한 것으로 표시하지 않는다.
- 검증 결과는 `공용/08_1단계_통합_검증표.md`의 결과 열에서 읽는다. 결과를 바꿀 때 빌드·일시·인원·근거도 원문에 남긴다.

## 관리용 실행

Windows PowerShell 5.1 이상과 Git으로 생성할 수 있다. 생성 후 열람에는 둘 다 필요 없다.

```powershell
# 문서·Git·검증표 묶음만 새로고침
powershell -NoProfile -ExecutionPolicy Bypass -File .\Plan\Dashboard\Refresh.ps1

# 변경 검토와 review.json 수정이 끝난 경우에만 검토 기준을 갱신
powershell -NoProfile -ExecutionPolicy Bypass -File .\Plan\Dashboard\Refresh.ps1 -ConfirmReview
```

HTML, CSS, JavaScript 파일은 모두 이 폴더에 있다. 외부 라이브러리나 온라인 서비스에 자료를 전송하지 않는다.
