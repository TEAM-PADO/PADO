# 플레이어 전투 — 현재 구현 명세

기준일: 2026-09-29. 이 문서는 현재 프로젝트의 C++ 코드, PADO 자산 목록, 저장된 플레이어 블루프린트 그래프를 기준으로 작성했다. 수치는 별도 표시가 없으면 **C++ 기본값**이다. 블루프린트·아이템 Definition에서 덮어쓸 수 있으므로 실제 플레이 값은 에디터와 실행 빌드에서 확인해야 한다. 기존 기획 목표와 개발 단계는 [기본 기획](../공용/00_기획핵심과_미결정.md)과 [개발 순서](../공용/01_개발순서.md)를 따른다.

## 현재 범위

현재 플레이어 구현은 **3인칭 이동·조준과 월드 아이템을 이용한 총기 사용의 기반**이다. 총기와 탄창은 재사용 가능한 시스템으로 만들어졌지만, 새 게임에서 기본 권총을 받고 좀비를 처치해 차를 사는 배달 전투 흐름은 아직 연결되지 않았다.

| 영역 | 현재 구현 |
|---|---|
| 캐릭터 | 카메라 기준 이동, 시점 회전, 점프, 달리기 의도, 조준 단계별 카메라·이동 속도, 애니메이션용 이동 상태 |
| 입력 | Enhanced Input으로 이동·시점·점프·달리기·상호작용·공격·재장전·투하·조준 입력 전달 |
| 아이템 | 월드 아이템 한 개를 들고 사용·투하, 서버에서 줍기 거리와 아이템 상태 확인, 보유 상태 복제 |
| 총기 기반 | 단발 동작과 자동·반자동·점사 Fire Action, 조준선 판정, 탄창 소비·재장전, 로컬 발사 연출·반동 |
| 화면 | 플레이어 블루프린트가 임시 조준점 위젯을 생성 |
| 멀티플레이 기반 | 이동 예측에 달리기·조준 상태 반영, 아이템 보유·탄약·재장전 상태 복제, 서버의 아이템·탄약 처리 |

## 담당 경계와 구현 목표

아래는 앞으로 구현·연결할 기능의 분담이다. 현재 구현 표나 실제 빌드 검증 결과를 뜻하지 않는다. **호스트·서버에서 판정한다는 실행 권한과 기능을 구현하는 담당을 구분한다.** 전투 기능의 서버 처리도 플레이어 전투 담당의 범위다.

| 기능 | 플레이어 전투 담당 | 협업 경계 |
|---|---|---|
| 명중·피해·차량 충돌 | 무기 명중 판정, 서버의 공격 측 명중 재검증·피해 요청, 플레이어 피해와 차량 충돌 구현 | AI는 서버의 적 피해 수신·체력·보호·사망 처리, 코어는 처치 최종 인정·처치자 귀속·보상 자격·금액과 방 결과 판정 |
| 공용 월드 상호작용 | 문·차량·상점·아이템의 대상 탐색·우선순위, 캐릭터 상호작용 입력과 대상별 요청 연결 | UI는 선택 대상·가능 여부 안내와 메뉴 입력, 코어는 소유권 등 공통 검증과 배달·구매 등 게임 규칙 판정 |
| `PlayerState`와 개인 데이터 | 클래스·돈·인벤토리·개인 장비 상태와 복제, 공개 서버 API, 개인 저장 스냅샷의 직렬화·복원 구현 | 코어는 보상·거래·배달 규칙을 판정해 API로만 변경을 요청하고 개인 스냅샷을 방 `SaveGame`에 통합 |
| 일반 슬롯·택배 전용 슬롯 | 여유 있는 일반 인벤토리와 별도 택배 슬롯, 장착·사용·아이템 이동 및 총 습득·드롭의 서버 검증·처리 | UI는 복제된 슬롯·장착 상태와 요청 결과를 표시. 코어는 택배 지급·회수 사건과 거래 규칙을 판정 |
| 사망·부활 연결 | 사망 상태의 캐릭터 동작·입력 중단, 데이터 이탈·새 몸 생성·입력 복귀, 사망 드롭의 서버 처리와 최근 사망 드롭 기록·정리 | 코어는 사망자·생존자 집계·부활 조건·재지급 사건·배달 시간 판정, 플레이어는 공개 API로 권총을 중복 없이 지급. UI는 대기 화면·카메라·안내 |
| 전투 HUD | 체력·장탄·장착 총·차량·좌석 상태와 동작 가능 조건 제공, 화면과 실제 상태의 일치 검증 | UI가 HUD와 상호작용 안내 화면 제작 |

구매·수리에서 전투는 무기·차량의 기계적 상태와 적용 기능, 돈·소지 상태의 공개 조회·변경 API를 제공한다. 코어는 돈·소유권·거래 조건을 확인해 결과를 확정하고 API로 지불·지급을 요청한다. 배달의 수락·교체·완료·실패·보상 자격·지급액과 부활 조건은 코어가 판정한다. 수치는 기획 데이터로 분리하며 코드 상수로 확정하지 않는다.

### `PlayerState` 공개 서버 API와 개인 저장 계약

- 플레이어 담당이 `PlayerState` 클래스와 돈·인벤토리·개인 장비 필드·복제 방식을 설계한다. 서버에서만 수행되는 돈 증감, 총·택배 지급·회수, 소지 여부 조회 API를 제공하고 권한·요청 상태·중복 적용을 검증한다. 코어와 UI는 내부 변수나 인벤토리 배열을 직접 변경하지 않는다.
- 코어가 배달 수락 시 참가자 목록과 완료 시 접속 여부를 대조해 지급 대상을 결정한다. 수락 후 이탈·재접속한 사람의 자격은 유지하고 수락 후 최초 합류자는 그 건의 완료 보상에서 제외한다. 플레이어 API는 이 판정 결과를 한 번만 반영하며 지급 자격이나 금액을 독자 계산하지 않는다.
- 총 습득·개별 드롭·사망 드롭의 거리·소유·현재 상태 검증과 `PlayerState` 변경은 플레이어 전투의 서버 처리다. 택배 지급·소지 검증·배달 종료 회수는 코어가 배달 규칙을 판정하고 같은 공개 API로 요청한다.
- 개인 저장 스냅샷의 데이터 형식·직렬화·생성·복원은 플레이어 담당이 구현한다. 코어는 배달 완료·우체국 도착 시 방 저장을 호출하고 스냅샷을 방 진행·차량 상태와 함께 보존한다. 방 종료 후 재개·최종 문 앞 체크포인트 불러오기는 코어가 선택한 저장본을 공개 복원 API로 적용한다. 호스트가 방을 유지한 채 재접속하는 경우에는 **현재 방이 유지한 상태/스냅샷**을 연결하고 과거 저장본으로 돈·인벤토리를 되돌리지 않는다. 일반 재개 시 진행 중 택배를 복원하지 않는 규칙과 문 앞 체크포인트의 별도 복원은 [공동 저장 규칙](../공용/07_배달_상태와_저장_규칙.md)을 따른다.
- UI는 복제된 `PlayerState`의 돈·총·택배·장비와 서버 응답을 표시한다. 배달 목표·타이머·보스·공용 결말은 코어의 `GameState`를 사용한다. 화면에서 개인 보상이나 상태를 먼저 확정하지 않는다.

## 실제 입력과 이동

입력 자산 IMC_Player에 다음 키가 연결되어 있고, PlayerController가 해당 입력을 캐릭터에 전달한다. 실행 시 입력 자산이 PlayerController 블루프린트 기본값에 지정돼 있어야 한다.

| 입력 | 현재 동작 |
|---|---|
| WASD / 마우스 | 카메라 방향 기준 이동 / 컨트롤러 시점 회전 |
| 왼쪽 Shift | 누르는 동안 달리기 의도를 설정한다. 조준 자세에서는 속도 계산상 달리기가 적용되지 않는다. |
| Space | 점프 |
| 오른쪽 마우스 버튼 짧게 누르기 | 조준 상태를 켜거나 끈다. Tap 트리거 임계 시간은 0.2초다. |
| 오른쪽 마우스 버튼 길게 누르기 | 누르는 동안 견착 상태로 바꾼다. Hold 트리거 임계 시간은 0.15초다. |
| 왼쪽 마우스 버튼 | 든 아이템의 사용 시작·종료를 전달한다. 맨손 Attack 확장 함수는 현재 빈 구현이다. |
| R | 든 아이템이 재장전 가능한 경우 서버에 재장전을 요청한다. |
| E | 들고 있는 아이템이 없으면 월드 아이템 하나를 골라 줍기를 요청한다. 차량 탑승 입력은 없다. |
| G | 현재 든 월드 아이템을 내려놓는다. |

캐릭터는 **평상시에도 컨트롤러 Yaw를 따라 회전**한다. 이동 방향으로 몸을 자동 회전시키는 설정은 꺼져 있다. 조준에는 Idle·Shouldered·Aiming 세 단계가 있고, 기본 설정에서는 아이템을 들고 있어야 Idle 이외 단계로 들어간다. 카메라는 단계 사이를 보간하며, 아이템을 잃으면 Idle로 돌아간다.

| 이동 값 | C++ 기본값 |
|---|---:|
| 기본 보행 속도 | 500 cm/s |
| 달리기 속도 | 기본 속도 × 1.6 = 800 cm/s |
| 견착 이동 속도 | 기본 속도 × 0.75 = 375 cm/s |
| 조준 이동 속도 | 기본 속도 × 0.5 = 250 cm/s |
| 점프 Z 속도 / 공중 조작 비율 | 500 cm/s / 0.35 |

실제 보행 기준 속도는 Movement Attribute의 영향을 받고, 자세 배율은 그 값에 곱해진다. 달리기·조준 단계는 이동 예측 데이터에 실려 서버에서 재생된다. 현재 캐릭터·발사 코드에는 달리기나 점프 중 발사를 막는 전용 조건이 없다.

## 월드 아이템과 총기

E 상호작용은 카메라 앞을 구형 Sweep으로 찾는다. 시선에 줍기 가능한 아이템이 없으면 캐릭터 주변에서 가장 가까운 아이템을 고른다. 카메라 탐색 거리 기본값은 900 cm, Sweep 반경은 24 cm다. 최종 줍기 거리는 **캐릭터 기준 250 cm**이며 서버가 보유 상태, 아이템 상태, 거리와 부착 소켓을 다시 확인한다. 현재는 한 번에 월드 아이템 하나만 들 수 있고, 다른 아이템으로 바꾸려면 먼저 내려놓아야 한다. 화면에 표시된 후보 하나만 선택하는 상호작용 UI는 없다.

월드 아이템의 보유자와 월드/보유 상태는 복제된다. 투하는 서버가 캐릭터 앞의 위치를 계산해 처리한다. Holder가 종료될 때 들고 있던 아이템을 놓는 정리 경로는 있지만, 플레이어 **사망 사건에 연결된 투하**는 없다.

현재 PADO 무기 Definition 자산은 돌격소총과 저격총이다. 권총용 애니메이션 자산은 있으나 기본 권총 Definition, 새 플레이어에게 권총을 지급하는 흐름은 없다. 총기별 실제 피해·발사 간격·탄창·사거리는 각 Definition 설정을 확인해야 하며, 아래 공통 클래스 기본값을 특정 총의 실측 값으로 취급하지 않는다.

새 게임의 기획 결정으로는 기본 권총 뒤에 **라이플·샷건·스나이퍼를 각각 150코인에 구매**할 수 있어야 한다. 탄약 구매나 예비탄 소모 없이 재장전 때마다 탄창을 계속 채운다. 이는 현재 자산 완성 여부와 구분되는 구현 목표다. 특히 샷건 자산과 세 총의 실제 전투 수치는 별도 제작·확인이 필요하다.

| 총기 공통 설정 | C++ 기본값과 동작 |
|---|---|
| Fire Action 모드 / 발사 간격 | Automatic / 0.1초. Definition에서 Semi Automatic 또는 Burst와 간격을 지정할 수 있다. |
| Magazine Trait 용량 | 30발. 현재 탄창은 아이템 Definition의 Trait이 결정한다. |
| 재장전 | 서버가 탄창을 가득 채운다. 몽타주가 있으면 완료 Notify 또는 몽타주 종료 시 충전하고, 없으면 즉시 충전한다. 별도 예비탄 수량은 구현되어 있지 않으며, 새 게임 기획도 예비탄 무제한·탄약 구매 없음으로 확정했다. |
| Aim Line Trace 거리 / 시작점 | 10000 cm(100 m) / 시점. Definition에서 사거리와 조준 단계별 시작점을 바꿀 수 있으며, 총구 소켓이 없으면 시점으로 대체한다. |
| 명중 시야 | 기본적으로 Visibility 채널의 장애물 가림을 검사한다. 에셋에서 이 옵션을 바꿀 수 있다. |
| 허용 핑 상한 | Fire Action 기본값 250 ms. 이를 넘으면 탄약과 연출은 처리하되 명중 결과는 적용하지 않는다. |

조종하는 머신이 화면 중앙으로 목표점을 구하고 설정된 시작점에서 즉시 선형 판정을 한다. 로컬에서 발사 연출과 반동을 실행하고 발사 결과를 묶어 서버로 보낸다. 서버는 무기 보유·Action 활성·차단 태그·탄약 등 실행 조건을 확인하지만, **전송된 명중 경로와 목표를 다시 추적하지 않는다.** 따라서 현재 구현을 호스트가 사거리·총구 시야를 독립적으로 재판정하는 방식으로 설명해서는 안 된다. 탄착각 확산은 조준선 판정에 구현되어 있지 않다.

## 아직 연결되지 않은 게임 흐름

아래 항목은 현재 플레이어 전투 기능으로 기술하거나 완료 판정하지 않는다.

| 범위 | 남은 연결 |

## 차량·운반 구현 목표

- 혼자 운전·로드킬·정차 후 사격·재탑승할 수 있어야 한다. 2~4인은 한 차에 동승하고 `Ctrl+1~4`로 좌석을 변경한다. 운전자는 사격할 수 없고 동승자만 창밖으로 사격한다.
- 운전석이 비면 마지막 가속 입력 이후 차량이 감속한다. 소유자나 운전자가 사망해도 파괴되지 않은 차는 남고 동승자가 운전석으로 옮겨 운전할 수 있다.
- 차량 충돌·내구도 피드백과 파괴를 구현하고 파괴 시 탑승자 사망 처리를 요청한다. 파괴된 차량은 다시 구매해야 하며, 구매·수리 조건과 코인 판정은 코어에 연결한다. 차량 전투의 입력 예측·보정은 초기 다인 검증에서 확인한다.
- 택배는 별도 전용 슬롯을 쓰며 총과 함께 운반하고 차량 탑승 중에도 운반 제약이 없다. 동료 전달은 바닥에 개별 드롭한 뒤 줍는 방식이며, 사망 현장의 총·택배도 같은 서버 습득 계약으로 회수한다.

## 사망·부활 구현 목표

2026-10-01 기획 반영. 아래는 현재 구현 상태가 아니라 [사망·부활 판정 규칙](../공용/07_배달_상태와_저장_규칙.md)에 따른 구현 목표다.

- 팀 전원 사망이면 1인 포함 우체국 자동 부활. 생존자가 있으면 사망자는 대기하고, 생존자 한 명이 우체국 내부 안전 구역에 도착해야 사망한 팀원 전원을 부활시킨다. 이미 내부에 생존자가 있으면 조건을 충족한다. 마지막 생존자가 사망하면 대기자도 자동 부활로 전환한다.
- 기존 몸에서 데이터가 빠져나와 우체국으로 이동하고 새 몸에 들어가는 연출을 연결한다. 생존자 복귀 전에는 우체국에서 데이터만 대기하며, 새 몸의 조작은 부활 완료 후 돌려준다.
- 사망 시 아이템을 묶지 않고 개별로 현장에 떨어뜨리고 돈은 유지한다. 플레이어별 최근 사망 1회분만 유지하며 다음 사망 시 이전 미회수분을 제거한다. 이미 회수한 아이템·다른 팀원의 드롭·차량은 이 삭제에서 제외한다. 새 몸에는 기본 권총을 한 번 지급한다. 배달 시간은 대기·연출 중에도 계속 흐른다. 호스트의 확정 상태에 맞춰 새 몸 생성·입력 복귀·연출을 연결한다.
- 사망 드롭에는 3분 정리를 적용하지 않고 직접 내려놓은 일반 아이템에만 적용한다. 택배는 배달 최종 제한시간 초과·완료·중단·교체에 맞춰 제거한다. 회수는 선택이며 우체국에서 다른 배달로 교체하거나 실패한 같은 배달을 재수락해 새 택배로 진행할 수 있다. 이는 현재 구현과 구분되는 목표다.

## 완료 확인

- 1/2/4인 호스트·클라이언트에서 개인 돈·장비·일반 슬롯·택배 전용 슬롯이 복제되고 UI가 같은 상태를 표시한다. 보상·거래 변경은 코어 판정과 공개 서버 API를 거치며, 이탈·복귀·후발 최초 합류의 보상 자격을 플레이어가 임의 변경하지 않는다.
- 서버가 총 습득·드롭·사망 드롭을 검증하고, 현장에 남은 총·택배를 본인 또는 동료가 다시 습득할 수 있다. 택배를 차량 안에서도 소지하고 바닥 드롭·줍기로 전달할 수 있다.
- 혼자 운전·로드킬·정차 사격·재탑승, 2~4인 좌석 변경·동승 사격, 운전자 사격 금지와 빈 운전석 감속을 확인한다. 소유자·운전자 사망 후 동승자 운전과 차량 파괴 시 탑승자 사망·재구매도 확인한다.
- 방 종료 후 일반 재개·최종 문 앞 체크포인트는 선택한 저장본의 개인 스냅샷을 복원하고, 현재 방 재접속은 방이 유지한 상태/스냅샷을 연결해 과거 저장본으로 되돌리지 않는지 확인한다. 개인 데이터 직렬화·복원은 플레이어 API에서 처리되고 코어가 내부 배열·필드를 직접 바꾸지 않는다. 기존 사망·부활 및 아이템 수명 예외도 함께 확인한다.
