## 게임 개요와 세계

- 인간을 닮았지만 피가 나지 않는 AI 휴머노이드가 우체부이자 고객인 좀비 세상이다. 시점은 3인칭이며 1~4인이 배달과 주행·좀비 전투를 함께 한다.
- 우체국 내부·앞마당·총 상점·차량 상점·배송지는 하나의 큰 오픈 지도에 있다. 장소 이동에 별도 레벨 전환·로딩 화면이 없다.
- 우체국 내부와 총 상점 내부는 좀비 진입 금지 안전 구역이다. 두 출입구 사이 도로·보도는 안전 구역 밖이며 좀비가 활동한다. 우체국 앞마당과 총 상점을 우체국 내부로 취급하지 않는다.
- 도시 위성지도 시안은 전체 맵이 아닌 중심부다. 거점 사이에도 건물을 배치하고 도로·건물은 시안 밖 다른 도시 구역으로 이어진다. 총 상점은 우체국 맞은편 비슷한 규모 건물의 1층, 차량 상점은 중심부에서 조금 떨어진 곳에 둔다.
- 정해진 줄거리를 따라가는 대신 배달을 중심으로 플레이한다. 마지막 수취인 확인 여부에 따른 두 결말 뒤에도 같은 방을 계속 플레이한다. 이 게임은 2026-09-29 출발 기획이며 이전 `협동문명사냥`의 세부 규칙을 자동으로 이어받지 않는다.

## 방·저장·합류

- 첫 구현은 리슨 서버다. 방마다 별개 진행이며 다른 방의 돈·장비를 가져오지 않는다. 호스트가 해당 방의 진행과 참가자 상태를 저장하고 다시 연다.
- 별도 로비 레벨은 없다. 메인 메뉴는 게임 시작·게임 참가·게임 종료다. 새 게임 또는 이어하기를 확정하면 게임 지도에 바로 입장한다.
- 호스트별 게임 저장 슬롯 1개를 먼저 구현·검증한다. 저장이 없으면 새 게임, 있으면 이어하기·삭제를 제공한다. 기존 저장을 삭제 확인 없이 덮어쓰지 않는다. 단일 슬롯 검증 후 다중 슬롯 목록·선택·개별 삭제와 데이터 분리를 확장한다. 최종 문 앞 체크포인트는 같은 게임의 별도 상태이며 추가 게임 슬롯이 아니다.
- 방 생성·이어하기 때 세션을 **공개방** 또는 **친구 참여방**으로 선택한다. 공개방은 참가 목록에서 참가하며 친구 여부·비밀번호를 입장 조건으로 요구하지 않는다. 친구 참여방은 호스트의 스팀 친구이거나 올바른 비밀번호를 제출한 경우 참가할 수 있다. 스팀 초대만을 유일한 참가 경로로 제한하지 않는다. 승인되면 진행 중 게임에 바로 들어간다.
- 친구 참여방의 입장 조건은 코어/네트워크가 서버에서 다음 순서로 판정한다.
  1. 호스트의 스팀 친구인가? → 친구이면 비밀번호 제출 없이 입장 허용.
  2. 친구가 아니라면 비밀번호를 제출했는가? → 제출했다면 방 비밀번호와 검증하여 일치할 때 입장 허용.
  3. 친구가 아니고 비밀번호를 제출하지 않았거나 검증에 실패했다면 입장 거절 및 메인 메뉴 복귀. UI는 서버의 거절 사유를 표시한다.
- 배달 중에도 합류하며 처음 합류한 참가자는 우체국에서 시작한다. 진행 중인 목표에는 참여할 수 있다. 완료 보상 자격은 아래 시간 제한과 보상 항목을 따른다.
- 열린 방의 재접속은 현재 방이 유지한 개인 상태를 사용한다. 종료한 방을 다시 열 때만 저장본을 복원한다. 현재 방 재접속을 과거 저장으로 덮어쓰지 않는다.

## 시간 제한과 보상

- 일반 배달은 우체국 팀원이 수락한 순간부터 호스트 타이머가 연속해서 흐른다. 상점·도로·배송지 이동과 사망·부활 대기·연출 중에도 멈추지 않는다. 보스 배달에는 제한시간 타이머를 두지 않는다.
- 일반 배달은 보상 감소 시각과 최종 실패 시각을 구분한다. 첫 기준을 넘기면 정해진 금액을 한 번만 차감하고, 최종 마감부터 배송 완료·보상이 불가능하다. 보스 배달은 처치 전후 모두 제한시간·시간 초과 실패·시간 감액이 없다.
- 완료 보상은 수락 때 방에 있었고 완료 순간 접속 중인 플레이어 각자에게 동일하게 지급한다. 우체국에 남아 있어도 자격은 같다. 당시 참가자가 이탈 후 완료 전에 재접속하면 자격을 유지하고, 수락 후 처음 합류한 참가자는 해당 완료 보상에서 제외한다.
- 일반 좀비 처치 보상은 처치자만 받는다. 로드킬은 운전자, 동승 사격은 발사자다. 보스 처치 자체에는 별도 코인을 주지 않는다.
- 둘째 보스의 수취인 확인 생략 차감은 일반 배송 지연 차감과 별개인 정액 차감이다. 시간·보상·가격·차감액의 실제 첫 테스트 값은 경제와 밸런스 표에서만 관리한다.
- 인원에 따라 일반 좀비의 수·체력만 조정한다. 배달 제한시간·보스 체력·보상은 인원수로 자동 변경하지 않는다.

## 차량 액션과 성장

- 새 방은 기본 권총만 지급하고 돈·차량 없이 시작한다. 성장은 총·차 구매에 집중한다. 첫 구현에 무료 기본 차량은 두지 않으며 플레이 테스트 후 필요성을 재검토한다.
- 구매 가능한 총은 라이플·샷건·스나이퍼다. 탄약 구매 없이 재장전마다 예비 탄약 소모 없이 탄창을 채운다. 탄창 용량·재장전 동작은 유지하며 탄약을 저장 자원으로 취급하지 않는다.
- 총은 바닥 드롭 후 동료가 줍는 방식으로 전달한다. 차 소유권은 넘기지 않지만 동료를 태울 수 있다. 총·차 판매는 없다.
- 한 차에 1~4인이 함께 탄다. 운전자는 사격하지 못하고 동승자는 창밖으로 개인 총을 쏜다. 혼자일 때는 운전·로드킬로 이동하고 정차·하차해 사격한다. 각자 차를 구매해 타는 것도 허용한다.
- 소유자가 사망해도 파괴되지 않은 차는 현장에 남아 동승자가 운전할 수 있다. 손상된 차는 유료 수리, 파괴된 차는 재구매한다.
- 차량 소환 대수 상한과 멀쩡한 차의 자동 삭제는 적용하지 않는다. 빈 차·정지한 차의 물리·네트워크 갱신 빈도를 낮추거나 잠재우고 파괴 잔해를 정리한다. 1~4인 주행·전투 측정에서 문제가 확인되면 제한을 검토한다.
- 우체국 근처 약한 좀비 구역으로 무자본·차량 상실 상태에서도 구매 비용을 다시 벌 수 있게 한다.

## 차량 상호작용·피해 규칙

다음 수치는 첫 플레이 테스트 기준이다. 구간 피해와 폭발 피해는 구현·검증 완료를 뜻하지 않는다.

| 항목 | 적용 규칙 |
|---|---|
| 탑승 | 주행 중에도 문 근처에서 상호작용 입력을 0.5초 유지하면 탑승한다. 입력 해제·거리 이탈은 취소하고 시간을 초기화한다. 이동·피격 자체는 취소 조건이 아니다. |
| 좌석 배정 | 완료된 요청부터 처리하고 처리 시 빈 좌석을 확인한다. 빈 운전석 우선, 이후 가까운 빈 좌석이다. |
| 좌석 변경 | `Ctrl+1~4`로 빈 좌석에 즉시·연속 변경한다. 사격·재장전 중에도 허용하며 동작 종료 대기·쿨타임이 없다. 점유 좌석 변경은 불가하다. 운전자 사격 금지는 변경 후에도 적용한다. |
| 빈 운전석 | 주행 중 운전석이 비면 마지막 액셀 입력만 받은 뒤 서서히 감속한다. |
| 하차 | 즉시 가까운 빈 공간으로 내리며 주행 중에도 허용한다. 하차 순간 속도 20km/h 이하 피해 0, 20km/h 초과~60km/h 이하 피해 50, 60km/h 초과 즉사다. |
| 탑승자 보호 | 창밖 사격자도 차량만 피해를 받는다. 같은 공격의 차체·탑승자 동시 명중은 해당 차량에 한 번만 적용한다. |
| 차량 파괴 | 내구도 0에서 즉시 폭발한다. 탑승자는 즉시 사망하며 차는 재구매한다. |
| 폭발 근거리 | 폭발 위치 중심의 가까운 구역에서 플레이어·일반 좀비 즉사, 보스 피해 200, 차량 즉시 파괴다. 보스는 체력을 차감하고 0이면 일반 사망 처리한다. |
| 폭발 외곽·차폐 | 다음 구역 피해는 70이다. 벽으로 완전히 가려지면 차단한다. 동료·적·다른 차량 모두 대상이다. 다른 차량 탑승자에게 직접 피해를 주지 않고 그 차에 한 번 적용하며 파괴되면 탑승자가 사망한다. 보스 피해 보호가 우선한다. 두 구역 반경은 미정이다. |
| 좀비 충돌 | 속도별 피해를 주고 일반 좀비는 밀려난다. 다시 충돌하면 다시 피해를 받는다. 차도 내구도 손실·속도 저하를 받으며 속도별 값은 미정이다. 좀비는 돌진 차량을 회피하지 않고 공격을 시도한다. |
| 보스 충돌 | 피해를 받지만 밀려나지 않는다. 차량 충돌은 플레이어 선제 공격으로 인정하고 보스 피해 보호가 우선한다. |
| 아군 충돌 | 차량으로 동료를 치면 피해를 적용한다. 폭발은 위 구역·탑승자 보호 규칙을 따른다. 총기 아군 피해는 미정이다. |
| 기타 손상 | 벽·다른 차량 충돌은 속도가 높을수록, 낙하는 높이가 높을수록 내구도 손상이 커진다. 구간·정확한 값은 미정이며 탑승자 보호·파괴 시 사망은 동일하다. |

## 택배·사망·부활

- 캐릭터당 인벤토리 슬롯은 4개이며 택배 전용 슬롯은 없다. 총·일반 택배·보스 택배는 공용 4칸을 사용하고 일반·보스 택배를 한 캐릭터가 함께 운반할 수 있다. 일반 택배는 수락자가 받고 바닥 드롭 후 동료 줍기로 전달한다. 보스 택배는 해당 보스의 유효한 처치 때 현장에 하나 떨어지며 개인 귀속 없이 팀원 누구나 회수·운반·배송할 수 있다. 바닥 드롭 후 동료 줍기로 전달할 수 있다. 차량 탑승 운반 제약은 없다. 택배는 배달 유형·목적지·시도에 연결하며 보스 택배는 해당 팀 배달에 연결된 하나만 유지한다. 소지자는 운반 상태일 뿐 처치자나 영구 소유자가 아니다.
- 인벤토리 4칸이 가득 차 있으면 일반 배달 수락·택배 지급 또는 바닥 택배 습득을 거절한다. 아이템을 직접 버려 빈 칸을 만든 뒤 다시 요청해야 하며 자동 교체·자동 투하는 하지 않는다. 보스 배달 수락 때는 택배를 지급하지 않으므로 공간 부족만으로 수락을 막지 않고, 처치 후 보스 택배 습득 때 빈 칸을 확인한다. 거절한 일반 수락은 새 배달·타이머·자격을 만들지 않는다.
- 보스 택배 소지자가 사망하면 현장에 드롭하고 누구나 회수할 수 있다. 이후 사망 때 이전 미회수 드롭을 정리해도 보스 택배는 보존한다. 열린 방에서 소지자가 이탈하면 택배를 인벤토리에서 제거해 마지막 캐릭터 위치의 안전한 회수 지점에 한 번 드롭하며, 남은 팀원이 계속 배송한다. 재접속 때 택배를 다시 지급하지 않는다. 방 종료 후 이어하기에서도 원래 소지자의 복귀를 기다리지 않는다. 지형 아래로 빠짐 등 실제 회수 불가능한 택배는 해당 배송지 문 앞의 안전한 회수 지점에 복구한다. 이전 택배를 제거하고 같은 배달의 택배 하나만 유지하며, 정상적으로 회수 가능한 원거리 택배는 이동시키지 않는다.
- 사망 시 돈은 유지하고 총·택배 등 소지품은 개별로 현장에 투하한다. 묶음·회수 가방은 만들지 않는다. 플레이어별 최근 사망 1회분의 미회수 드롭만 유지하고 다음 사망 때 그 플레이어의 이전 잔여분을 제거한다. 회수한 아이템·다른 팀원의 드롭·차량·보스 택배는 제외한다. 보스 택배는 사망 회차와 무관하게 배송 완료까지 보존한다.
- 직접 내려놓은 일반 아이템만 3분 후 제거한다. 사망 드롭에는 이 시간을 적용하지 않는다. 이 수명은 현재 방 규칙이며 바닥 아이템·사망 회차를 영구 저장하지 않는다.
- 택배는 해당 배달의 최종 제한시간 초과·완료·중단·교체 때 소지품과 바닥 모두에서 제거한다. 일반 배달 교체·완료로 보스 택배를 제거하지 않는다. 일반 보상 감소 때는 유지하고, 유효한 보스 처치 뒤 무제한 배송에는 시간 경과 삭제가 없다.
- 회수는 필수가 아니다. 일반 배달은 사망이나 미회수 택배 정리만으로 실패·시간 초기화를 하지 않는다. 우체국에서 다른 건으로 교체하거나 실패한 같은 건을 새 택배로 재수락할 수 있다. 새 시도의 택배·타이머·자격과 이전 시도를 혼용하지 않는다.

사망·전멸·부활의 팀 생존자 수는 **접속 중인 참가자**를 대상으로 판정한다. 접속 중인 팀의 생존자가 0명이면 전원 사망 조건이다.

- 연출은 몸에서 데이터 이탈 → 우체국 귀환 → 조건 미충족이면 대기 → 새 몸 진입 → 조작 복귀다. 전멸은 조건 대기를 생략한다. 데이터 귀환 자체를 생존자 복귀나 야외 도착 저장으로 취급하지 않는다.
- 사망·대기·연출 중 이동·공격·줍기·배송 입력은 금지한다. 부활 완료 때 기본 권총을 한 번 지급하고 새 몸을 조작한다. 도착·전멸이 겹쳐도 새 몸 생성·권총 지급은 한 번만 처리한다. 생존자의 전원 집결은 요구하지 않는다.
- 일반·보스 배달은 전멸만으로 실패하지 않는다. 보스 전투 중 전멸하면 미처치 보스의 전투·타깃을 해제하고 체력을 최대치로 초기화하며, 같은 보스 배달·시도·수락 자격을 유지해 재수락 없이 재도전한다. 이미 처치한 보스는 되살리지 않고 처치 기록·배송 대기·현장 택배를 유지한다. 소지 택배는 기존 사망 드롭 규칙으로 현장에 투하한다. 개별 사망은 배달 실패나 보스 체력 초기화 조건이 아니다. 보스 배달 종료 뒤에도 최초 수락한 지역은 영구 개방을 유지한다.

## 보스 전투와 실패

- 보스는 배송지 앞에 있고 길을 완전히 막아 경로를 강제로 바꾸는 거대 좀비는 이 3종만 둔다. 빠르고 강한 엘리트 좀비 아이디어는 후순위다.
- 첫째·둘째 보스는 해당 보스 배달 수락 후 플레이어가 탐지/교전 범위에 접근하면 먼저 공격한다. 최초 수락 전 잠금·피해 보호 상태에서는 보스 전투를 시작하지 않는다. 보스 첫 테스트 탐지 거리는 20m, 타깃 재선정 간격은 0.5초다. 확정 밸런스가 아니며 AI·레벨의 실제 테스트 근거를 받아 기획이 조정값을 승인한다.
- 최종 보스는 우체국 밖에서 보이는 중심부의 마지막 인간 집을 지킨다. 해당 배달 수락 후에도 플레이어가 먼저 공격하기 전에는 공격하지 않는다.
- 보스는 레벨이 지정한 전투장 안에서만 추적·이동한다. 유효 대상이 모두 전투장 밖으로 나가면 추적을 멈추고 원래 자리로 돌아간다. 다른 유효 대상이 전투장 안에 남아 있으면 그 대상으로 전환한다. 복귀만으로 체력을 회복하지 않으며 전멸 즉시 또는 마지막 실제 피해 이후 1분 무피해 조건으로만 최대 체력 초기화한다.
- 보스 공격 대상은 전투장 안에서 감지·공격할 수 있는 보행 생존 플레이어를 1순위, 생존자가 탄 차량을 2순위로 고른다. 같은 순위에서는 가까운 대상을 선택한다. 탑승자는 개인 후보가 아닌 차량 하나로 묶고 차량 거리는 차체 표면 기준으로 계산하며, 빈 차량·사망자는 제외한다. 선택 대상에 도달할 수 없으면 도달 가능한 다른 유효 대상을 같은 우선순위로 다시 고른다. 도달 가능한 대상이 없으면 접근 가능한 지점에서 대기하고 주기적으로 경로·대상 유효성을 재평가한다. 장애물을 통과하거나 순간이동하지 않는다. 경로 대기 자체로 체력을 초기화하지 않으며 기존 전멸/무피해 회복 조건을 적용한다.
- 일반 총격으로 보스에게 유효 피해를 주면 체력을 차감하고 피격 반응만 표시한다. 총격 피격 자체로 진행 중인 공격·이동 행동을 중단하거나 경직시키지 않는다. 누적 총격 경직 규칙은 두지 않는다. 체력이 0이면 기존 사망 처리로 공격을 종료하고 처치·택배 드롭을 연결한다. 차량 충돌 시 보스가 밀려나지 않는 규칙은 유지한다. 피격 표현은 공격 애니메이션과 충돌하지 않도록 AI·전투가 연결한다.
- 첫 보스 테스트에서는 레벨이 지정한 보스 전투장 내부에서 일반 좀비 생성과 외부 일반 좀비의 진입을 차단하고 보스만 검증한다. 전투장 밖 일반 좀비의 생성·추적·공격·재생성 규칙은 유지한다. 레벨은 전투장 경계·스폰 금지 구역을 제공하고 AI는 스폰/이동 경계 처리를 연결한다. 이는 첫 테스트 범위이며 이후 혼합 전투 허용 여부는 별도 테스트 결과로 기획이 결정한다.
- 최초 수락 전 보스 지역은 문·펜스 등 실제 차단물로 진입을 막고 ‘보스 배달 수락 필요’를 안내한다. 해당 보스 배달 최초 수락 시 차단물을 열어 영구 개방하고 저장·복원 시 개방 상태를 유지한다. 잠금 상태에서도 보스의 총기·충돌·폭발 피해 보호를 적용한다. 차단물·안내 위치와 전투장 경계는 레벨이 제공한다.
- 해당 보스 배달 최초 수락 전에는 보스 지역을 잠그고 보스 피해를 보호한다. 후보가 해금됐더라도 수락 전에는 지역 진입·보스 피해·처치를 허용하지 않는다. 총기·차량 충돌·차량 폭발 등 모든 피해 경로에 보호를 적용한다. 최초 수락하면 지역을 영구 개방하고 해당 보스 배달 전투의 피해 보호를 해제한다. 완료·중단 및 일반 배달 수락·교체·완료로 재잠금하지 않는다. 보스별 개방 이력을 저장·복원한다. 재잠금에 따른 플레이어·차량 강제 퇴장은 없다. 최초 수락 전 잠금은 문·펜스 등 실제 차단물과 수락 필요 안내로 표현한다. 수락 후에는 배송 완료까지 보스 배달이 유지되고, 결말 뒤에는 현재 범위에서 보스를 재등장시키지 않는다.
- 보스 배달은 처치·회수·배송 모두 제한시간이 없다. 전멸 시 배달은 실패하지 않으며 미처치 보스만 전투 해제·최대 체력 회복한다. 배달·시도·수락 자격·이미 처치한 보스 기록·택배·지역 개방을 유지하고 재수락 없이 이어간다. 일반 배달은 보스 배달 진행 중에도 병행할 수 있다.
- 미처치 보스는 마지막으로 실제 피해를 받은 뒤 1분 이상 추가 피해를 받지 않으면 체력을 최대치로 초기화한다. 보스가 추적·공격 중이거나 플레이어가 전투 구역 안에 있어도 동일하게 적용한다. 실제 체력 차감이 발생할 때마다 무피해 경과시간을 0으로 갱신하고, 빗나감·피해 보호로 무효 처리된 공격은 갱신하지 않는다. 피해를 주지 않는 추적·공격·전투 재개도 시간을 갱신하지 않는다. 배달·시도·자격·지역 개방은 유지한다. 전멸 시에는 1분을 기다리지 않고 즉시 초기화한다. 처치한 보스는 이 조건으로 되살리지 않는다.
- 보스 배달은 수동 취소·중단·다른 보스 배달로 교체할 수 없다. 전멸·일반 배달 교체·택배 분실로 종료하거나 새 시도를 만들지 않고 배송 완료까지 유지한다. 지형 문제로 회수 불가능한 택배는 해당 배송지 문 앞에 같은 시도의 택배 하나만 복구한다. 배송 완료 때만 배달 진도·보상·다음 보스 해금을 반영한다. 첫 결말 전 처치 보스는 시간 경과로 재생성하지 않는다.
- 현재 범위에서는 결말 뒤 보스 3종을 재등장시키지 않으며 반복 보스 자유 전투·보스 배달 재수락을 제공하지 않는다. 결말 컷신 뒤 같은 방에서 일반 배달을 계속하고, 야외 일반 좀비는 기존 재생성 규칙대로 등장한다. 보스 처치·배송 완료·지역 개방·결말 기록은 유지한다. 재등장 간격·위치·겹침 처리는 현재 결정 대상에서 제외한다.

| 상점 출입·구매·수리·아이템 이동·일반 배달 수락·실패·퇴장 | 그 사건만으로 저장하지 않음 | 다음 저장 전 종료하면 마지막 저장 상태로 돌아감 |

- 방 진행·후보·해금·결말·보스별 처치 기록과 최초 수락에 따른 지역 개방 이력·진행 보스 배달/시도/자격/팀 택배 소지·바닥 상태, 개인 코인·공용 4칸 인벤토리의 총/보스 택배, 파괴되지 않은 차량·소유·내구도를 함께 저장한다. 보스 최초 수락과 최초 처치는 즉시 자동 저장한다.
- 보스 처치 후 활성 배송 대기가 저장돼 있으면 팀은 해당 배달지 문 앞에서 재개한다. 배달지·시도·처치·무제한 배송·팀 택배·소지/바닥 상태·수락 자격을 복원한다. 저장된 소지자가 재개 시 참가 중이면 해당 인벤토리에 복원한다. 미회수 택배 또는 부재 참가자가 소지했던 택배는 그 참가자의 복원 인벤토리에서 제외하고 문 앞에 하나만 복원한다. 해당 참가자가 나중에 합류해도 다시 지급하지 않는다. 차량은 접근 가능한 재개 지점에 남은 내구도로 둔다. 누구나 빈 칸을 확보한 뒤 바닥 택배를 회수할 수 있다.
- 그 외 일반 재개는 우체국, 차량은 우체국 앞에서 시작한다. 완료 진도는 유지하고 일반 진행 배달은 다시 수락한다. 처치 전 보스 배달은 저장된 같은 시도·수락 자격·개방 이력을 유지하고 보스 체력은 최대치로 재개한다. 일반 바닥 아이템·일반 타이머·보스 잔여 체력은 복원하지 않는다. 보상은 다시 지급하지 않는다.
- 활성 보스 배송 대기 중 우체국 도착 또는 일반 배달 완료로 저장이 갱신돼도 문 앞 재개를 유지한다. 보스 배송 완료가 다음 저장에 반영되면 일반 재개로 돌아간다. 보스 배달 중단은 허용하지 않고 일반 배달 교체도 보스 배송 대기를 종료하지 않는다.
- 최종 문 앞 체크포인트는 이후 일반 저장으로 덮어쓰지 않는다. 명시적으로 불러오면 팀·최종 택배·전달자·자격과 선택 전 상태를 복원하고 이후 코인·장비·일반 배달 진도까지 되돌린다. 선택한 진행의 최종 완료 보상은 한 번 지급한다.
- 구매·수리 직후 종료 시 되돌아가는 범위와 저장 성공 여부를 UI가 분명히 표시한다. 개인 API 반영 완료 후 스냅샷을 수집해 방 저장에 묶는다.

## 수취인·이야기·결말 연출안

택배 내용물 자체보다 배달을 통해 숨은 인간을 찾아내려는 AI의 목적이 중요하다. AI는 좀비화 결과를 알면서도 인류를 위한 약으로 분류하고 부작용으로 처리한다. 좀비는 제1원칙의 인간으로 취급하지 않는다. 우체국 시스템과 수취인은 담담한 업무 말투의 블랙코미디를 쓴다.

수취인을 직접 만나면 매번 인간/로봇 식별을 자동으로 진행하며 별도의 식별 생략 선택은 넣지 않는다. 첫째는 등장 후 택배 수령 전에, 둘째·셋째는 문을 열어 수취인을 만난 뒤 식별한다. 첫째·둘째는 ‘로봇 확인’, 셋째는 ‘인간 확인’을 표시한다. 만나지 않은 수취인은 스캔하거나 정체를 공개하지 않는다.

### 반복 배달의 기본 대사

| 상황 | 대사·표시 문구 초안 | 연출 의도 |
|---|---|---|
| 일반 배달 수락 | 우체국 시스템: “배송 건을 배정했습니다. 지정된 문 앞에서 배송하십시오.” | 간단한 반복 업무로 시작 |
| 일반 문 앞 상호작용 | 우체국 시스템: “배송이 완료되었습니다.” | 수취인 확인 단계 없이 완료 |
| 첫 보스 수취인 수령 | 상호작용 뒤 로봇이 나옴. 수취인: “수령 확인. 업무가 원활하시길 바랍니다.” | 기본 수취인 등장 절차 |
| 둘째·셋째 수취인 미등장 | “충전 중이라 못 나가요. 문 앞에 두세요.” | 둘째 로봇과 마지막 인간이 같은 응답 사용 |
| 둘째 문을 열고 확인 | 충전 중 로봇: “확인이 필요하셨군요. 수령 처리하겠습니다.” | 셋째 선택을 위한 복선, 정상 보상 |
| 둘째 확인 없이 완료 | 우체국 시스템: “수취인 확인이 생략되었습니다. 보상이 조정됩니다.” | 확인 생략에 따른 감소 보상 안내 |
| 셋째 확인 없이 완료 | 우체국 시스템: “수취인 확인 예외를 기록했습니다. 배송은 완료로 처리합니다.” | 인간을 살려 둔 선택의 결과로 연결 |
| 보상 감소 | 우체국 시스템: “배송 지연이 기록되었습니다. 보상이 조정됩니다.” | 시간 압박을 행정 문구로 표현 |

일반 배달에는 문 열기·수취인 등장 절차가 없고, 첫 보스는 수취인이 직접 나오므로 확인 생략 선택이 없다. 둘째·셋째에만 실제 택배 전달자에게 선택지를 표시한다. 선택지·두 결말 조건·대사는 기획이 확정한다. 네트워크/코어는 서버에서 전달자·택배 소지 여부·거리·배송지 ID·현재 배달 단계를 검증하고, 게임 규칙·배송 완료·보상 차감·결말·도전과제 결과를 확정한다. AI는 수취인 등장·응답·퇴장 이벤트를 제공하고 UI는 서버 응답과 복제된 공용 결말 상태를 표시한다. 돈·택배 변경은 플레이어 담당이 제공한 `PlayerState` 공개 서버 API를 통해 반영한다.

### 보스 1·2 장면

1. 코어가 제공한 처치 기록과 보스 택배 소지·배송 가능 상태를 확인하고 현관 장면으로 연결한다. 지역은 최초 수락 후 영구 개방하며, 최초 수락 전 피해 보호·수락 후 전투 허용과 팀 공유 택배 규칙을 연결한다.
2. AI가 서버의 처치 이벤트를 코어에 전달하고 코어가 유효한 처치로 인정하면 해당 시도의 보스 택배를 현장에 한 번 드롭한다. 우체국 시스템이 “위험 경로가 정리되었습니다. 택배를 회수해 배송을 계속하십시오.”라고 안내한다. 팀원 누구나 주운 뒤 배송한다. 처치 전후 모두 제한시간이 없으며, 전멸하면 미처치 보스만 전투 해제·최대 체력 초기화하고 배달을 유지한다. 결말 전 보스는 시간 경과만으로 재생성하지 않는다.
3. 첫 번째는 문 앞 상호작용하면 로봇 수취인이 나온다. 우체부가 스캔해 ‘로봇 확인’을 표시한 뒤 택배를 전달한다. 둘째는 나오지 않아 선택지를 표시한다. 들어가면 충전 중인 수취인을 스캔해 ‘로봇 확인’을 표시하고 정상 보상, 확인하지 않고 완료하면 감소 보상을 받는다. 정액 차감은 경제와 밸런스 표를 따른다. 이 단계에는 인간 공개 장면을 넣지 않는다.

수취인 식별은 같은 얇은 얼굴 추적 프레임과 간결한 판정 표시를 반복한다. 로봇은 ‘로봇 식별 신호 확인 → 로봇 확인’, 마지막 인간은 ‘로봇 식별 신호 없음 → 생체 신호 확인 → 인간 확인’으로 보여준다. 첫 두 배달에서 익숙해진 업무 절차가 마지막에 인간 수색임을 드러낸다. 구체적인 장치·스캔 시간·카메라는 콘티에서 정한다.

보스 1·2의 배달 안내에는 의심 주소라는 우체국 시스템의 분류를 넣는다. 처치 자체의 별도 코인 보상은 없으며, 배송을 마쳤을 때 보스 배달 보상만 지급한다.

### 마지막 보스와 두 결말

최종 보스는 우체국 밖에서 보이는 중심부의 마지막 인간 집 앞을 지킨다. 플레이어가 먼저 건드리지 않으면 위험하지 않다. 의뢰를 수락하면 시스템이 “매우 의심스러운 주소입니다. 수취인을 반드시 확인하십시오.”라고 지시한다. 처치·회수·배송 모두 제한시간은 없다. 보스를 처치하고 현장에 떨어진 택배를 주운 뒤 현관에서 노크해 수취인 확인을 시도한다. 택배 소지자가 현관 문 앞에 도착하면 **노크·결말 선택 전에 별도 체크포인트를 저장**한다. 이를 불러오면 보스 처치 후의 문 앞에서 다른 결말을 고를 수 있지만, 체크포인트 뒤에 쌓은 코인·장비·일반 배달 진도는 되돌아간다.

#### 문을 열어 확인한 경우 — AI 관점의 해피엔딩

1. 집 안에서 이전 로봇들과 **똑같이** “충전 중이라 못 나가요. 문 앞에 두세요.”라는 응답이 들린다. 선택은 실제 택배 전달자에게만 표시한다.
2. 전달자가 문을 연다. 집 안에 숨은 이 도시의 마지막 인간이 보인다. 인간은 짧게 **“잠깐만요. 저 아직 사람이에요.”**라고 말한다.
3. 우체부가 같은 수취인 식별 절차로 얼굴을 스캔한다. ‘로봇 식별 신호 없음 → 생체 신호 확인 → 인간 확인’을 표시한다. 외형이나 본인의 말만으로 처리하지 않고 인간임을 식별한 뒤 다음 절차로 넘어가는 컷이다.
4. 우체국 시스템은 “인류 보호용 약물 투여 절차를 시작합니다.”라고 알린다. 전달한 플레이어의 캐릭터가 **우체부의 숨겨진 기본 장비**를 컷신에서 처음 꺼내 인간에게 좀비약을 주입한다. 팀 전원이 함께 본다. 주입 도구는 택배 내용물이나 플레이어가 구매·관리하는 아이템이 아니다.
5. 변화 뒤 시스템이 “예상된 부작용이 확인되었습니다. 치료 절차는 완료되었습니다.”라고 말한다. **변한 인간인 좀비 한 마리가 집 밖으로 나오고, 그 뒤 집 안은 비어 있다.** 이 지역 AI는 마지막 인간을 찾았다고 판단하고 승리를 선언한다. 연출은 AI가 좀비화를 알면서도 약의 부작용으로 처리한다는 설정을 드러낸다.
6. 해피엔딩 결과와 **「ai의 시대」 도전과제 달성**을 표시한다.

#### 문을 열지 않고 완료한 경우 — 인간 번영 결말

1. 전달자가 문을 열지 않고 ‘수취인 확인 예외’를 선택한다. 시스템은 평소와 같은 문구로 예외를 기록하고 배송을 완료한다.
2. 팀 전원에게 **「인간을 지켜준 로봇」 도전과제 달성**을 보여준다. 집 안의 인간이 살아남았음을 관객에게 보여주되, 그 순간 플레이어 캐릭터에게 정체를 알려주지 않는다.
3. 이후의 짧은 장면들에서 다른 지역의 생존자들이 만나 번영하고, 훗날 인간이 AI를 다시 지배하는 미래를 보여준다. 이 지역 AI가 인간을 살려 둔 결정의 결과로 닫는다.

이 결말에서는 집에서 좀비가 나오지 않는다. 인간은 정체가 드러나지 않은 채 살아남는다.

### 제작 시 지킬 조건

- 어느 선택이든 **팀 전원이 같은 컷신·엔딩**을 본다. 문 열기 여부와 약 주입 캐릭터는 실제 택배 전달자를 기준으로 한다.
- UI는 실제 전달자 여부를 코어가 제공한 상태로 표시하고 선택을 서버에 요청한다. 최종 인간의 AI 반응은 시네마틱/퀘스트 상태와 충돌하지 않도록 이벤트로 연결하고, 결말을 자체 확정하지 않는다. 컷신 진입·스킵 정책은 기획 승인 뒤 코어의 시작/종료 상태와 연결한다.
- ‘충전 중’의 음성·문구는 둘째 보스의 로봇과 셋째 보스의 인간 집에서 같은 말로 유지한다. 일반 배달에는 이 선택 절차를 넣지 않는다.
- UI/클라이언트가 두 결말의 콘티 초안·영상 길이·숏 구성·카메라·시퀀스와 제작 계획을 작성하고 기획자가 승인한다. 이 문서는 사건 순서와 필수 정보를 고정한다. UI가 필요한 애니메이션·효과·사운드·소품을 공동 자산 목록에 취합하고 항목별 실제 제작 담당을 지정해 컷신 완성·통합/팀 재생을 주관한다.
- AI는 적·수취인·인간의 동작과 실내/퇴장 반응, 전투는 전달자와 주입 동작, 레벨은 집·현관·좀비 출구 등 공간을 제공한다. 코어는 선택·결말과 컷신 시작/종료 상태를 확정·동기화한다. 컷신 제작 담당 지정과 게임 결과 판정은 별도 책임이다.
- 어느 결말을 보더라도 컷신 뒤 같은 방의 플레이 화면으로 돌아가 일반 배달을 계속한다. 현재 범위에서 보스는 재등장하지 않고 보스 배달도 다시 수락하지 않는다. 일반 좀비는 기존 야외 재생성 규칙대로 계속 등장한다.
- 확정 대사 녹음·번역 전에는 기획자가 현장 플레이를 보고 대사의 길이와 톤을 한 번 더 확인한다.

## 역할과 공동 계약

호스트 판정 권한과 개발 담당은 구분한다. UI/플레이어 입력 → PlayerController 등의 Server RPC → 기능 담당 서버 검증 → PlayerState 공개 서버 API로 개인 상태 반영 → GameState/PlayerState 복제·표시로 연결한다. 전투는 공격측 명중 재검증·피해 요청과 플레이어 피해·차량 충돌, AI는 적 피해 수신·체력·보호·피격/사망을 구현한다. 코어는 처치 최종 인정·보상·배달/방 상태를 연결한다. 같은 피해를 두 경로에서 재적용하지 않는다.

### 클래스별 소유자

| 항목 | 구현 소유자 | 책임과 경계 |
|---|---|---|
| `GameMode` 및 방 규칙 | 네트워크/코어 | 서버 전용 배달·방·보상 자격·부활 조건 판정 |
| `GameState` | 네트워크/코어 | 일반 1건과 별도 보스 1건의 현재 배달·목적지 ID·시도·자격·서버 시간 기준을 구분하고 보스 단계·지역 개방 이력·공용 결말 상태 복제 |
| `PlayerState` | 플레이어/전투 | 개인 돈·인벤토리·총·택배·장비 상태, 복제, 공개 서버 API, 개인 저장 스냅샷 직렬화·복원 |
| `PlayerController`의 요청 경로 | 코어가 공통 계약 제공, 기능 담당이 연결 | 클라이언트 요청의 서버 진입점. UI는 요청·응답 표시에 연결하고 기능별 검증 담당으로 전달 |
| 방별 `SaveGame` | 네트워크/코어 | 방 ID 연결, 저장 시점·파일 입출력·방 상태 통합, 개인 스냅샷 수집과 복원 호출 |
| 배송지 Anchor/Actor 배치 | 레벨 | 코어 발급 ID 할당, 월드 위치·상호작용 범위·문·수취인·마커 위치 제공 |

코어는 `PlayerState`의 변수·인벤토리 배열·개인 저장 직렬화 코드를 직접 수정하지 않는다. 개인 상태 구현 담당과 방 전체 영속 저장을 호출·통합하는 담당을 구분한다.

### 기능별 책임과 전달

| 항목 | 주 담당 | 다른 파트와 연결 |
|---|---|---|
| 명중·피해·차량 충돌 | 전투가 서버의 공격측 명중 재검증·피해 요청, 플레이어 피해 처리·차량 충돌 구현 | AI가 서버의 적 피해 수신·체력·보호·피격/사망을 구현하고 적 체력에 한 번 적용. 코어는 공통 요청·소유권 검증과 처치 최종 인정·보상·방 상태 연결. 전투와 코어는 적 피해를 별도로 재적용하지 않음 |
| 체력·장탄·장착 총 HUD | UI가 화면 제작 | 전투는 확정 상태 제공과 호스트/참가자 상태 일치 확인 |
| 공용 월드 상호작용 | 전투가 문·차량·상점·아이템의 대상 탐색·우선순위·캐릭터 입력과 요청 연결 구현 | UI는 대상 안내·메뉴 입력, 코어는 배달·거래 등 요청의 유효성과 결과 확정 |
| `PlayerState`·인벤토리·개인 장비 | 플레이어 담당이 클래스·필드·개인 복제·공용 인벤토리 4칸·장착·총/택배 드롭 후 줍기·공개 서버 API 구현 | 코어는 보상/배달 택배 규칙·공통 요청 계약을 검증한 뒤 API로 변경 요청. 개인 변수·배열을 직접 수정하지 않음. UI는 복제 상태 표시·요청 |
| 개인 저장·방 저장 | 플레이어 담당이 개인 저장 스냅샷 직렬화·복원 API, 코어가 방 저장 호출·통합과 방 진행/후보/해금/차량 저장 | 코어는 `PlayerState` 스냅샷을 함께 저장하고 복원 API를 호출. 보스 처치 후 재개는 해당 문 앞에서 배송 대기·택배·보상 자격 복원, 그 외 일반 재개는 진행 배달 초기화·완료 진도 복원, 최종 문 앞 체크포인트 예외 유지 |
| 배송지 ID·Anchor | 코어가 ID 생성·변경·폐기와 배달 정의·서버 시작 매칭 검증, 레벨이 발급 ID 할당·공간 배치 | 기획은 표시 이름·배달 유형·보상·목적지 설명·보스 연결이 있는 추가 요청서를 관리. 기획·레벨·UI는 ID를 임의 발급하지 않음 |
| 컷신·부활 연출 | UI/클라이언트가 제작 계획·콘티 초안·카메라·시퀀스·자산 취합·통합/재생 주관 | 기획은 콘티·길이·필수 표현 승인, AI·전투는 캐릭터 동작, 레벨은 공간, 코어는 시작/종료 상태와 팀 동기화. 애니메이션·효과·사운드 등 실제 자산 제작 담당은 UI가 공동 자산 목록의 항목별로 지정 |
| 거리 등급·제한시간·보상 | 기획이 변경값 최종 승인 | 레벨은 측정·변경 제안과 승인 목표에 따른 공간 조정, 코어는 승인된 배달 데이터 반영 |

### 공개 API와 인수 계약

- 플레이어 담당자는 돈 지급·차감, 총 지급·습득·드롭, 택배 지급·조회·제거, 기본 권총 재지급, 개인 저장 스냅샷 생성·복원에 필요한 공개 API와 성공/실패 결과를 제공한다. 구체적인 함수명·필드·직렬화 형식은 구현 담당이 합의하며 이 문서에서 고정하지 않는다.
- 개인 상태를 변경하는 API는 서버 권한에서만 실행한다. 코어는 판정 결과를 넘기고 `PlayerState` 구현 내부로 들어가지 않는다. UI는 값을 직접 변경하지 않는다.
- 완료·처치·구매·드롭·택배 회수의 중복 요청은 서버에서 한 번만 반영한다. 개인 API 반영 뒤의 스냅샷을 방 저장에 묶어 보상과 저장이 어긋나지 않게 한다.
- 기획 요청 → 코어 ID 발급 → 레벨 Anchor 할당 → 코어 시작 검증 → 후보 사용 순서로 배송지를 인수한다. 누락·중복·정의 없는 ID는 오류이며 결과는 기획·레벨과 공유한다.
- 코어는 현재 방의 이탈·재접속 자격을 유지하고, 방 종료 후 일반 저장 재개와 구분한다. 현재 방 재접속에 과거 저장본을 덮어써 돈·인벤토리를 되돌리지 않는다.
- 기획·PM이 단계별 시나리오와 변경 영향 담당을 관리하고 코어가 실행 일정·근거를 취합한다. 각 파트가 실제 확인을 수행하며 문서 수정만으로 미실행 항목을 통과 처리하지 않는다.

### 공동 산출물

- UI는 공동 자산 목록에 필요 항목·수량·실제 제작 담당·통합 담당·임시/최종 상태를 취합하고 기획은 우선순위를 승인한다. 임시 자산으로 시작해도 최종 필요 목록을 보존한다.
- 기획·PM은 인수 기준·시나리오·변경 영향 담당을 관리하고 코어는 공통 빌드·일정·실행자·결과·수정 담당을 취합한다. 각 파트는 실제 실행 근거를 제출한다. 결과 원본은 통합 검증 기록이며 문서 정리로 미실행을 통과 처리하지 않는다.
- 코어는 인원별 다수 좀비·여러 차량·보스전의 성능 조건·목표·측정 방법을 취합한다. 레벨·AI·전투·UI는 자기 처리 비용, 코어는 네트워크/동기화 비용을 측정하고 개선 담당을 정리한다. 기획은 목표·체감 품질을 승인한다.
- 담당자는 첫 작업·다른 파트가 제공할 ID/상태/자산·기획 모호함·성능/일정 위험을 자기 문서에 남긴다. 별도 기술 문서를 자동으로 추가하지 않는다.

## 단계별 개발 범위

단계는 일정·인원 배분이나 실제 현재 진행 상태가 아닌 통합 목표다. 담당자는 개인 문서에 구현·미구현·검증 결과를 구분한다. 1단계 후보 1개로 기본 흐름을 먼저 확인하고 이후 최종 후보 구성으로 확장한다.

### 1단계 — 배달 한 건이 끝까지 돌아가는 통합판

**목표:** 새 방에서 기본 권총으로 약한 좀비를 처치해 첫 차를 사고, 우체국에서 일반 배달을 수락한다. 차로 이동하며 좀비를 돌파해 배송지 문 앞 상호작용으로 완료·보상을 받고, 팀원 한 명이 우체국으로 돌아오면 다음 건을 고를 수 있다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 플레이어 전투 | PlayerState 클래스·개인 돈/인벤토리/장비 복제·공개 서버 API·개인 저장 스냅샷 생성/복원, 3인칭 이동·기본 권총·호스트 명중 재검증/피해, 첫 차 운전·승하차·충돌·로드킬, 월드 대상 탐색·입력, 공용 인벤토리 4칸·장착·드롭/줍기·사망 개별 투하, 코어 부활 판정에 따른 새 몸·권총 API·조작 복귀·데이터 동작·전투 HUD용 상태 |

**통과 기준:** 새 방의 기본 권총·돈 0·차량 없음에서 시작해 경제와 밸런스 표의 차량 가격·처치 수익에 맞춰 첫 차를 사고, 혼자와 2인 이상이 각각 한 건을 끝까지 완료한다. 수락 순간부터 타이머가 흐르고, 자격 있는 참가자만 동일한 완료 보상을 받는다. 완료 직후 방을 종료해 다시 열어도 진도와 보상이 유지되며 플레이어는 우체국에서 시작한다.

사망·부활은 1단계에서 함께 확인한다. 1인·전원 사망 시 자동 부활, 생존자가 우체국 밖이면 부활 대기, 한 명의 내부 복귀로 사망자 전원 부활, 이미 내부에 생존자가 있는 경우, 마지막 생존자 사망 시 자동 부활 전환을 검증한다. 몸에서 우체국으로 데이터가 돌아와 새 몸에 들어가는 기본 연출과, 대기 중에도 배달 타이머가 흐르는 규칙을 확인한다.

### 2단계 — 실패, 성장, 합류와 이어하기

**목표:** 의도하지 않은 종료나 실패가 발생해도 방의 상태가 규칙대로 이어지고, 차와 총을 사며 반복 배달할 수 있다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 플레이어 전투 | 동승 사격·Ctrl+1~4 좌석 변경·빈 운전석 감속, 공용 인벤토리 4칸·장착 전환·총/택배 서버 습득/드롭·바닥 전달, 구매/차감·저장 스냅샷 API 확장, 차량 수리/파괴·탑승자 사망·소유자 사망 후 운전 승계 |

**통과 기준:** 시간 초과, 전원 사망, 차량 파괴, 배달 중 합류·재합류, 방 종료 후 재개를 실험한다. 진행 중 다른 배달로 교체, 실패한 같은 건의 새 택배 재수락, 현장 회수 없이 배달 지속이 가능한지도 확인한다. 이 단계에서는 배달 진행 중 종료했다면 완료 진도는 보존하고 해당 배달을 처음부터 다시 받는다. 3단계에서는 보스 3종 처치 저장의 문 앞 배송 재개와 최종 문 앞 별도 체크포인트가 예외다. 사망 드롭은 개별로 최근 사망 1회분만 유지하고 다음 사망 때 이전 미회수분을 제거한다. 직접 내려놓은 일반 아이템만 3분 정리하며 택배는 최종 제한시간 초과·완료·중단·교체 때 제거한다.

### 3단계 — 보스 배달과 결말

**목표:** 일반 배달 누적 횟수와 앞 보스 완료 조건으로 보스 배달 3개가 순서대로 열리고, 마지막 선택 뒤에도 같은 방에서 일반 배달과 일반 좀비 전투를 계속한다. 보스는 재등장하지 않는다.

이 단계에서 일반 배달 최대 1건과 별도 보스 배달 최대 1건을 병행한다. 해당 보스 배달 최초 수락으로 지역을 영구 개방하고, 보스 수락 시 택배를 지급하지 않은 채 유효 처치 때 현장에 드롭·회수·배송하는 흐름을 통합한다. AI는 처치 이벤트, 코어는 시도별 택배 드롭 판정·중복 방지·두 배달 상태, 플레이어는 현장 택배 회수, UI는 두 목표와 회수 단계를 연결한다. 지역 개방·일반 배달 병행·택배 드롭/회수의 인수 결과는 실제 실행 뒤 기록한다.

| 파트 | 이 단계에서 필요한 것 |
|---|---|
| 플레이어 전투 | 보스전 중 사망·재진입, 다수 플레이어와 차량 전투의 마무리, 전투 피드백과 밸런스 조정 |

**통과 기준:** 보스 3종 각각 처치 직후 자동 저장하고, 문 앞에 도착하기 전 종료해도 해당 배달지 문 앞에서 택배·보상 자격을 복원해 배송을 이어간다. 보스 처치·회수·배송에 시간 초과 실패가 없으며, 전투 중 전멸하면 미처치 보스 체력만 최대치로 초기화하고 같은 배달·시도·자격을 유지해 재수락 없이 재도전한다. 처치 후 전멸하면 보스를 되살리거나 택배를 삭제하지 않고 배송을 계속한다. 최종 문 앞 체크포인트를 불러오면 팀이 선택 직전으로 돌아가 다른 결말을 볼 수 있으며, 체크포인트 뒤의 성장·진도는 되돌아간다. 마지막 배달자는 ‘충전 중’ 응답 뒤 수취인 확인 여부를 결정하고 팀 전원이 같은 결말을 본다. 결말 뒤에도 일반 배달·일반 좀비 재생성이 유지되고 보스 재등장·완료 보스 배달 재수락은 없다.

보스별로 첫째는 상호작용 후 로봇 등장·수령, 둘째는 실내 충전 중 로봇 확인/확인 생략에 따른 정상·감소 보상, 셋째는 문을 열어 인간 좀비화 해피엔딩·「ai의 시대」 또는 열지 않고 인간 번영·「인간을 지켜준 로봇」을 확인한다. 둘째 확인 생략 차감은 경제와 밸런스 표의 확정된 첫 테스트 값으로 실제 지급 금액을 검증한다.

다중 게임 저장 슬롯은 단일 슬롯의 반복 저장·재개·삭제 검증을 통과한 뒤 확장한다. 기존 저장 유지·게임별 데이터 분리·선택 슬롯만 삭제되는지 확인한다. 보스 지역·처치·저장은 위 확정 규칙으로 검증하고, 보스 외형·패턴·전투 수치 등 미결정 항목은 결정 전 통과 기준으로 고정하지 않는다.

## 실제 입력과 이동

입력 자산 IMC_Player에 다음 키가 연결되어 있고, PlayerController가 해당 입력을 캐릭터에 전달한다. 실행 시 입력 자산이 PlayerController 블루프린트 기본값에 지정돼 있어야 한다.

| 입력 | 현재 동작 |
|---|---|
| WASD / 마우스 | 카메라 방향 기준 이동 / 컨트롤러 시점 회전 |
| 왼쪽 Shift | 누르는 동안 달리기 의도를 설정한다. 조준 자세에서는 속도 계산상 달리기가 적용되지 않는다. |
| Space | 점프 |
| 오른쪽 마우스 버튼 짧게 누르기 | 조준 상태를 켜거나 끈다. Tap 트리거 임계 시간은 0.2초다. |
| 오른쪽 마우스 버튼 길게 누르기 | 누르는 동안 견착 상태로 바꾼다. Hold 트리거 임계 시간은 0.15초다. |
| 왼쪽 마우스 버튼 | 든 아이템의 사용 시작·종료를 전달한다. 맨손 Attack 확장 함수는 현재 빈 구현이다. |
| R | 든 아이템이 재장전 가능한 경우 서버에 재장전을 요청한다. |

| G | 현재 든 월드 아이템을 내려놓는다. |

캐릭터는 **평상시에도 컨트롤러 Yaw를 따라 회전**한다. 이동 방향으로 몸을 자동 회전시키는 설정은 꺼져 있다. 조준에는 Idle·Shouldered·Aiming 세 단계가 있고, 기본 설정에서는 아이템을 들고 있어야 Idle 이외 단계로 들어간다. 카메라는 단계 사이를 보간하며, 아이템을 잃으면 Idle로 돌아간다.

| 이동 값 | C++ 기본값 |
|---|---:|
| 기본 보행 속도 | 500 cm/s |
| 달리기 속도 | 기본 속도 × 1.6 = 800 cm/s |
| 견착 이동 속도 | 기본 속도 × 0.75 = 375 cm/s |
| 조준 이동 속도 | 기본 속도 × 0.5 = 250 cm/s |
| 점프 Z 속도 / 공중 조작 비율 | 500 cm/s / 0.35 |

실제 보행 기준 속도는 Movement Attribute의 영향을 받고, 자세 배율은 그 값에 곱해진다. 달리기·조준 단계는 이동 예측 데이터에 실려 서버에서 재생된다. 현재 캐릭터·발사 코드에는 달리기나 점프 중 발사를 막는 전용 조건이 없다.

## 월드 아이템과 총기

E 상호작용은 카메라 앞을 구형 Sweep으로 찾는다. 시선에 줍기 가능한 아이템이 없으면 캐릭터 주변에서 가장 가까운 아이템을 고른다. 카메라 탐색 거리 기본값은 900 cm, Sweep 반경은 24 cm다. 최종 줍기 거리는 **캐릭터 기준 250 cm**이며 서버가 보유 상태, 아이템 상태, 거리와 부착 소켓을 다시 확인한다. 현재는 한 번에 월드 아이템 하나만 들 수 있고, 다른 아이템으로 바꾸려면 먼저 내려놓아야 한다. 화면에 표시된 후보 하나만 선택하는 상호작용 UI는 없다.

월드 아이템의 보유자와 월드/보유 상태는 복제된다. 투하는 서버가 캐릭터 앞의 위치를 계산해 처리한다. Holder가 종료될 때 들고 있던 아이템을 놓는 정리 경로는 있지만, 플레이어 **사망 사건에 연결된 투하**는 없다.

현재 PADO 무기 Definition 자산은 돌격소총과 저격총이다. 권총용 애니메이션 자산은 있으나 기본 권총 Definition, 새 플레이어에게 권총을 지급하는 흐름은 없다. 총기별 실제 피해·발사 간격·탄창·사거리는 각 Definition 설정을 확인해야 하며, 아래 공통 클래스 기본값을 특정 총의 실측 값으로 취급하지 않는다.

기획 목표와 현재 자산 완성 여부를 구분한다. 샷건 자산과 구매 대상 총기의 개별 Definition·실제 전투 수치는 별도 제작·확인이 필요하다.

| 총기 공통 설정 | C++ 기본값과 동작 |
|---|---|
| Fire Action 모드 / 발사 간격 | Automatic / 0.1초. Definition에서 Semi Automatic 또는 Burst와 간격을 지정할 수 있다. |
| Magazine Trait 용량 | 30발. 현재 탄창은 아이템 Definition의 Trait이 결정한다. |
| 재장전 | 서버가 탄창을 가득 채운다. 몽타주가 있으면 완료 Notify 또는 몽타주 종료 시 충전하고, 없으면 즉시 충전한다. 별도 예비탄 수량은 구현되어 있지 않다. |
| Aim Line Trace 거리 / 시작점 | 10000 cm(100 m) / 시점. Definition에서 사거리와 조준 단계별 시작점을 바꿀 수 있으며, 총구 소켓이 없으면 시점으로 대체한다. |
| 명중 시야 | 기본적으로 Visibility 채널의 장애물 가림을 검사한다. 에셋에서 이 옵션을 바꿀 수 있다. |
| 허용 핑 상한 | Fire Action 기본값 250 ms. 이를 넘으면 탄약과 연출은 처리하되 명중 결과는 적용하지 않는다. |

조종하는 머신이 화면 중앙으로 목표점을 구하고 설정된 시작점에서 즉시 선형 판정을 한다. 로컬에서 발사 연출과 반동을 실행하고 발사 결과를 묶어 서버로 보낸다. 서버는 무기 보유·Action 활성·차단 태그·탄약 등 실행 조건을 확인하지만, **전송된 명중 경로와 목표를 다시 추적하지 않는다.** 따라서 현재 구현을 호스트가 사거리·총구 시야를 독립적으로 재판정하는 방식으로 설명해서는 안 된다. 탄착각 확산은 조준선 판정에 구현되어 있지 않다.

### 공개 API와 데이터 계약

돈 증감, 총·택배 지급/회수·소지 조회, 기본 권총 재지급, 개인 스냅샷 생성/복원의 공개 API와 성공/실패 결과를 제공한다. 서버 권한·거리·소유·현재 상태·중복 요청 검증을 구현하고, 코어에서 받은 판정 결과를 적용한다. 함수명·필드·직렬화 형식은 합의 결과를 기록한다.

공격 측 명중 재검증 범위를 제안하고 AI와 피해 요청/결과·타깃 규약을 합의한다. 적 피해는 AI 수신 경로에 연결한다. 구매·수리에서는 무기·차량의 기계적 상태와 적용 기능을 제공한다. 미정 차량 수치·충돌 피해·내구도 손실·감속 표는 데이터로 제안하고 측정 근거를 남긴다.

### 진행과 확인

2026-10-01 사망·부활, 2026-10-02 차량·운반 기획의 연결 작업은 아직 구현 목표다. 위의 구현 조사 결과와 구분해 기능별 구현 상태·막힌 입력·필요 자산·다른 파트 제공 데이터와 다음 작업을 기록한다.

1단계의 권총·생존·첫 차 흐름이 연결된 뒤 [통합 검증표](../공용/08_1단계_통합_검증표.md)의 전투·차량·개인 API/저장 항목을 실행한다. 이 문서의 구현 조사는 **코드와 저장된 자산 구조 확인 결과**이며 실제 빌드 플레이나 접속 통과 결과가 아니다. 무기 DPS·생존성·차량 입력 예측/보정은 빌드와 조건을 붙여 측정한다.

필요한 총·차량·플레이어 동작·애니메이션·효과·사운드 항목과 수량은 UI의 공동 자산 목록에 전달한다. 여기에 전투 파트의 자산 연결 상태를 남긴다.
